# 体积预算

> 数据来源：Phase 2 实测（Release x64，`dumpbin` 节大小）；Phase 3 移除 ImPlot 后总量不变；
> 2026-10-06 应用层重构（ADR-046）后复测总量；同日内嵌 UI 字体子集 + FreeType 后复测（ADR-048）。
> **本页是体积数据的唯一出处**（[迁移计划](01-迁移计划.md)只留一行链接）；Phase 7 裁剪落地后在本页更新。

## 1. 现状构成

| 组成 | 原预估 | 实测（Release x64） |
|---|---|---|
| MuPDF 静态库（含内置字体资源） | 15~25 MB | **≈ 38 MB**，其中内置 CJK 兜底字体占绝对主体：`SourceHanSerif-Regular.ttc` 24.8MB + Droid 两个 8.7MB |
| ImGui + freetype | ~1 MB | ≈ 1 MB（ImPlot 已随 ADR-021 从构建与仓库移除；Phase 6 起启用 FreeType 装载器，走 libmupdf 已带进来的 freetype，未新增依赖） |
| 嵌入 UI 字体子集 | 1.5~2 MB | **1.04 MiB**（`assets/ui_font_subset.otf`，1,091,992 字节；ADR-048） |
| 静态 CRT + 其余代码 | ~2 MB | ≈ 2 MB |
| **exe 合计** | 目标 < 30 MB | **40.0 MiB**（`bin\Release\LilithReader.exe`，41,908,736 字节） |

- 节大小（Phase 2 实测）：`.data` ≈ 34MB、`.text` ≈ 3.8MB、`.rdata` ≈ 2.4MB；导入表只有系统组件。
- UI 字体子集的实际收益比预估更好（1.04 MiB vs 预估 1.5~2 MB）：CFF 子集 + `pyftsubset` 默认
  保留 kern，3869 个硬约束字 + 767 个常用符号共 4636 个码位。
- **体积目标已由 "< 30MB" 调整为 "< 45MB"**：原预估严重低估了 MuPDF 的内置字体资源。

## 2. 为什么不裁 CJK 兜底字体

那 24.8MB 的思源宋体是运行期真会走到的 CJK 兜底字体
（`font-table.h` 的 `FONT(han, SourceHanSerif_Regular_ttc, …)`，由 `fz_new_cjk_font`
在文档未内嵌中文字体时调用）。砍掉它，中文读者打开大量 PDF/EPUB 会看到空白或方块，
与本项目目标用户直接冲突。

## 3. Phase 7 的裁剪手段（按收益排序，届时逐项评估并出 ADR）

1. 用 `TOFU_CJK_LANG` 走 Droid 兜底（约 -24MB，代价是汉字字形观感下降）
2. 去掉罕用 Noto 文种（SignWriting 2.8MB、Tangut 2.0MB 等，约 -5MB）
3. UPX 压缩（UI 字体子集化已于 Phase 6 落地，ADR-048，-1.04MB 已计入当前总量）
4. 仅保留 PDF 解析器（-5~8MB，与"多格式"目标冲突，优先级最低）

结论：**Phase 7 再争取压到 20MB 量级**。

## 4. 安装包体积（Phase 7）

`installer\dist\LilithReader-0.6.0-setup.exe` = **24.9 MiB**（26,091,650 字节）。

构成：lzma2/max 压缩的 exe（约 24.5MB）+ 7 个文件类型关联图标（每个 17 帧，合计约 280KB）
+ 卸载器与向导资源。

其中图标帧集由 1 帧扩到 17 帧（ADR-051）使安装包增大约 0.8MB —— 换来的是 100~200% 缩放下
图标不再被拉伸发糊，这个代价是划算的。
