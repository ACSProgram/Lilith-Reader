## 1. 现状构成（2026-10-10 实测）

exe = **40,216,576 字节 ≈ 38.35 MiB**。

| PE 节 | 大小 | 内容 |
|---|---|---|
| `.data` | 30.42 MiB | **字体数据，占 exe 约 80%**：思源宋体 ttc 23.67 + Noto 保留文种 6.10 + urw/sil 0.91（三项合计 30.68 MiB，与节大小吻合） |
| `.text` | 4.24 MiB | MuPDF + 应用 + ImGui + FreeType 全部代码（含导出功能，ADR-101） |
| `.rdata` | 2.35 MiB | 字体表、常量、字符串 |
| `.rsrc` | 1.15 MiB | 内嵌 UI 字体子集（1.04 MiB，ADR-048）+ 图标 |
| 其它（`.pdata`/`.reloc`/`.fptable`/头部） | ~0.2 MiB | |

字体明细（libmupdf 1.26.10 资源，经 overlay port 裁剪后编入 exe 的部分）：

| 组成 | 大小 | 说明 |
|---|---|---|
| SourceHanSerif-Regular.ttc | **23.67 MiB** | CJK 兜底主力，内含 KR/K/SC/TC 四个字形面共享轮廓 |
| Noto 保留文种 | 6.10 MiB | 152 个文件：Emoji / Symbols / Symbols2 / **Math（学术数学符号兜底）** / Music + 南亚/东南亚等小文种 |
| urw + sil | 0.91 MiB | Base14 标准字体 + Charis SIL |

## 2. overlay port 的作用（当前约束）

- 本项目的 libmupdf 经 overlay port 剔除两个 Droid CJK 兜底与 8 个罕用 Noto 文种后再链接
  （清单与字节级对照见归档）。**当前实测下这些字体本就不进 exe**，但 overlay 仍有保留价值：
  若端口/bin2coff 变化使大字体重新进入链接，overlay 会继续把它们挡在 exe 之外（防复发）。
- 运行期影响：删减只作用于"文档未内嵌字体时的兜底"；内嵌字体的 PDF/EPUB 完全不经过兜底链。
  被移文种中唯一可能被感知的是乌尔都语 Nastaliq 书写风格降级为 Naskh 阿拉伯体（保留）；
  其余为死语言。

## 3. 为什么不裁思源宋体

那 23.67 MiB 的思源宋体 ttc 是运行期真会走到的 CJK 兜底字体
（`font-table.h` 的 `FONT(han, SourceHanSerif_Regular_ttc, …)`，由 `fz_new_cjk_font`
在 EPUB/HTML 及带语言标记的文档未内嵌中文字体时调用）。砍掉它，中文读者打开大量
PDF/EPUB 会看到空白或方块，与本项目目标用户直接冲突。

## 4. 剩余裁剪手段（按收益排序；落地前先出 ADR）

1. **思源宋体子集化**（≈ **-10~12 MiB**）：ttc 内含 4 个字形面共享轮廓，替换为单个 SC 面
   并按需子集（GB2312 全集 + GBK + Ext A + 假名/谚文/注音/部首，约 3 万字形 vs 全量 6.5 万），
   预计 24.8 → 12~14 MiB。需替换字体资源 + 修正 `font-table.h` 的 subfont 索引 +
   GB2312/GBK 全集覆盖率验收（数学/希腊/西里尔符号走 Noto，不受影响）。**体积上唯一的大杠杆。**
2. 再剔 Noto 保留中的死文字小块（Bhaiksuki/Bamum 等数十个 <100KB 文件，合计 ≈ -1~1.5 MiB）——
   清单长、收益小，性价比一般。
3. 字体资源压缩 + 运行期解压（"字体专用 UPX"，无杀软启发式风险）：≈ -14 MiB，但需改
   第三方端口构建并增加启动耗时，除非极限追求体积否则不推荐。
4. ~~UPX 整包压缩~~：**ADR-072 否决** —— 本应用单文档、每次打开都是冷启动，UPX 的
   全镜像解压既拖慢启动又不省运行内存，还加重杀软启发式风险。

## 5. 安装包体积

`installer\dist\LilithReader-1.0-rc.1-setup.exe` = **24.04 MiB**（25,203,706 字节，1.0-rc.1 打包实测）。

构成：lzma2/max 压缩的 exe + 7 个文件类型关联图标（每个 17 帧，合计约 280KB）
+ 卸载器与向导资源。图标帧集由 1 帧扩到 17 帧（ADR-051）使安装包增大约 0.8MB ——
换来的是 100~200% 缩放下图标不再被拉伸发糊，这个代价是划算的。

CI 的安装包体积门禁上限见 ADR-084（35 MiB）；历次安装包数据见
[归档](archive/2026-10/体积预算-裁剪过程.md)。
