## 写入规则（防止文档堆积臃肿）

1. **按性质落位**：当前事实 → `02-架构设计.md`；规划与待办 → `01-迁移计划.md`、`04-人工验证.md`；选型理由 → `03-决策记录.md`（只追加，末尾续写）；数据与预算类参考 → 独立文档（如 `05-体积预算.md`）；历史记录 → `archive/YYYY-MM/` 并在[索引](archive/README.md)登记。
2. **一事一档**：某类内容在文档里超过一节的规模、且生命周期与主文档不同时，拆成独立文件，主文档留一行链接。不要让单个文件无限增长。
3. **当前文档用现在时**：不保留"本轮调整"、完成清单、排查日志——那些整节移入归档。02 只描述当前实现，未实现的标"Phase N 计划"。
4. **根 README 只留项目门面**：目标、技术栈、构建、状态、已知问题；过程记录一律进归档。
5. 归档文件记录"当时是什么"，不作为当前实现依据；可复用结论先改写进事实文档，再在日志里链接过去。
