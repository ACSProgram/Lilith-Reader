# 文档导航

本页只负责把任务导向正确的地方，不承载具体内容。当前事实以各文档与源码头注释为准；本页随文档增删维护。

## 两类文档，别混淆

| | 面向谁 | 写什么 | 在哪 |
|---|---|---|---|
| **读者文档** | 所有想了解/使用本项目的人 | 它是什么、能做什么、怎么用；说人话，不写实现细节、不写 ADR 编号、不写执行状态 | 根 [`README.md`](../README.md) |
| **技术文档** | 开发与维护者 | 模块边界、线程模型、选型理由、验证项、体积数据、历史记录 | `docs/` 下全部（含本页） |

**写文档前先选层**：一条信息既能写给读者又能写给开发者时，读者版进根 README（讲效果），
技术版进 `docs/`（讲机制），不要在同一份文档里既讲"怎么用"又讲"为什么这么实现"。

## 写入规则（防止文档堆积臃肿）

1. **按性质落位**，不按"谁写的"落位：当前事实 → `02`；规划待办 → `01`/`04`；选型理由 → `03`；
   数据与预算 → `05`；过程记录 → `archive`。**禁止**把工作日志、排查过程、完成清单写进
   `01`/`02`/`05` 或根 README。
2. **一事一档**：某类内容超过一节规模、且生命周期与主文档不同时，拆独立文件，主文档留一行链接。
3. **当前文档用现在时**：`02` 只描述当前实现；"规划中"的内容必须显式标注，不得写成已完成时态。
   调试修复的过程叙事一律进 `archive`，决策本体（决定/理由/后果）才进 ADR —— 两者重合时
   以 ADR 为准、过程指向 `archive`。
4. **根 README 只留读者看得懂的内容**：功能、操作、架构概览、构建与安装、已知问题。
   不写实施阶段、不写纪律、不写 ADR 编号堆砌。
5. **归档必须登记索引**：新增 `archive/YYYY-MM/` 文件后在 [archive/README.md](archive/README.md) 索引表加一行。
6. **文档与代码同步**：改了实现必须同步 `02` 与相关 `*.ixx` 头注释；改了构建/依赖必须同步 `02 §8`；
   发现文档与代码矛盾时**以代码为准**改文档，并在 ADR 补勘误注记（若涉及已记录的决策）。
7. 不在 `docs/` 之外创建文档（不建 `.workbuddy/`、`.agent/` 等私有目录，不在源码目录散落笔记）。
