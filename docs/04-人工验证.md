## Phase 4 渲染调度与纹理管理（待执行，2026-10-05 建立）

> 自动化已覆盖的部分（无需人工）：预算钳制、LRU 逐出选择、失败重试策略
> —— `tests/page_cache_test.cpp`，32 例断言。下列为**必须人工运行**的资源/交互类项。

### 4-1 内存曲线平稳有界（核心验收）
- **做什么**：打开一本 **1000 页以上**的 PDF，用滚轮/方向键**连续快速滚动 10 分钟**
  （来回滚动 + 跳页 + 缩放混合），期间每约 30 秒看一次任务管理器
  「详细信息 → 内存(专用工作集)」。
- **算通过**：内存上升后趋于平稳，**不随滚动时间单调增长**；峰值不超过设定预算的合理倍数
  （默认 512MiB 预算下工作集稳定在数百 MB 量级，不出现持续爬升到 GB 级）。
- **备注**：可把 `LilithReader.ini` 的 `[cache] BudgetMB` 设为 `128` 复测，内存上限应随之下降。

### 4-2 无句柄 / GDI / USER 对象泄漏
- **做什么**：同上滚动过程中，任务管理器「详细信息」页启用「句柄」「GDI 对象」「USER 对象」列
  持续观察；再反复打开/关闭同一文档 20 次。
- **算通过**：三列数值**平稳、不持续单调上升**；反复开关文档后回落到与初始接近的水平。

### 4-3 快速缩放不闪白、不残留
- **做什么**：对同一页连续快速 `Ctrl+滚轮` 放大缩小 30 次，再静置 1~2 秒。
- **算通过**：全程**不出现白色/占位框闪烁**；停下后画面清晰（高清纹理已换入）；无残影/错位。

### 4-4 方向感知预加载（体感）
- **做什么**：正常向下阅读，留意下一页是否已就绪。
- **算通过**：正向翻页基本无需等待；反向快速回翻允许短暂占位（符合预期）。体感项，无严格判据。

### 4-5 失败重试（可选，构造性）
- **做什么**：用超大幅面（A0 海报类）或人为损坏样本触发单页渲染失败（难以构造可跳过）。
- **算通过**：**从未成功渲染过**的失败页显示「渲染失败 · 点击重试」占位，点击后重新尝试，
  成功后占位消失；**曾成功渲染过**的页重渲失败时**保留旧图**（不闪白、不显示占位），
  继续缩放（倍率变化）会重新尝试。两路都不出现无限重试。

## 非阻塞复核项（Phase 4 顺带做，不单独排期）

以下项目因**耗时或依赖环境**未做穷尽复测，不影响当前阶段结论，Phase 4 收尾时顺带确认即可：

## 已知限制（不属于缺陷，无需修复）

- **阅读窗口已脱离输入法**（ADR-028）：本阶段没有需要输入法的文本输入，故整窗脱离。
  **将来加入中文输入（搜索/批注）时必须改回"仅在文本输入激活时关联"**，否则中文打不进去。
- 加密文档只能识别并提示，密码输入框在 Phase 5。
- 阅读位置记忆、书签、目录跳转在 Phase 5。
- **交互以键盘为主**，工具栏/设置面板等 UI 控件在后续阶段；本期只保证快捷键**不依赖窗口焦点**
  且不受输入法干扰，并未减少对键盘的依赖。
- UI 字体仍为系统微软雅黑（子集化内嵌在 Phase 6）。
- Windows Defender 误报问题见 README「已知问题」，与本阶段无关。
