## 待执行

### 4-2 无句柄 / GDI / USER 对象泄漏

- **做什么**：打开文档，滚动过程中在任务管理器「详细信息」页启用「句柄」「GDI 对象」「USER 对象」
  列持续观察；再反复打开/关闭同一文档 20 次。
- **算通过**：三列数值**平稳、不持续单调上升**；反复开关文档后回落到与初始接近的水平。

### 4-5 失败重试（构造性）

- **做什么**：用超大幅面（A0 海报类）或人为损坏样本触发单页渲染失败。
- **算通过**：**从未成功渲染过**的失败页显示「渲染失败 · 点击重试」占位，点击后重新尝试，
  成功后占位消失；**曾成功渲染过**的页重渲失败时**保留旧图**（不闪白、不显示占位），
  继续缩放（倍率变化）会重新尝试。两路都不出现无限重试。

### 8-5 程序运行中安装

- **做什么**：先启动 Lilith Reader 并保持打开，再运行安装程序。
- **算通过**：安装程序在"准备安装"阶段提示需要关闭正在运行的应用并可自动关闭
  （Windows 重启管理器），而不是抛文件占用的报错；关闭后能继续完成安装。
- **前置**：`installer\dist\LilithReader-<版本>-setup.exe` 已构建。

### 9-1 按键自定义（设置 → 按键分栏）

- **做什么**：`Ctrl+,` 或 `F1` 打开设置，切到「按键」分栏；点某条命令的键槽进入捕获、按一个组合键；
  再试：给不同命令绑同一个键、右键清除某个键槽、点「恢复默认」；改完**重启程序**再看该分栏。
- **算通过**：捕获时按下的组合被如实记入键槽并**立即生效**；冲突有提示；右键可清除；
  恢复默认能回到出厂键位；重启后改过的键仍在（落盘到 `LilithReader.ini` 的 `[keys]` 节）；
  菜单与右键菜单里显示的快捷键随改键同步。

### 9-4 全屏切换不再闪烁（`F11` / `Esc`）——部分通过

- **做什么**：三种起始状态各做一遍，每种来回切换多次：① 普通尺寸窗口；② **最大化**窗口；
  ③ 窗口拖到副显示器后再做 ①②。进入用 `F11`，退出用 `F11` 与 `Esc` 各试。
- **已通过**：**普通尺寸**进出全屏干净、无单帧闪烁；退出后回到进入前的状态与位置。
- **已知缺陷（无需再单独排期）**：**最大化**状态下退出全屏仍有"往左上缩一下再归位"的抖动。
  已排除命令派发时机（ADR-060）、Win32 调用顺序（ADR-058）、swapchain 重建时机（ADR-057）三条路。
- **若顺手复现，请记录**：进入还是退出、单屏还是跨屏、进入前是普通还是最大化、
  系统"最小化/最大化时动画"开关是否打开。

### 10-4 修改时间变了也不丢阅读位置

- **做什么**：读到第 N 页后关闭；用"复制 / 解压 / 重新下载"的方式让文件**内容不变但修改时间变了**，
  再打开。三种「智能匹配」设置各试一遍。
- **算通过**：仍恢复到第 N 页。**关**时只走路径键层，而路径键仍含 mtime，预期行为与"询问 / 自动"不同。

### 12-9 EPUB 与选区持久性（缺样本）

- **做什么**：① 用一份**多页** EPUB 重复选择与复制；② 在某页选好一段文字后，把鼠标移到**另一页**
  （不要点击），再回到右键菜单点「复制」。
- **算通过**：① EPUB 下同样能选择并复制；② 选区高亮**仍然显示**，且复制出的是**原来那一段**。
- **样本说明**：`tests/samples/real.epub` 只有 1 章、正文 5 个字，做不了跨页；
  需要多章节、每章有实质正文的 EPUB（用户自备）。

### 14-2 主题优先级与纸张协调

- **做什么**：在设置中依次选择"浅色""深色""跟随系统"，每种主题下分别切换原色、深色纸张、暖色；
  再关闭文档、打开另一本文档，观察界面主题与纸张方案的记忆范围。
- **算通过**：显式"浅色"时打开深色纸张文档界面仍为浅色；显式"深色"时打开原色/暖色文档界面仍为深色；
  "跟随系统"时深色纸张会使界面变暗、原色/暖色遵循系统明暗；纸张方案仍随各自文档记忆，
  且暖色/深色纸张下页面与界面色调保持同族、照片与插图不被染色。

### 15-1 崩溃链路端到端（Debug 构建）

- **做什么**：Debug 构建下临时调用 `crash::debug_trigger(0)`（未捕获 C++ 异常）与
  `crash::debug_trigger(1)`（访问违规）各一次，验证完移除调用。
- **算通过**：exe 同目录出现 `crash/LilithReader_<时间戳>.dmp` 与 `last_crash.txt`；
  摘要含阶段标记（`startup`/`frame`）与日志尾部；再次启动弹出"上次运行异常退出"确认框，
  主按钮打开的正是 `crash\` 目录；确认后标记归档为 `last_crash.reported.txt`，**不再重复提示**。
- **反向项（回归）**：一次**正常**启动并退出后再次启动，**不得**出现该提示。

### 15-2 日志的生成与轮转

- **做什么**：启动后查看 exe 同目录 `logs\LilithReader.log`；把单文件上限临时调小（或手工
  把日志灌到 2 MiB 以上）验证轮转。
- **算通过**：每行含时间、线程 ID、等级、模块与 `key=value` 字段；打开/关闭文档、渲染失败、
  退出都有记录；超过 2 MiB 后旧文件变为 `LilithReader.log.1`、新日志继续写 `LilithReader.log`，
  磁盘上恒定不超过两个日志文件；UI 在日志写入期间无可感知卡顿。

### 15-4 帧异常自愈（可选，需临时注入）

- **做什么**：Debug 构建下临时在某个绘制分支里 `throw std::runtime_error("test")`。
- **算通过**：进程不退出，日志出现 `frame aborted: test`，窗口保留上一帧画面（不闪黑）；
  下一帧起恢复正常绘制；Debug 日志里**没有** `IMGUI STACK LEAK`。
