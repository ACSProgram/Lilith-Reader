### 4-2 无句柄 / GDI / USER 对象泄漏

- **做什么**：打开文档，滚动过程中在任务管理器「详细信息」页启用「句柄」「GDI 对象」「USER 对象」

- **算通过**：三列数值**平稳、不持续单调上升**；反复开关文档后回落到与初始接近的水平。

### 4-5 失败重试（构造性）

- **做什么**：用超大幅面（A0 海报类）或人为损坏样本触发单页渲染失败。
- **算通过**：**从未成功渲染过**的失败页显示「渲染失败 · 点击重试」占位，点击后重新尝试，  
  成功后占位消失；**曾成功渲染过**的页重渲失败时**保留旧图**（不闪白、不显示占位），  
  继续缩放（倍率变化）会重新尝试。两路都不出现无限重试。

### 9-1 按键自定义（设置 → 按键分栏）

- **做什么**：`Ctrl+,` 或 `F1` 打开设置，切到「按键」分栏；点某条命令的键槽进入捕获、按一个组合键；  
  再试：给不同命令绑同一个键、右键清除某个键槽、点「恢复默认」；改完**重启程序**再看该分栏。
- **算通过**：捕获时按下的组合被如实记入键槽并**立即生效**（改完不用重启即可用新键）；冲突有提示；  
  右键可清除；恢复默认能回到出厂键位；重启后改过的键仍在（落盘到 `LilithReader.ini` 的 `[keys]` 节）。
- **备注**：菜单/右键菜单里显示的快捷键应随改键同步（取当前绑定，不是写死字符串）。

### 9-4 全屏切换不再闪烁（`F11` / `Esc`）——部分通过

- **做什么**：**三种起始状态各做一遍**，每种都来回切换多次：  
  ① 普通尺寸窗口；② **最大化**窗口；③ 把窗口拖到副显示器后再做 ①②。  
  进入用 `F11`，退出用 `F11` 与 `Esc` 各试。
- **已通过的部分**：**普通尺寸**进出全屏干净、无单帧闪烁；退出后窗口回到进入前的状态与位置  
  （进入前是最大化就回到最大化，且"还原"回到最大化前的尺寸）。
- **已知缺陷（不阻塞，无需再单独排期）**：**最大化**状态下退出全屏仍有"往左上缩一下再归位"的抖动。  
  已试过命令时机（ADR-060）、Win32 顺序（ADR-058）、swapchain 时机（ADR-057）三条路均未根治，  
  记入根 README「已知问题」。**若日后顺手复现，请记录**：进入还是退出、单屏还是跨屏、  
  进入全屏前窗口是普通还是最大化、系统"最小化/最大化时动画"开关是否打开。
- **备注**：本轮把全屏切换挪到**帧首**执行（ADR-060），普通窗口的闪烁由此消除。

### 12-6 全文搜索（停手自动检索）✅

- **做什么**：`Ctrl+F`（或菜单「查找…」）打开侧栏「搜索」分栏，**只输入**一个文中确实存在的词
  （中英文各试一次），输入完**不要按任何键**，等约半秒。
- **算通过**：① 侧栏自动展开**并且分栏真的切到「搜索」**（不是停在「目录」），输入框获得焦点；
  ② **中文可直接输入**（输入法关联切换生效，不打出一串英文）；③ 打完字**停手约 0.4 秒即自动
  开始检索**，不需要按回车或点按钮（这是本轮新增的行为）；④ 检索过程中显示
  "检索中… N/M 页 · 已找到 K 处"，期间**界面不卡**（可继续滚动、翻页）；⑤ 完成后显示"共 K 处"，
  列表每行是「第 N 页」+ 命中所在行的上下文；⑥ 点击任一条目跳到该页，命中处高亮，
  **当前命中颜色更重**；⑦ 回车与「搜索」按钮仍可用（**不等防抖、立刻检索**）；
  ⑧ 关键字为空时按回车/点按钮，状态栏提示"请输入要查找的关键字"（而不是毫无反应）。

**确认结果**：停手自动检索、中文输入、结果列表、跳转和高亮均符合预期，已归档。

### 12-7 搜索的取消、改词与边界 ✅

- **做什么**：① 搜一个不存在的词；② 搜一个极常见的字并在检索**进行中**点「取消」；
  ③ 在检索进行中**改一个字**（不要按回车）；④ 在检索进行中把关键字**全部删掉**；
  ⑤ 检索中关闭文档。
- **算通过**：① 显示"没有找到「…」"；② 点「取消」后输入框清空、检索立即停止、列表与画布高亮清空；
  ③ 改字的**瞬间**旧检索停止、结果列表清空（不混入旧词的命中），随后自动开始搜新词；
  ④ 关键字删空后结果清空、回到"在全文范围内查找文字"；⑤ 关闭文档不崩溃，重新打开后搜索状态干净。

**确认结果**：取消按钮、改词作废、清空关键字、无匹配和关闭文档路径均符合预期，已归档。

### 12-9 EPUB 与选区持久性

- **做什么**：① 用一份**多页** EPUB 重复 12-1/12-2（选择与复制）；② 在某页选好一段文字后，
  把鼠标移到**另一页**（不要点击），再回到右键菜单点「复制」。
- **算通过**：① EPUB 下同样能选择并复制（高亮与文字重合、粘贴出的文字正确）；
  ② 选区高亮**仍然显示**，且复制出的是**原来那一段**（不是空、也不是鼠标刚移到那一页的内容）。
  ②是本轮最容易出错的路径 —— 选区几何与内容快照是解耦的，这里正是验证解耦是否真的成立。
- **样本说明**：`tests/samples/real.epub` 只有 1 章、正文 5 个字，一屏就看完，**做不了跨页**；

## 已知限制（不属于缺陷，无需修复）

- **输入法关联是条件式的**（ADR-028/040）：阅读态脱离输入法（否则吞字母/数字键），  
  仅在文本输入激活（密码框等）时临时关联回来。若将来加入需要中文的搜索/批注框，机制已就位。
- 加密文档的**权限位**（`can_copy`/`can_print`）已读取。复制功能已落地（Phase 8），但
  **尚未**与 `can_copy` 联动 —— 声明了"禁复制"的加密文档目前仍可复制，属待办（ADR-039/069）。
- **文本选择限单页**（ADR-069）：跨页选择需要"页序 + 页内偏移"的复合定位与跨页高亮，
  当前不做；拖到页边之外时选区止于本页。
- **不做 OCR**（产品决定）：纯扫描件没有文本层，因此不可选择、也搜不到（见 12-8）。
- **公式/矢量内容的复制边界**（ADR-071）：内容被画成矢量路径或位图时**没有文本层**，
  因此不可选择、复制不到；字体缺 `ToUnicode` 时能选中但复制会缺字；公式的上下标/分式是多个
  文本对象，`fz_copy_selection` 按**阅读顺序**拼接，可能与视觉顺序不同。四类现象与根因见
  [架构设计 §10.6](02-架构设计.md) —— 均属 PDF 文本提取的固有限制，**不修**。
- **首次悬停有约一帧的 I 型光标延迟**：文本布局是按需抽取的（只抽鼠标所在那一页），
  首次进入某一页时内容快照尚未到达（ADR-069）。
- **搜索的自动检索有 0.4s 防抖**（ADR-071）：千页文档上"改一个字"到出结果的总延迟
  ≈ 0.4s + 一批（24 页）扫描时间。这是刻意的（逐键检索会把工作线程持续占满）。
- **交互不再只靠键盘**（Phase 6）：顶栏图标按钮 + 主菜单 + 画布右键菜单 + 设置/按键界面已就位，  
  与快捷键等价；阅读态快捷键**不依赖窗口焦点**、不受输入法干扰（ADR-026/028）的约束仍然生效。
- UI 字体为**内嵌子集**（Noto Sans SC，GB2312 一级 + 源码字符集）+ 系统 `msyh.ttc` 生僻字 fallback  
  （ADR-048）。子集不含的字若系统也没有对应字体，会显示缺字框 —— 属预期降级。
- 缩略图侧栏只请求当前页 ±40 页（随当前页扩展），并非整本一次性渲染。
- 视图动效（缩放插值/滚动平滑/跳页滑行/顶栏滑动）由 `[ui] Motion` 统一开关（ADR-047）；  
  关闭后所有路径立即生效，不留中间态。
- Windows Defender 误报问题见 README「已知问题」，与本阶段无关。
