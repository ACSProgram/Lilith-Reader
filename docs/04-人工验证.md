## 当前没有待执行的人工验证项

最近一次人工验证是**第四轮调试**（2026-10-05），用户已实测确认：

- **多列切换生效、快捷键全部可用**（1~4 主键盘与小键盘、G 跳页、F 回 fit-width、方向键…）。
  根因是**输入法吞键**（`VK_PROCESSKEY`），修法与排查见
  [决策记录](03-决策记录.md) ADR-028、[archive/2026-10/phase3-画布.md](archive/2026-10/phase3-画布.md) §9。
- **页间距随缩放变化**（ADR-029）—— 用户明确说明"不用人工验证测试"，该性质已由
  `canvas_test` 的 `test_gap_scales_with_zoom` 自动化钉死。

下一次人工验证将在 **Phase 4（渲染调度与纹理管理）** 收尾时建立。

## 非阻塞复核项（Phase 4 顺带做，不单独排期）

以下项目因**耗时或依赖环境**未做穷尽复测，不影响当前阶段结论，Phase 4 收尾时顺带确认即可：

- 1000 页 PDF 持续滚动/缩放的帧时间（< 8ms）与连续滚动 10 分钟的内存曲线。
- 双显示器下把窗口从 100% 屏拖到 150% 屏。
- 真实 `.mobi` 样本打开（无法程序化构造）。
- 输入法脱离（ADR-028）在**切换输入语言后**仍生效（代码已在 `WM_INPUTLANGCHANGE` 里补了再脱离）。

## 已知限制（不属于缺陷，无需修复）

- **阅读窗口已脱离输入法**（ADR-028）：本阶段没有需要输入法的文本输入，故整窗脱离。
  **将来加入中文输入（搜索/批注）时必须改回"仅在文本输入激活时关联"**，否则中文打不进去。
- 加密文档只能识别并提示，密码输入框在 Phase 5。
- 阅读位置记忆、书签、目录跳转在 Phase 5。
- **交互以键盘为主**，工具栏/设置面板等 UI 控件在后续阶段；本期只保证快捷键**不依赖窗口焦点**
  且不受输入法干扰，并未减少对键盘的依赖。
- UI 字体仍为系统微软雅黑（子集化内嵌在 Phase 6）。
- Windows Defender 误报问题见 README「已知问题」，与本阶段无关。
