# 人工验证清单

> 项目纪律：开发过程不实际运行软件做测试（编译/自动化测试除外）。
> 本文档记录需要人工运行确认的验证项。每项写明：**做什么（步骤）、做到什么样算通过（判据）**。
> 验证完成后请在条目前打 ✅ 并注明日期与发现的问题。

## §1 Phase 1 应用外壳（2026-10-05 交验，编译已通过：0 警告 0 错误）

环境：`bin\Release\LilithReader.exe`（约 2.3MB，静态 CRT，依赖仅系统 DLL）。

### 1.1 拖放打开与格式识别占位页
- **步骤**：启动程序（无参数）。依次拖入窗口：
  1. 一个 `.pdf` 文件
  2. 一个 `.txt` 文件
  3. 一个无扩展名文件
- **通过判据**：
  1. 拖入 pdf → 标题栏变为 `Lilith Reader — <文件名>`，页面居中显示文件名、"格式 .pdf · 已识别"、"文档渲染核心（MuPDF）将在 Phase 2 接入"。
  2. 拖入 txt → 页面显示"暂不支持的格式"，下方列出支持格式清单。
  3. 无扩展名文件 → 同样显示"暂不支持的格式"，不崩溃。
- **补充**：拖入多个文件时取第一个，其余忽略。

### 1.2 命令行打开
- **步骤**：`Win+R` 或终端执行：
  - `LilithReader.exe <存在的pdf完整路径>`
  - `LilithReader.exe <相对路径文件>`
  - `LilithReader.exe Z:\不存在的路径\no.pdf`
- **通过判据**：前两者进入与 1.1 相同的"已识别"占位页（相对路径同样生效）；第三者显示"文件不存在"占位页并列出传入路径。

### 1.3 Esc 行为
- **步骤**：打开一个文档后按 Esc；再在引导页按 Esc。
- **通过判据**：第一次按 Esc 返回拖放引导界面且标题恢复"Lilith Reader"；第二次按 Esc 程序退出。

### 1.4 窗口状态持久化
- **步骤**：
  1. 启动后把窗口移动到非常规位置（如屏幕右下）、调整尺寸，正常关闭（Alt+F4 或 Esc）。
  2. 重新启动 → 确认位置/尺寸恢复。
  3. 最大化后关闭，再启动 → 应以最大化恢复（还原后是第 1 步保存的正常矩形）。
  4. 手工编辑 exe 同目录 `LilithReader.ini`，把 X 写成 `-2000`（屏幕外），启动 → 回退到默认 1280×800 居中位置，且 ini 被下次关闭时的合法值覆盖。
- **通过判据**：以上 4 步行为均符合；多显示器环境下（如有）负坐标显示器上的位置也能正确恢复。

### 1.5 最小尺寸与 DPI
- **步骤**：
  1. 向内拖动窗口边框缩到最小 → 不小于 480×320。
  2. 若有 100% / 150% 缩放的多显示器，把窗口跨屏拖动。
- **通过判据**：尺寸钳制生效；跨 DPI 屏拖动时窗口尺寸按系统建议矩形调整，无崩溃、无半边黑屏。

### 1.6 调试浮层
- **步骤**：按 F3 两次。
- **通过判据**：左上角出现/消失一个小浮层，显示 FPS 与分辨率。

### 1.7 依赖纯净性（已由 dumpbin 静态确认，留档）
- dumpbin /dependents 输出：d3d11.dll、D3DCOMPILER_47.dll、USER32.dll、KERNEL32.dll、SHELL32.dll、IMM32.dll——无 CRT、无第三方 DLL。**已通过**（2026-10-05）。
