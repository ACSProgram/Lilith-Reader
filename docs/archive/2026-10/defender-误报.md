# Windows Defender 误报（初期问题，已归档）

> **状态**：**已归档**（2026-10-07）。初期构建出现，此后未再复现；不再列入
> [计划](../../01-计划.md) 的遗留问题与风险清单，也不再出现在根 README「已知问题」。
> 本文件只记录"当时是什么"，不作为当前实现依据。

## 现象

初期构建的 `LilithReader.exe` 被 Windows Defender 的启发式引擎判定为可疑并拦截/删除。
成因是当时 exe 的形态：**未签名** + `/MT` 静态链接 + 把 MuPDF 等大量第三方代码整体编入，
没有版本资源与图标可供识别，命中启发式规则。

## 处置与结果

| 阶段 | 动作 | 结果 |
|---|---|---|
| Phase 1~2 | 本机把 `bin\` 加入 Defender 排除项 | 本机可用，但不解决分发到他人机器的问题 |
| Phase 2 | 向微软上报误报（WDSI filesubmission） | — |
| Phase 7 | 补齐 exe 版本资源（`FileDescription`/`ProductName`/版本号，`src/app/app.rc`）与完整帧集图标 | 此后**未再复现** |

## 定性

- 记录为**"未再复现"**，而非"已根治"：本程序**始终未做代码签名**。未签名 + 静态链接的
  exe 在其它机器、其它引擎版本或其它启发式规则下，仍有可能被误判。
- 若今后再次出现，处置方式同上表：本机排除 + 向微软上报误报；要彻底消除需**代码签名证书**。
- 与之相关但**不同**的一条仍然有效：UPX 整包压缩被否决的理由里包含"加重杀软启发式误报风险"
  （ADR-072），与本条无关。
