# UI 细节优化轮（2026-10-06）

> 归档：本文件记录 2026-10-06 这一轮"按键分栏补操作清单 + 滚轮缩放修饰键可改 + 顶栏唤醒源收敛 +
> 页面淡入触发条件"的实施过程、根因分析与验证结论。**当前事实**以
> [02-架构设计](../../02-架构设计.md) §2.2/§7 与 [ADR-066](../../03-决策记录.md) 为准；
> 本文件只记录"当时发生了什么"。

## 1. 范围

用户提出三条诉求（均为界面观感/可发现性）：

1. 按键设置界面缺少**操作的介绍**：像"按住 Ctrl 滚轮缩放"这种操作，即使不适合自定义按键，
   也必须在界面上列出，否则用户不知道它存在；而这种修饰键最好也能自定义（比如改成 Alt）。
2. 怀疑**没有页面预加载**：正常速度浏览时，"每次到换页的时候都有轻微闪烁"，看起来像
   "看到页面的一瞬间才开始加载"。问实现预加载代价大不大、值不值得做。
3. **顶栏**在跳转窗口 / 右键菜单出现时也会跟着滑出来，希望能去掉。

落地结果：**修饰键型命令 + 下拉框**、**「鼠标与固定键」参考清单**、**顶栏唤醒源收敛**、
**页面淡入改为"纹理在眼前就绪才淡入"**（ADR-066）。改动集中在
`src/app/{ui,session}.cpp` 与 `app_internal.h`。

## 2. 根因（三条都不是"缺功能"）

### 2.1 盲点不是功能缺失，而是"能力不可见"

滚轮缩放的修饰键是**写死的 `io.KeyCtrl`**（`handle_canvas_input`），既不在命令表里
（ADR-054 的改键机制管不到它），也没有任何界面位置能列出它 —— 用户只能靠猜。
同理，右键菜单、拖拽平移、拖滚动条、单击失败占位重试这些**改不了但不是命令**的操作，
在按键分栏里一条都查不到。

### 2.2 换页"闪烁"：预加载一直在，是淡入的触发条件不对

- **预加载不是缺失项**：Phase 4 就落地了（可见行 ±1 行、**方向感知**，ADR-032），
  每次翻页时下一页纹理**早已备好**；代价只有"多驻留约一个视口的纹理"，远在 512MiB 预算内。
  故本轮**没有做任何预加载改动**（用户问的"代价大不大 / 值不值得"因此不成立）。
- **真正的原因**：页面淡入的触发条件是"**本页第一次被画到**就从 `alpha=0` 渐显 0.18s"
  （Phase 6 微动效，ADR-047），而绘制顺序里**边框与投影是全不透明度先画**的。于是翻页时
  先冒出一个空白页框、内容再慢慢浮出来 —— 观感正是"看到页面的一瞬间才开始加载"。
  放大到一页大于视口、或用 `→` 翻页（滑行 135ms < 淡入 180ms）时最明显。

### 2.3 顶栏被唤醒的来源是"任何弹窗"

`top_bar_should_show()` 里有两项会把顶栏强行拉出：
`g_open_jump / g_open_password`，以及 `IsPopupOpen(AnyPopupId | AnyPopupLevel)` ——
后者把**画布右键菜单**也算作"菜单"，于是一右键顶栏就滑出来。

## 3. 修复（ADR-066）

| 问题 | 做法 |
|---|---|
| 修饰键不可改 | 命令表新增 `Cmd::ZoomWheelMod`（分组「缩放」）+ `CmdDef::mod_only`：绑定**修饰键集合**（`ImGuiMod_*`，ini 存 `Ctrl` / `Ctrl+Alt`，空 = 无），不走 `cmd_pressed`，由 `wheel_zoom_mod_held()` 在画布输入里读；**修饰键严格相等**（绑 Alt 时 Ctrl+Alt 不缩放）；界面侧是**下拉框**（无 / Ctrl / Alt / Shift / Ctrl+Alt，默认 Ctrl），选「无」即滚轮只滚动 |
| 不可改操作查不到 | 按键分栏末尾新增「**鼠标与固定键**」只读清单：滚轮滚动、按住修饰键+滚轮缩放（文案随上面选择同步）、左键拖拽平移、右键菜单（`Shift+F10` / 菜单键同效）、拖拽或点击滚动条、单击「渲染失败」占位重试、鼠标移到窗口顶部重现顶栏、`Esc` 关对话框。判据：**凡是用户能做的操作，界面里必须查得到** |
| 顶栏被弹窗唤醒 | 唤醒源收敛为三类：鼠标靠近窗口顶端、设置窗口开着、**顶栏自身的弹出菜单**（主菜单 / 缩放档位，新状态 `g_toolbar_pinned`，由 `draw_top_bar` 每帧写）。画布右键菜单与跳页 / 密码 / 确认弹窗**一律不唤醒**。保留"顶栏自身菜单"的理由：菜单挂在顶栏按钮正下方，顶栏滑走菜单会悬空 |
| 翻页淡入像没加载 | `PageFade` 增 `waiting`（本页当前正以占位显示）。纹理到达时：此前是占位态 → 淡入（保留"内容换入"的柔和感）；**是被预加载好之后才滑入视野的 → 直接全不透明显示** |

实现中两处易错点（已随手修掉）：

1. `chord_from_string` 原逻辑把**末段一律当键名**，于是 ini 里的 `Ctrl` 会被拿去反查键盘名而落空
   （→ `ImGuiKey_None`，选择丢失）。改为末段也先判修饰键名，才能表示"无主键、纯修饰键"的串。
2. **冲突判定**：修饰键集合与"主键组合"不同域（`ImGuiMod_Ctrl = 4096` 与具名键
   `512..649` 永不相等），故 `find_bind_conflict` / `update_key_capture` 都显式跳过 `mod_only` 条目。

## 6. 附记：构建环境的一个坑（与本项目无关）

在本机以 Git Bash / PowerShell 直接调 `build.bat` 时，MSBuild 可能报：

```
error MSB6001: "CL.exe" 的命令行开关无效。System.ArgumentException: 已添加项。
字典中的关键字:"Path"所添加的关键字:"PATH"
```

**不是代码或工程配置问题**：进程环境块里同时存在 `Path` 与 `PATH` 两个键（大小写重复），
`ToolTask` 构造 `ProcessStartInfo.EnvironmentVariables` 时抛异常。用一份**清理过的环境**
（键名大小写折叠后只剩一条）启动 MSBuild 即正常。
与项目无关，故不改 `build.bat`；记在这里以免下次误判为工程坏了。
