## 3. 关键设计

### 3.1 画布：纯函数布局 + 可失效缓存（ADR-018）

- 文档内部坐标以**点（pt）**为单位，`zoom` = 每点屏幕像素；`margin_px`/`gap_px` 为
  **屏幕像素**常量（换算进文档坐标时除以 zoom，使缩放时间距视觉恒定）。
- `fit_width` 派生 `zoom = (viewport_w − 2·margin_px − (cols−1)·gap_px) / (cols · max_page_w_pt)`，
  该式保证 `content_width_px ≡ viewport_w`。
- 内容窄/矮于视口时居中；否则按 scroll 偏移并钳制到 `[0, content − viewport]`。
- **以鼠标为锚的缩放**：`scroll = doc_pt · z_new − anchor`，再钳制——定点不变性由单测钉死。
- 派生量（内容尺寸、行顶前缀和）做可失效缓存；**滚动不使缓存失效**（滚动只影响原点），
  故每帧滚动仍是 O(1) 查询。
- 本期所有页面按**统一尺寸**布局（取首页尺寸）；`set_page_sizes` 接口已就位，逐页布局留后续。

### 3.2 渲染调度层：线程与纹理（ADR-019 / ADR-020）

- 单工作线程独占 `Document`；UI 线程零 `fz_*`、零阻塞。命令（打开/关闭/解锁）优先于渲染请求。
- 渲染线程用 `ID3D11Device` 直接建纹理（`CreateTexture2D` + 初始数据，`IMMUTABLE`；
  device 方法 free-threaded），上传完成即释放 `PageBitmap`。
- 被替换/逐出的纹理进**退役队列**；UI 线程**帧首** `drain_retired()` 统一 `Release`。
  正确性依据：帧 N 引用的纹理若在帧 N 期间退役，只在帧 N+1 帧首（帧 N `Present` 之后）
  释放；D3D11 的 `Release` 在 GPU 仍使用时由运行时延迟回收。
- 页状态机 `Unloaded → Loading → Loaded / Failed`；请求按 (页, 倍率) **去重**。
- 缓存：Phase 3 用**保留窗口**（可见 ± 预加载，外扩 4 页）逐出窗口外页；Phase 4 换字节预算 LRU。

### 3.3 缩放防抖（3b）

目标倍率稳定 **150ms** 后，才把 `g_want_scale` 切到新倍率请求高清重渲染；期间维持旧倍率，
页面用现有纹理**双线性放大**显示（不闪白、不错位）。首帧（刚进入阅读态）不走防抖。

### 3.4 输入映射

滚轮滚动 / Ctrl+滚轮以鼠标为锚缩放 / 左键拖拽平移 / ←→ 翻行（单列即翻页）/ ↑↓ 与
PgUp PgDn 滚动 / Home End 首末页 / G 跳页 / 1~4 列 / F 与 Ctrl+0 回 fit-width /
+/− 以视口中心缩放 / F11 全屏。

## 4. 落地过程中遇到的问题（均已解决）

1. **`std::min/max` 被 Windows 宏劫持**：`main.cpp` 新增 `std::min/max` 后报 C2589
   "`::` 右边的非法标记"。修：文件头 `#define NOMINMAX`。
2. **模块内前向声明的 COM 类型不与 `d3d11.h` 同一实体**：`render.ixx` 的全局模块片段里
   `struct ID3D11Device;` 与 `main.cpp` 里 `d3d11.h` 的完整声明不被 MSVC 视为同一类型，
   `Renderer(ID3D11Device*)` 报 C2665 无法转换。修：接口改用**不透明 `void*` 设备句柄**
   （与纹理句柄一致），实现单元再 `static_cast`——顺带强化了后端解耦。
3. **画布内联成员导致测试 LNK2019**：`Canvas::state/page_count` 等内联定义在**接口单元**
   （`canvas.ixx`）发射；`canvas_test.exe` 只链 `canvas.obj` 时缺符号。修：链接时一并
   加上 `canvas.ixx.obj`（已写入 `run_tests.ps1` 与 tests/README 备注）。
4. **两条测试期望写错**（非代码缺陷）：
   - 非均匀页尺寸用例未计入**垂直居中偏移**（内容矮于视口时 `origin_y > 0`）；
   - 空文档内容高：原实现为 `2*margin = 32`，与"无内容即无尺寸"的直觉不符。
     修：`ensure_layout` 对 `n == 0` 显式置内容尺寸为 0，并修正测试期望。

## 8. 第三轮调试修复（2026-10-05）

人工试用反馈 5 个问题，逐一定位根因并修复。**问题 3（操作过度依赖键盘）属 UI 阶段范围，
本期不动**，其余 4 项 + 1 项顺带发现如下。

### 8.1 部分 PDF 渲染形变 → 画布改用逐页真实尺寸（ADR-022）

- **现象**：部分 PDF 页面被拉伸变形。
- **根因**：画布用**首页尺寸**统一布局全部页（`set_uniform`），渲染层却按各页自身
  `fz_bound_page` 出图；PDF 允许各页 MediaBox 不同（封面/横向插页/扫描裁切不一），
  纵横比不一致时纹理被拉伸进"首页纵横比"的矩形。
- **为何既有测试没抓到**：`tests/samples/` 全是均匀尺寸。深挖发现样本生成器
  `minimal_pdf` 的 `Kids` 写成了 `4+2i`（真实页对象是 `5+2i`）→ 生成的是**非法 PDF**，
  靠 MuPDF 修复才打开、各页被修成默认 Letter 612×792。**生成器已修正**。
- **修复**：`Document::info()` 逐页探测尺寸（每页独立 `fz_try`，失败页 `{0,0}`）→
  `DocumentInfo::page_sizes` → 画布 `set_page_sizes()`（行高取行内最大、每页按自身纵横比）。

### 8.2 左右翻页在末尾卡住 → 显式阅读游标（ADR-023）

- **现象**：连续按 ←→ 到某一页后不再前进。
- **根因**：翻行以 `visible_first()` 为游标（由滚动位置反推）。视口比"一行"还高时
  （横向页 / 缩小 / 多列），末尾若干行的 `row_top > max_scroll_y`，**无法**对齐到视口顶部；
  滚到底后 `visible_first()` 停在倒数第二行 → 按键无进展。
- **修复**：画布引入阅读游标 `nav_row_`（唯一有状态量，**不参与布局**）；
  `scroll_rows(dir)` 在游标上推进，与滚动钳制解耦；到底时游标取末行（页码显示末页）。

### 8.3 缩放时闪烁 + 纹理泄漏 → 重渲染保留旧纹理（ADR-024）

- **现象**：缩放后偶发闪一下。
- **根因**：`render_one` 进入 `Loading` 时用 `PageSlot{}` 覆盖槽位 → 旧纹理立刻从快照
  消失，UI 退回"载入中…"占位框；同一动作还丢弃了旧 SRV 指针且不入退役队列 →
  **每次重渲染泄漏一个纹理**。
- **修复**：`mark_loading` 只改状态、保留旧纹理；替换时退役旧纹理；失败时保留旧纹理。

### 8.4 字偏小 / 未考虑屏幕缩放 → DPI 缩放 + 字号钩子（ADR-025）

- **根因**：字体固定 18px，ImGui 样式与自绘像素常量都不随 DPI 变化。
- **修复**：`FontScaleDpi`（自动）+ `FontScaleMain`（`g_user_scale`，将来全局设置接入点）
  + `ScaleAllSizes` + 自绘常量统一过 `px()`；基准字号 18 → 20。

### 8.5 顺带修复：布局缓存每帧失效

`Canvas::set_viewport` 原来**无条件** `dirty_ = true`，而 UI 每帧都调用它 →
"滚动不重算布局"的 O(1) 性质被破坏（每帧重算行前缀和 + 两次 vector 重分配）。
改为**无变化直接返回**，并在视口变化时 `clamp_scroll()`（避免视口变大后露出内容下方空白）。

## 9. 第四轮调试修复（2026-10-05）：快捷键失效 与 页间距

### 9.1 现象（问题一：按 1/2/3/4 不切换列数）

用户反馈：**按 1/2/3/4 不切换列数**，主键盘与小键盘都不行；**但"其他快捷键貌似能用"**。
后半句是决定性线索 —— 它否定了"焦点"方向的假设（若焦点是原因，方向键会一起失效）。

### 9.2 第一次定位：方向错了（保留作教训）

第一轮排查走的是**纯推理**：`imgui_impl_win32.cpp` 里 `'1'..'4'` → `ImGuiKey_1..4`、
`VK_NUMPAD1..4` → `ImGuiKey_Keypad1..4` 且 `WM_KEYDOWN` 里已 `AddKeyEvent`；全库检索确认
ImGui 核心从不引用数字键；`IsKeyPressed` 走 `TestKeyOwner(key, ImGuiKeyOwner_Any)`。
⇒ 推出"键位已到 ImGui，唯一拦截点是应用自己的 `!focused` 门"，据此修了焦点问题
（ADR-026）并补了小键盘映射（ADR-027），**并直接提交了**。

**用户实测否掉了这个结论**：`focus 1`（画布有焦点）时数字键依旧无效，且其他快捷键正常。
⇒ 推理链里有一个未经验证的前提："**键位确实到达了 ImGui**"。它恰恰是错的。

### 9.3 第二次定位：现场取数，一次命中

不再推理，在 F3 浮层里加**分层诊断**：窗口层原始消息（`WM_KEYDOWN`/`WM_CHAR` 的原始码）、
ImGui 侧键状态（`IsKeyDown`）、应用侧（`pressed_column_key()` 返回值、`set_columns` 调用次数、
`handle_canvas_input` 调用次数）。用户一次按键即定位，读数：

```
build Oct  5 2026 20:39:27              ← 确认跑的是新构建
WM_KEYDOWN: E5 E5 E5 E5 72              ← 0xE5 = VK_PROCESSKEY；0x72 = VK_F3
WM_CHAR   : 0032 0032 0032 0032 0032    ← 0x0032 = '2'，字符照样送达
imgui down  1234: 0 0 0 0   pad: 0 0 0 0
colkey 0   set_columns calls 0   handle_input calls 2009
canvas hover 0  focus 1  text-input 0
```

### 9.4 真根因：输入法吞掉字母/数字键（ADR-028）

输入法启用时，Windows 把字母/数字键的 `WM_KEYDOWN` 的 `wParam` 换成占位码
**`VK_PROCESSKEY (0xE5)`**（真实键码只交给输入法），字符则用 `WM_CHAR` 交给应用。
ImGui 的 win32 后端 `ImGui_ImplWin32_KeyEventToImGuiKey()` 的 switch **没有 0xE5 这个 case**
（已全文件检索确认），于是 `key == ImGuiKey_None` → `AddKeyEvent` 被跳过 →
**`ImGuiKey_1..4` 根本不置位**。表现为"**字符到了、按键没到**"。

影响面不止数字键：**所有字母键（`G` 跳页、`F` 回 fit-width）以及数字键**都被吞；
只有 F 系列、Esc、方向键、PgUp/PgDn 等"输入法不接管"的键能穿透 —— 用户"其他快捷键能用"
指的正是这几类。

### 9.5 修复

- **让阅读窗口脱离输入法**（ADR-028）：窗口创建后 `ImmAssociateContext(hwnd, nullptr)`，
  并链接系统库 `imm32.lib`（`src/LilithReader.vcxproj`）。键盘回归原生语义。
  理由：本阶段没有任何需要输入法的文本输入（唯一的文本框是纯数字页码）；这也是唯一能让
  **所有**键可靠工作的做法，不依赖"输入法是否把字符透传"。
  **后续约束**：将来加中文输入框时必须改回"仅在文本输入激活时关联"。
- 同轮保留两处**旁路隐患**的修复（ADR-026 焦点门、ADR-027 小键盘映射）—— 它们不是本次
  症状的根因，但本身确实会让快捷键静默失效。

### 9.6 证据

### 9.8 问题二：页间距固定，缩小时显得过大（ADR-029）

- **现象**：用户反馈"页面的间隔貌似是固定的，理想情况最好随着缩放改变，不然页面缩小的
  时候感觉上的间距会显得太大"。
- **根因**：`gap_px` 是**屏幕像素常量**，`ensure_layout` 里除以 zoom 换算进文档坐标 ——
  屏幕间距恒为 `gap_px`，与缩放无关。页面缩小而间距不变，视觉比例失衡。
- **修复**：间距改为"**列宽（最宽页）的比例**" `gap_ratio`（默认 0.013），
  屏幕间距 = `gap_ratio × 列宽 × zoom`，**严格正比于 zoom**；`fit_width` 方程把间距项
  放进分母，**"内容宽恰等于视口宽"的不变量仍严格成立**。留白 `margin_px` 保持屏幕像素
  （界面 chrome，不该随缩放）。用比例而非固定 pt，是为了让不同页幅的文档视觉比例一致；
  且在 fit-width 单列下屏幕间距 = 比例 × 视口宽，与本轮修改前观感一致（约 1.3% 视口宽），
  **默认视图无可见回归**。
- **证据（自动化，用户已说明无需人工验证）**：`canvas_test.cpp` 新增
  `test_gap_scales_with_zoom`（5 例），把"间距 ∝ zoom"钉死；另有 7 处按旧语义写死的
  期望值改为按定义独立重算（新增 `gap_at(zoom)` / `fit_zoom(cols)` 两个独立推导的辅助函数）。
  最终 `canvas_test` **92 通过 / 0 失败**、`doc_test` **43 通过 / 0 失败**。
