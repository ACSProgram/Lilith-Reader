# 交互与动效优化轮（2026-10-06）

> 归档：本文件记录 2026-10-06 这一轮"按键自定义 + 动效补齐 + 窗口/全屏闪烁修复"的实施过程、
> 根因分析与验证结论。**当前事实**以 [02-架构设计](../../02-架构设计.md) §7/§7.1 与
> [ADR-054~061](../../03-决策记录.md) 为准；本文件只记录"当时发生了什么"。

## 1. 范围

用户提出四项诉求：① 字体子集内嵌到底有什么用（体积没缩）；② 人工验证 7 大项已过，但动效仍有
未覆盖处（侧栏弹出、设置窗口开合）；③ 实现按键自定义，用它替代"快捷键与帮助"窗口（或并入设置分栏）；
④ 后续多轮反馈的动效与闪烁问题。

最终落地：**按键自定义**（ADR-054）、**动效补齐**（ADR-055/056/059/061）、
**窗口与全屏闪烁修复**（ADR-057/058/060/061）。

## 2. 触发的问题（人工反馈原文要点）

1. "字体子集内嵌有什么作用？体积也没有缩小啊。"
2. "动画没有全覆盖，还有一些弹出窗口没有动画，比如跳转页码，不要我说设置你只做了设置，自己要检查。"
3. "窗口打开关闭的动画手感有点怪怪的，因为是逐渐消失的模式，好像很少有窗口动画是这样的。"
4. "esc 退出全屏的时候会导致窗口变化后又归位。" → 后续："特别是窗口最大化的时候退出全屏，
   窗口会往左上缩然后归位，产生较大抖动，非最大化的时候全屏，一瞬间也会有闪烁。"
5. "跳转页码关闭的时候会闪烁一下。"
6. "窗口动画可以再稍微利落一点（非线性变化，或者简单加速）。"
7. "最小化窗口的过程会有帧闪烁。"

## 3. 根因与修复

### 3.1 字体子集内嵌的作用（答疑，无代码改动）

子集（`assets/ui_font_subset.otf`，1.04 MiB）的作用**不是压体积**，而是让界面观感固定、不依赖
系统字体（非中文 Windows 上界面自述文字不缺字）。exe 约 40 MiB 的主体是 MuPDF 内置的 CJK
**文档**兜底字体（约 34 MiB），与界面字体无关。结论：保留。

### 3.2 按键自定义：输入映射收敛为命令表（ADR-054）

改前快捷键散落在 `handle_canvas_input` / `draw_shell`，一条命令一处 `IsKeyPressed`，改键无从谈起；
"快捷键与帮助"窗口列的是**写死的字符串**，与实现天然漂移。

改为 `Cmd` 枚举 + `kCmds[]`（id/分组/显示名/是否连发/是否全局/两个默认键槽），生效键存 `g_binds`，
派发只有 `cmd_pressed(Cmd)` 一条路径；设置窗口新增「按键」分栏，删除帮助窗口；
`Esc` 语义改为"关对话框"的固定键并默认绑定全屏（不再"关文档→退出"）。

### 3.3 窗口开合动画：从"整窗淡出"到"缩放+淡入淡出"再到"定时补间"（ADR-055/056/061）

三轮演进，每次都是**人工体感**驱动的：

| 轮次 | 做法 | 问题 |
|---|---|---|
| 一（ADR-055） | 只对 alpha 做一阶滞后 | 关闭时窗口**原地保持原尺寸**、内容逐渐透明 —— "逐渐消失的模式，很少有窗口动画是这样的" |
| 二（ADR-056） | 以窗口中心为不动点，尺寸 96%↔100% + 透明度 0↔1 | 手感仍"软"：一阶滞后收敛到 99% 之后还要再磨一个时间常数 |
| 三（ADR-061） | **定时补间 + 三次缓出**（`ToggleAnim`，160ms） | 达标 |

同时补上"静止后交还 ImGui、用户拖动位置被记录为下次缩放基准"（否则关闭时会把窗口拉回屏幕中央）。

### 3.4 弹出对话框动效 + 关闭闪帧（ADR-059/061）

跳页 / 密码弹窗原为"啪"地出现与消失。改为**淡入淡出 + 轻微滑落**，并用**延迟关闭**
（逻辑关闭只把目标进度降到 0，收敛后才真正 `CloseCurrentPopup`）。

**关闭闪帧的根因**：动画收敛那一帧走的是"关闭分支"，只调了 `BeginPopupModal` + `CloseCurrentPopup`，
**没有套用 alpha 样式** —— 于是以 ImGui 默认不透明度（1.0）多画了一帧再销毁，即"闪一下"。
修复：`popup_anim_apply` 改为**无条件**套用（收敛帧 value 已是 0，全透明后再销毁）。

**刻意不做缩放**：这两个弹窗是 `AlwaysAutoResize` 的输入框，缩小外框会让内部固定宽度控件
（页码输入框：窗口约 156px、内宽 140px，缩 4% 即切掉 6px）被裁剪。

### 3.5 全屏切换闪烁：三轮才找到真正的层面（ADR-057/058/060）

| 轮次 | 假设 | 结论 |
|---|---|---|
| 一（ADR-057） | swapchain 重建时机 | `WM_SIZE` 在 `SetWindowPos`/`SetWindowPlacement` 中**同步**到达，当场 `ResizeBuffers` 会让"按旧尺寸排布的本帧绘制数据"被画进新尺寸后备缓冲。改为**帧首统一应用**。部分有效 |
| 二（ADR-058） | Win32 调用顺序 | 退出全屏改为**先提交样式（FRAMECHANGED）再落位**，避免"用未生效的无边框度量摆窗口、再被帧重算挪一次"。部分有效 |
| 三（ADR-060） | **执行时机** | 命令派发在 `NewFrame()` **之后** —— 在帧中途改窗口几何，本帧绘制数据就已与窗口矩形不一致，只能被 DWM 拉伸。改为**帧间执行**（`g_request_fullscreen_toggle`）。**普通窗口闪烁由此消除** |

第三轮是真正的层面：**窗口几何是帧级状态，任何改变它的操作都必须在帧边界完成**，
在帧中途改则无论怎么调顺序都救不回来。

### 3.6 最小化闪帧（ADR-061）

**根因**：最小化后客户区为 0 → ImGui 视口 0 尺寸 → **什么都画不出**，整帧只剩
`ClearRenderTargetView` 的清屏色（深蓝），在收起动画里就是一闪。

修复：`WM_SIZE(SIZE_MINIMIZED)` 置 `g_minimized`，主循环帧首 `Sleep(10); continue;` **整帧不渲染**
（与 ImGui 官方 DX11 示例处理 occluded 的写法一致）。顺带省掉最小化期间的 CPU/GPU。

## 6. 遗留缺陷（不阻塞）

**最大化状态下退出全屏有一次可见抖动**（窗口先向左上收缩再归位）。

已排除：命令派发时机（ADR-060）、Win32 调用顺序（ADR-058）、swapchain 重建时机（ADR-057）。
**剩余疑点**：`SetWindowPlacement(SW_SHOWMAXIMIZED)` 内部会"先落到 `rcNormalPosition`、再最大化"，
这个**单次 Win32 调用内部的中间几何**被 DWM 合成出来 —— 帧首纪律管不到它。

下一步候选：① 转换期间用 `WM_SETREDRAW` / `ShowWindow(SW_HIDE)` 抑制中间帧；
② 进入全屏前先 `SW_RESTORE`、退出后重新最大化；③ 验证是否与系统"最小化/最大化时动画"开关相关。
已记入根 README「已知问题」。
