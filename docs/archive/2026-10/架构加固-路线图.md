## 1. 来源与总览

来源：一次外部架构复查报告。其结论是——功能已相当完整、自动化覆盖尚可，**不需要推倒重写**；
但代码已进入"功能能用、边界开始互相缠绕"的阶段，继续直接加功能会放大维护成本。
最该先处理的是**边界、状态模型与异步原则**。

分批原则（对应 [AGENTS.md](../../../AGENTS.md) §3）：

- 一批一个主题、先出 ADR，再动代码；
- **保持对外 API 不变**，把回归面压到最小；
- 能写成断言的进 `tests/`，只能眼判的进 `04-人工验证.md`；
- 一批收尾即编译零错、测试全绿、文档同步、立即提交。

**报告核对结论**（本路线图据此排序）：

- 多数指控属实，已逐条定位到源码；个别夸大（`01-计划.md` 早已声明进入正式阶段、
  `02` 内并无 "Phase N" 字样，带 Phase 字样的是各 `*.ixx` 头注释）。
- 两处产品决策已定：**`can_copy` 保持放行**（不联动，仅改说明）；**格式识别保留扩展名闸门**、

## 2. 问题清单（分批依据）

> 已按报告核对并定位到源码。**加粗**是与本路线图批次直接相关的项。

**A. 最高优先级**

1. UI 线程阻塞与文件 I/O —— 本批已处理异步持久化与 `file_exists` 预检；
   **残留**：`platform.cpp` 剪贴板失败时的 `Sleep(10)` 重试（→ 第五批）。
2. **三套状态模型** —— app 的 `UiDoc`、render 的 `DocState`/`DocPhase`、`session.cpp` 的 `g_*`
   各持一套文档状态；异步结果靠 `request_id` 与 `g_doc.kind` 多处配合验收，
   存在"旧结果晚到污染新文档"的窗口（→ 第三批）。
3. document MuPDF 边界 —— 本批已处理 `PageBitmap` 属性快照与销毁边界；
   **残留**：覆盖全模块的 `fz_*` 静态检查（→ 第五批）。
4. **渲染器职责过载** —— `render.cpp` 的 `Renderer::Impl` 曾同时管文档生命周期、渲染、缩略图、
   搜索、文本抽取、图片复制、LRU 缓存、D3D 纹理所有权、退役队列、工作线程调度、故障隔离
   （**已随第二批拆为五个内部组件，ADR-085**）。
5. **页状态是多布尔字段拼出的状态机** —— `Entry` 曾有 `status / stale / manual_retry /
   auto_retries / failed_scale`，存在理论上不应出现的组合（**已随第二批收进 `PageState` 显式
   状态机，ADR-085**）。

**B. 补丁式结构**

- `app_internal.h` ≈709 行跨 TU 可变全局；`ui.cpp` ≈2213 行混合绘制/设置/菜单/弹窗/文本布局；
  `session.cpp` ≈1429 行混合文档状态/输入映射/阅读位置/动画/文本选择/搜索；
  `render.cpp` ≈1800（第二批已按职责组件化，体量未减但边界清晰，ADR-085）、`document.cpp` ≈1611。
- **扩展名/格式判断两处维护**（`utils.ixx` 白名单 vs `document.cpp` 的 `extension_family`，
  注释已承认"需保持同步"）；命令 ID 历史名（`ToggleInvert`/`ToggleSepia`）混在当前业务语义里。
- 优先拆 `app` 与 `render`，**先不要继续加搜索/批注/多标签等功能**。
- 落位：app 拆分（→ 第三批）、render 拆分（**已完成，第二批/ADR-085**）、扩展名归一（→ 第五批）。

**C. 功能缺口**

- 阅读位置**不是持续保存** —— 本批已处理（防抖 + 退出 flush）。
- `can_copy` 已读未生效 —— **产品决定：不联动**（已改 README）。
- 格式识别文案与真实行为不一致 —— 本批已改 README（保留闸门）。
- `.mobi` 无真实样本、失败提示体系、D3D 设备丢失恢复、UI 层自动化缺口 —— 见第四批。

**D. 文档**

  —— 见第四批（代码稳定后再做，避免文档反复改）。

## 3. 第二批：拆渲染后台服务（报告 §五 第 4 步）—— 已完成，ADR-085

- **问题**：`Renderer::Impl` 已不是"渲染调度层"，而是一个大型后台应用服务；加新功能只能继续往
  `Impl` 加字段和分支。
- **目标**：**单工作线程不变**，把 `Impl` 拆成内部组件，**先保持外部 API 不变**以缩小回归面。
- **组件划分**（报告建议）：DocumentWorker（文档生命周期与 MuPDF 调用）/ PageScheduler
  （可见页、预加载、重试）/ TextureStore（纹理所有权、缓存、退役）/ ContentService
  （文本、图片、链接）/ SearchJob（搜索代次、取消、结果发布）。
- **附带**：`Entry` 状态机显式化 —— 用状态对象 + 转移函数表达
  `Unloaded → Loading → Loaded`、`Loaded → Refreshing → Loaded`、`Unloaded → Loading → Failed`，
  把"手动重试 / 自动重试 / 旧纹理保留"作为转移语义，而非外部字段组合。
- **先出 ADR**：组件边界与共享状态归属（谁持 `Document`、谁持纹理、谁持退役队列、谁持搜索代次）。
- **涉及文件**：`src/render/render.cpp`、`src/render/render.ixx`（+ 可能新增内部头/子单元）。
- **验收**：外部 API 与现有行为不变；`tests/render_search_test.cpp`、`tests/render_fault_test.cpp`
  保持全绿（它们已覆盖跨线程检索与故障隔离/洪峰/超大页）；可抽的纯逻辑（如退役/LRU 选择）继续单测。
- **风险**：线程与所有权边界一动就出竞态/悬垂。全程以 `render_fault_test` 的坏文件、请求洪峰、
  1200 页、A0 幅面等路径压测；每完成一个组件就跑一次全量。

## 4. 第三批：拆应用层（报告 §五 第 5 步）

- **问题**：`UiDoc` / `DocState` / `g_*` 三套状态；`session.cpp` 与 `ui.cpp` 巨型化；
  异步结果分散验收。这是**最大的一批、回归面最广**。
- **目标**：把 `app_internal.h` 的跨 TU 全局状态收进 `AppContext`，再拆：
  SessionController / InputBindings / ViewMotion / TextInteraction / SearchController /
  SettingsController / UI 绘制模块。
- **关键决定（先出 ADR）**：
  1. **单一会话状态源**（SessionController），渲染层与 UI 层都变成它的**投影**；
  2. 所有异步结果带**文档代次 + 请求代次**，在**统一处**验收（落实 ADR-081 第 2 条）；
  3. UI 绘制模块的划分与依赖方向（避免再次把绘制/逻辑混回一个 TU）。
- **涉及文件**：`src/app/app_internal.h`、`src/app/session.cpp`、`src/app/ui.cpp`、
  `src/app/main.cpp`、`src/app/platform.cpp`。
- **验收**：行为不变；把 app 层可判定的纯逻辑（输入映射表、命令冲突、阅读数据维护等）迁入
  `tests/`；`run_tests.ps1` 全绿；`build.bat` 0 警告。
- **风险**：一次拆完的回归面过大。建议**先 AppContext + SessionController**（收益最大、最先解决
  "状态互相缠绕"），UI 绘制模块化允许留尾到第五批。
- **已完成（第一步，ADR-086）**：`app_internal.h` 的跨 TU 可变状态收进 `AppContext`（单例 `g_app`，
  纯迁移、逐处 `g_x` → `g_app.x`）；文档/会话状态收进 `AppContext::session`（`SessionController`），
  成为单一状态源；打开/认证结果在 `SessionController::poll()` 按**文档代次 + 请求代次**统一验收，
  取代原先分散在 `poll_document` 里的判据。外部行为与 `app_internal.h` 的自由函数 API 不变；
  `build.bat` 0 警告、`tests/run_tests.ps1` 全绿（`check_theme_*` 源文本断言同步到新名字）。
- **已完成（第二步，ADR-087）**：会话侧四个控制器各自成 TU —— 命令/按键绑定 →
  `input_bindings.cpp`、视图动效 → `view_motion.cpp`、文本交互/剪贴板 → `text_interaction.cpp`、
  全文搜索 → `search.cpp`；`session.cpp` 只留 `SessionController`、视图变换/逐页尺寸、画布输入、
  缩放防抖与渲染请求。状态归属不变（仍在 `AppContext`）、对外 API 不变，是**纯迁移**。
  `build.bat` 0 警告、`tests/run_tests.ps1` 全绿。
- **剩余切片**：SettingsController 与 `ui.cpp` 的绘制模块化（两者同在 `ui.cpp`；路线图已明确
  允许留尾到第五批 —— `ui.cpp` 被 `check_menu_width.py` / `check_theme_precedence.py` 等源文本
  门禁按文件路径读取，拆分须同步改门禁）。
