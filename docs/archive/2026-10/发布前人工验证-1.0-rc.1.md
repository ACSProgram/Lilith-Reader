## 附带完成：`/analyze` 静态分析逐条判定（2026-10-07）

工具：`cl.exe /analyze`（`/std:c++20 /MT`，被引用的 IFC 同带插桩），Release x64。
**注意**：走 MSBuild 的 `/p:RunCodeAnalysis=true` 在本机会撞 `MSB6001`（进程环境块 `Path`/`PATH`
重复，见 [架构设计 §8.0](../../02-架构设计.md)），故改为直调 `cl.exe`。

结果：**0 错误 / 6 条告警**，逐条核对代码后的判定：

| 告警 | 位置 | 判定 | 依据 |
|---|---|---|---|
| C6262 函数使用堆栈 65544 字节 | `utils.ixx` `to_absolute` | **真问题（低危）→ 已修** | `wchar_t buf[32768]` 是 64 KiB 栈帧；同文件 `exe_dir()` 早已用堆分配，此处不一致。已改为 `std::wstring` 堆缓冲，修复后该告警消失 |
| C6001 使用未初始化的内存 `*buf` | `document.cpp` `outline()` | 误报 | `walk_outline` 对 `buf[count++]` 逐项完整赋值（`depth` / `page` / `title[0]` 与 NUL 结尾），读取区间 `[0,count)` 全部已初始化；分析器看不穿函数边界。**刻意不改成值初始化**：`kMaxOutlineNodes = 2048`、每项 392 B，等于每次调用 memset ≈ 784 KiB，不划算 |
| C28193 `marks` 保存了一个必须检查的值 | `document.cpp` `search_page()` | 误报 | 分配后紧接一行即 `if (quads == nullptr \|\| marks == nullptr)` 判空 |
| C6385 从 `quads` 读取的数据无效（cap*32 vs 64） | `document.cpp` `search_page()` | 误报 | `cap == max_hits`，且 `n` 在调用后被钳到 `<= max_hits`，循环 `i < n ≤ cap`，不可能越界 |
| C28182 解引用 NULL 指针 | `document.cpp` `render_page_region()` | 误报（模式性） | `new (std::nothrow) Impl{...}` 的下一行即判空；分析器把值初始化误当成对返回指针的解引用 |
| C28182 解引用 NULL 指针 | `persist.cpp` 构造函数 | 误报（模式性） | 同上：`new (std::nothrow) Impl{}` 后下一行立即 `if (!impl_) return;` |
