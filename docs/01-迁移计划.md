# Lilith Reader 迁移计划

> 来源：`F:\programs\Lilith\Lilith\Modules\Document\MuPDF\`（MuPDFCore + MuPDFViewer）
> 制定日期：2026-10-05
> 原则：**分阶段可验证、每阶段可运行、稳定性优先于功能堆叠。**

**纪律（2026-10-05 起）：开发过程中不实际运行本软件做测试（编译与自动化测试除外）。需要人工运行确认的验收项，统一记录在 [人工验证](04-人工验证.md)，写明"做什么、做到什么样算通过"，由人工按文档执行。**

## 0. 现状与差距分析

### 0.1 可直接继承的资产（已验证可用）

| 资产 | 位置 | 说明 |
|---|---|---|
| MuPDF 封装 | `MuPDFCore.ixx/.cpp` | `fz_context`/`fz_document` RAII 封装、`fz_try/catch` 错误处理模式、display list 能力 |
| 页面渲染管线 | `Document::renderPage` | 96dpi 基准渲染 → 位图；骨架正确，细节需改造 |
| 并发模型 | `MuPDFViewer` | ThreadPool + LRU 页缓存 + Loading 占位 + 相邻行预加载 + `viewing` 标记防止释放正在浏览的页 |
| ImGui 全套 | `Lilith/ImGui/` | 1.91.9 含 freetype、DX12/Win32 后端；换 DX11 后端即可 |
| 模块化风格 | 全项目 `.ixx` | C++20 modules 组织方式直接沿用 |

### 0.2 必须抛弃/重做的部分

| 问题 | 现状 | 处理 |
|---|---|---|
| OpenCV 中间层 | `pixmapToMat` RGBA→BGR 逐像素拷贝，再转纹理 | **删除**。MuPDF 直接生成 RGBA pixmap，`fz_pixmap_samples` 一步上传 GPU 纹理 |
| ImPlot 画布 | 用 ImPlot plot 当网格画布，坐标系绕（y 轴负方向、PlotToPixels 换算） | **删除**。自研画布（见架构文档 §2） |
| 固定 96dpi 渲染 | 放大只做纹理拉伸 → 模糊 | **重做**。按当前 zoom 渲染对应 DPI，防抖后高清换入 |
| 双 Document 绕线程限制 | `file_`/`file_render_` 两个 context 回避 fz_locks | **重做**。规范线程模型：每工作线程 `fz_clone_context`，或配置 `FZ_LOCKS` |
| 渲染失败态缺失 | 渲染任务抛异常后 `status_` 永远停在 Loading（白屏） | **补齐** `Failed` 状态 + 错误占位 + 有限重试 |
| 缓存预算按页数 | `MAX_COLUMNS * (MAX_LINES + 3)` | **改为按字节预算**（如 512MB），高 zoom 下单页可达几十 MB |
| 宿主依赖 | bass/Live2D/Qt/nvml/spdlog/Http 等 | 全部不带入 |

## 1. 阶段计划

### Phase 0：项目骨架与环境准备（✅ 已完成，2026-10-05）

**第一步：第三方库环境准备（独立步骤，最先执行）**
- [x] 全新下载**最新版** ImGui（1.93.0 WIP @ ed73ef4），不复制 Lilith 里的 1.91.9 WIP 旧版
- [x] 全新下载**最新版** ImPlot（1.1 WIP @ 09e2ba7）——最终产品用自研画布，ImPlot 作为交互参考基准与调试可视化备用引入
- [x] 采用 **DX11 后端**（`imgui_impl_dx11` + `imgui_impl_win32`），替换原项目的 DX12 后端
- [x] 建立 vcxproj：`/MT` 静态 CRT、vcpkg manifest 集成、triplet `x64-windows-static`
- [x] **跑通基本程序**：Win32 窗口 + D3D11 + ImGui 清屏 + 框架状态窗口（FPS/演示开关/中文字体）
- **验收（已通过）**：Release 编译，exe 仅依赖系统组件 DLL（d3d11、d3dcompiler_47、user32 等，无 CRT/第三方 DLL，dumpbin 验证），窗口可拖动缩放、Per-Monitor DPI aware、进程冒烟存活

**第二步：项目骨架收尾**
- [x] git 仓库 + README + docs 框架
- [x] vcpkg.json manifest（mupdf 暂缓至 Phase 2 开工时加入，避免首次构建被静态编译 MuPDF 阻塞）
- [x] 目录骨架 `src/{app,document,canvas,render,utils}`
- [x] 下载的 ImGui/ImPlot 源码放入 `third_party/`，随仓库提交（锁定版本）
- [ ] MuPDF 静态库经 vcpkg 就位并能在空程序中 `fz_new_context` 编译链接成功（Phase 2 开工时执行）
- **验收**：`git clone` 后按 README 一次构建成功。

> 工具链注意：MSVC 14.51（PlatformToolset v145，VS 18 Community）；构建脚本 `build.bat`。

### Phase 1：应用外壳（✅ 已完成，2026-10-05）
- [x] Win32 窗口 + D3D11 + ImGui 初始化（RAII 顺序管理，Phase 0 骨架延续精简）
- [x] 命令行解析：`LilithReader.exe <路径>`（`CommandLineToArgvW`，相对路径转绝对路径）；无参数时显示拖放引导界面
- [x] 文件拖放打开（`DragAcceptFiles`/`WM_DROPFILES`，多文件取第一个）
- [x] 窗口状态持久化（位置/尺寸/最大化，写 exe 同目录 `LilithReader.ini`；恢复前校验矩形至少 100×100 落在虚拟屏幕内、最小 400×300，无效回退默认值；负坐标经 `GetPrivateProfileStringW` 读取以支持多显示器）
- [x] 格式识别占位页：拖入/命令行打开文件后按扩展名分流——受支持格式（pdf/epub/mobi/fb2/cbz/xps）显示"已识别，Phase 2 接入渲染核心"占位页；不受支持显示"暂不支持的格式"；路径不存在显示"文件不存在"
- [x] 新增 `src/utils/utils.ixx` 模块（C++20 modules 首例）：路径/扩展名/UTF-8 转换/ini 读写，为后续阶段建立模块组织先例
- [x] F3 调试浮层（FPS/分辨率）；Esc：有文档返回引导页、无文档退出；WM_DPICHANGED 跟随系统建议矩形；最小窗口 480×320
- **验收（编译已通过，运行项转人工验证）**：见 [人工验证](04-人工验证.md) §1。

### Phase 2：MuPDF 文档核心移植
- [ ] 移植 `Document` 类：去 OpenCV、`renderPage` 返回 RGBA pixmap 视图（不拷贝，上传后由纹理层接管生命周期）
- [ ] 线程模型修正：渲染线程池每线程 `fz_clone_context`；document 级操作加 `fz_lock` 或串行化到单渲染线程（阅读器单线程渲染足够，优先简单）
- [ ] `fz_try/catch` 全覆盖审查：任何 fz_* 失败不得逃逸出模块边界
- [ ] 打开失败/损坏文件路径：返回结构化错误码（区分：不存在/格式不支持/文件损坏/加密）
- **验收**：用 fuzz 集合（空文件、改后缀的假 PDF、截断的 PDF、加密 PDF）逐个打开，全部优雅报错不崩溃。

### Phase 3：自研画布（核心工作量）
按架构文档 §2 实现，拆分三步：
- [ ] 3a 单页视口：fit-width/fixed-zoom 两模式、连续滚动、滚轮滚动、键盘翻页
- [ ] 3b 缩放：Ctrl+滚轮以鼠标为中心缩放，150ms 防抖触发按新 zoom 的高清重渲染，期间显示低清占位（渲染自旧纹理双线性放大）
- [ ] 3c 多列网格：1~4 列，列间距/页间距统一布局函数；网格模式下滚轮按行滚动
- **验收**：1000 页 PDF 滚动/缩放不卡帧（帧时间 < 8ms，不含后台渲染）；缩放过程中无闪白、无错位。

### Phase 4：渲染调度与纹理管理
- [ ] 页缓存 LRU 改为**字节预算**（默认 512MB，设置可调 128MB~2GB）
- [ ] 纹理延迟释放队列：删除的纹理必须先经历"帧末从 draw list 解除引用 → 下一帧释放"，杜绝悬空纹理句柄
- [ ] 渲染失败状态机：`Unloaded→Loading→Loaded/Failed`，Failed 显示错误占位 + 点击重试，最多自动重试 1 次
- [ ] 预加载策略：可视行 ±1 行；方向感知（向下滚动只预加载下方）
- **验收**：连续快速滚动 10 分钟，内存曲线平稳有界；任务管理器无 GDI/句柄泄漏。

### Phase 5：阅读功能
- [ ] 记住阅读位置（文档哈希为键，存 exe 同目录 `reader_state.bin`）
- [ ] PDF 目录（outline）侧栏 + 跳转
- [ ] 书签、页面缩略图侧栏（缩略图复用渲染管线，低 DPI）
- [ ] 旋转（0/90/180/270）、双页对开（书籍模式）
- [ ] 反色/护眼模式（shader 或 CPU invert，渲染线程做）
- [ ] 加密 PDF：密码输入对话框 + `fz_authenticate_password`（支持 AES-256 等 PDF 标准加密），权限位读取并在 UI 层尊重（禁复制/禁打印时相应功能置灰）
- **验收**： epub/mobi/cbz 各取 3 个样本文件验证多格式渲染质量，记录已知排版缺陷。

### Phase 6：美化
- [ ] 字体：子集化中文字体嵌入 exe（见架构文档 §4），imgui_freetype 高质量渲染，生僻字 fallback `msyh.ttc`
- [ ] 明/暗/护眼三主题，跟随系统可切换
- [ ] 微动效：页面淡入、缩放平滑插值、滚动条自动隐藏
- [ ] 最小化 UI：工具栏自动隐藏，快捷键完备（←→↑↓翻页、Ctrl+滚轮缩放、G 跳页、F11 全屏）
- **验收**：主观评审 + 100%/150%/200% DPI 缩放下无模糊错位（Per-Monitor DPI aware v2）。

### Phase 7：稳定性加固与发布
- [ ] 顶层异常防线：`std::set_terminate` + 无人值守 MiniDump（exe 同目录 `crash/`），崩溃后下次启动提示并询问上报
- [ ] 每帧 `TryInvoke` 式异常边界：单页渲染异常只影响该页，不影响进程
- [ ] 压力测试脚本：1000+ 页文档、超大幅面页面（A0 海报 PDF）、损坏文件批量、快速缩放抖动
- [ ] 静态分析：`/analyze`、AddressSanitizer 跑一轮完整冒烟（Debug 配置）
- [ ] 发布打包：图标、版本资源、`register_open_with.reg`（可选注册打开方式）、UPX 可选
- **验收**：48 小时日常使用零崩溃；crash 目录为空。

## 2. 里程碑与依赖关系

```
Phase 0 ─→ Phase 1 ─→ Phase 2 ─→ Phase 3 ─→ Phase 4 ─→ Phase 5 ─→ Phase 6 ─→ Phase 7
 骨架        外壳       MuPDF核心     画布★        调度         功能         美化        加固发布
```

- Phase 3 是最大风险点（自研画布交互工作量最大），3a/3b/3c 每步独立可演示。
- Phase 4 的纹理延迟释放必须与 Phase 3 同期定稿接口，避免画布直接持有裸纹理指针。
- Phase 5 之后即可日常自用（dogfooding），Phase 6/7 可根据体感迭代。

## 3. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| MuPDF AGPL 协议 | 闭源商业分发受限 | 当前自用/开源无碍；若商用换 PDFium（BSD），Core 层接口按此预留抽象 |
| vcpkg mupdf 静态 triplet 构建问题 | Phase 0 阻塞 | 备选：自行用 MuPDF 源码 + VS 编译静态库（官方支持 msvc-build） |
| epub 排版质量不佳 | 多格式体验参差 | epub 渲染缺陷记录在案，不承诺完美；PDF 优先级永远最高 |
| 自研画布交互手感不及 ImPlot 成熟 | 体验打折 | 先复刻 ImPlot 行为基线，再做平滑动画增强 |
| 大页面（A0/长图式 PDF）内存峰值 | OOM/卡顿 | 渲染尺寸上限钳制 + 分块渲染预留（tile 接口） |

## 4. 体积预算

| 组成 | 预估 |
|---|---|
| MuPDF 静态库（多格式全开） | 15~25 MB |
| ImGui + freetype | ~1 MB |
| 嵌入字体子集 | 1.5~2 MB |
| 静态 CRT + 其余代码 | ~2 MB |
| **合计目标** | **< 30 MB** |

若需极限压缩：MuPDF 裁剪至仅 PDF（去掉 epub/mobi 解析器）可再省 5~8MB，作为可选项保留。
