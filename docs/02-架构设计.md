# 架构设计

> 配套阅读：[迁移计划](01-迁移计划.md)、[决策记录](03-决策记录.md)

## 1. 总体结构

```
┌────────────────────────────────────────────────────┐
│ src/app        入口 / Win32 / D3D11+ImGui / 命令行  │
├────────────────────────────────────────────────────┤
│ src/canvas     自研画布：布局·缩放·平移·滚动·网格    │
├────────────────────────────────────────────────────┤
│ src/render     渲染调度：线程池·LRU字节预算·纹理池   │
├────────────────────────────────────────────────────┤
│ src/document   MuPDF 封装：Document·页面·密码·目录  │
├────────────────────────────────────────────────────┤
│ src/utils      路径/字符串/日志/崩溃转储            │
└────────────────────────────────────────────────────┘
```

依赖方向自上而下单向；`document` 与 `canvas` 互不 import，通过 `render` 调度层衔接——这是为将来替换 MuPDF 为 PDFium 预留的解耦（ADR-003）。

## 2. 自研画布设计

### 2.1 视图状态（唯一真源）

```
struct CanvasState {
    float   zoom;            // 每点屏幕像素（fit_width 时该值被派生值覆盖）
    float   scroll_x;        // 内容坐标（px）水平偏移
    float   scroll_y;        // 内容坐标（px）垂直偏移
    int     columns;         // 1~4 列
    bool    fit_width;       // fit-width 模式时 zoom 派生
    float   margin_px;       // 四周留白（**屏幕像素**：界面 chrome，不随缩放）
    float   gap_ratio;       // 页间/列间间距，占列宽比例（**文档空间**：随缩放，ADR-029）
};
```

页面布局是**纯函数**：`page_rect(index, state) → 屏幕矩形`。任何输入（滚轮/拖拽/键盘）只修改 state，渲染每帧按 state 重算布局。无 Invalidate 区域管理，天然可预测。

> **唯一的有状态量：阅读游标 `nav_row_`（ADR-023）**。它是"当前读第几行"，只服务翻页
> 与页码指示，**不参与任何布局计算**——布局仍是纯函数。之所以必须存在：当视口比"一行"
> 还高时（横向页 / 缩小 / 多列），末尾若干行的 `row_top` 会超过 `max_scroll_y`，无法对齐到
> 视口顶部；若翻页游标只能由滚动位置反推，就会在末行前反复无进展（"卡住"）。
> 手动滚动/缩放后游标按"视口顶部所在行"回同步，**已到底时取末行**（页码才显示末页）。

**坐标模型（ADR-018 / ADR-029）**：文档内部以**点（pt）**为单位，`zoom` = 每点屏幕像素
（`zoom = 1.0` 即 72dpi）。留白与间距的**单位刻意不同**：

- `margin_px` 是**屏幕像素**：它是"窗口边缘的呼吸空间"，属界面 chrome，**不随缩放变化**
  （缩小时内容通常小于视口而被居中，留白基本不可见）。
- `gap_ratio` 是**列宽的比例**（文档空间）：屏幕间距 = `gap_ratio × 列宽 × zoom`，
  故**随缩放线性变化** —— 缩小时页面变小、间距同比变小，视觉比例恒定。
  用比例而非固定 pt，是为了让不同页幅的文档视觉比例一致。
  （早期 gap 也是屏幕像素常量，缩小时页面变小而间距不变，看起来"间距过大" —— 第四轮反馈。）

`fit_width` 派生
`zoom = (viewport_w − 2·margin_px) / (cols · max_page_w_pt + (cols−1) · gap_pt)`，
其中 `gap_pt = gap_ratio × max_page_w_pt`，使内容宽度**恰等于**视口宽。
内容窄/矮于视口时居中，否则按 scroll 偏移并钳制到 `[0, content − viewport]`。
派生量（内容尺寸、行顶前缀和）做可失效缓存，滚动不使其失效；
`set_viewport` 在视口未变化时**不**使缓存失效（UI 每帧都会调用它）。

> **逐页尺寸（ADR-022）**：PDF 允许各页 MediaBox 不同（封面/横向插页/扫描裁切不一）。
> 画布按**逐页真实尺寸**布局——列宽取最宽页、行高取行内最高页、每页按自身纵横比绘制；
> 尺寸由 `document` 层逐页探测（`DocumentInfo::page_sizes`，每页独立容错）经
> `set_page_sizes()` 传入。只用首页尺寸统一布局会让异构 PDF **形变**。探测失败（`{0,0}`）
> 的页回退到首页尺寸。

### 2.2 输入映射

| 输入 | 行为 |
|---|---|
| 滚轮 | 垂直滚动 |
| Ctrl+滚轮 | 以**鼠标位置为不动点**缩放 |
| 左键拖拽 | 平移 |
| ←→ | 上一行 / 下一行（单列即上/下页）；按**阅读游标**推进，见 §2.1 |
| ↑↓ / PgUp PgDn | 小步 / 整屏滚动 |
| Home / End | 首页 / 末页 |
| G | 跳页输入框 |
| 1~4（**主键盘或小键盘**） | 列数 |
| F / Ctrl+0 | 回到 fit-width |
| +/−（含小键盘 `+`/`-`） | 以视口中心缩放 |
| F11 | 全屏 |

（平滑插值/惯性滚动属 Phase 6 微动效，本期为直接滚动。）
状态栏页码取**阅读游标**（`current_page()`）而非 `visible_first()`：后者在视口高于一行时
会停在倒数第二行，与所见不符。

**键盘快捷键是应用级语义，不看 ImGui 窗口焦点**（ADR-026）：门只有「阅读态 + 无弹窗
（`g_open_jump`）+ 无文本输入（`io.WantTextInput`）」。鼠标操作（滚轮/拖拽）仍需悬停在
画布上。原因：shell 与画布子窗口都带 `ImGuiWindowFlags_NoNav`（含 `NoNavFocus`），
ImGui 不会在启动时给它 `NavWindow`，以焦点为门会让快捷键在首次点击前**全部失效**。
数字/算术类快捷键一律**主键盘与小键盘两套都判**（ADR-027）：`ImGuiKey_1..4` 与
`ImGuiKey_Keypad1..4` 是不同的键，只判一套会出现"小键盘按了没反应"。

**窗口脱离输入法**（ADR-028）：输入法启用时，Windows 会把字母/数字键的 `WM_KEYDOWN` 换成
占位码 `VK_PROCESSKEY (0xE5)`，ImGui 后端不映射该键码 → 这些键在 ImGui 里完全不置位
（字符却经 `WM_CHAR` 正常送达）。故窗口创建后立即
`ImmAssociateContext(hwnd, nullptr)`，让键盘回归原生语义。
**将来加入中文输入（搜索/批注）时必须在文本输入激活时重新关联输入法**，否则中文打不进去。

### 2.2.1 界面缩放与 DPI（ADR-025）

- 进程为 **Per-Monitor V2 DPI aware**；ImGui 的 `DisplaySize` 是**物理像素**。
- 字体：`style.FontScaleDpi = 显示器 DPI 缩放`（`WM_DPICHANGED` 时刷新，1.92+ 动态字体
  自动按新尺寸重栅格化）；`style.FontScaleMain = g_user_scale` 是**将来"全局字号设置"**
  的接入点（现固定 1.0）。
- 界面度量：`style.ScaleAllSizes(dpi × user)`（每次从留底的基准样式重算，避免累积）。
- 自绘像素常量（状态栏高、画布留白/间距、滚动步长、居中文本偏移、最小窗口尺寸）
  `ScaleAllSizes` 管不到，统一过 `px()`。

### 2.3 渲染请求协议（画布 → 调度层）

画布每帧输出 `std::vector<RenderWant>{ page, scale }`（可见页 + 预加载页及其**目标倍率**，
可见页优先）。调度层负责去重、排队、换入。画布不感知线程，只读
`PageSlot{ PageStatus, void* texture, pixel_w/h, scale }`——`texture` 是**不透明句柄**
（`ID3D11ShaderResourceView*`），画布只读、绝不持有所有权（ADR-019）。

### 2.4 缩放清晰度策略

- 每页**一份**当前纹理；缩放变化 → **150ms 防抖** → 以新倍率请求渲染 → 完成后
  替换该页纹理，旧纹理入退役队列（ADR-019）
- 防抖期间**以及重渲染进行中**都用现有纹理**双线性放大**显示（不闪白、不错位）。
  落地要点（ADR-024）：页进入 `Loading` 时**只改状态、保留旧纹理**——若此时清空纹理，
  UI 会先退回"载入中…"占位框再换入，肉眼就是"缩放时闪一下"；且清空动作会让旧 SRV
  脱离退役队列而**泄漏**。新纹理就绪时在同一把锁内原子替换。
- 单页渲染尺寸上限钳制（默认 8192px），超大页面（A0/长图 PDF）预留 tile 分块接口
- 倍率与已投递倍率一致时**不重渲**；渲染请求按 (页, 倍率) 去重（ADR-020）

## 3. 渲染调度与稳定性

### 3.1 线程模型

- UI 线程：ImGui 帧循环 + 画布布局，**零阻塞调用**（绝不碰 fz_* 与磁盘）
- 渲染线程：Phase 2 起采用**单线程串行**——`Document` 实例归属唯一工作线程，
  UI 线程只投递请求、读取快照（ADR-012）。阅读器单线程渲染已足够流畅，
  且彻底规避共享 `fz_document` 的并发风险。Phase 3 起该线程由 `lilithreader.render`
  的 `Renderer` 持有（取代 Phase 2 的临时 `DocSession`，ADR-020）。
- 若将来确有并发渲染需求，再启用 ADR-006 预留的第二条路（每线程 `fz_clone_context`，
  共享 `fz_document`）；本期不实现，接口（`DocError` / `PageBitmap`）无需改动。
- 像素上传：渲染线程用 `ID3D11Device` 直接建纹理（`CreateTexture2D` + 初始数据，
  `IMMUTABLE`；device 方法 free-threaded，无需延迟上下文），上传完成即释放
  `PageBitmap`（ADR-019）

### 3.2 页状态机

```
Unloaded → Loading → Loaded
                  ↘ Failed（错误占位 + 点击重试，自动重试 ≤ 1 次）
```

修复 Lilith 版缺陷：渲染任务异常后 status 永远停留 Loading（白屏）。

### 3.3 缓存与生命周期

- 纹理删除经过**退役队列**：渲染线程把被替换/逐出的纹理入队，UI 线程**帧首**
  `drain_retired()` 统一释放——杜绝悬空 GPU 句柄（ADR-019）
- Phase 3 缓存策略为**保留窗口**（可见 ± 预加载，外扩 4 页）：窗口外的已加载页被逐出；
  **Phase 4** 改为按**字节预算**的 LRU（默认 512MB，可调 128MB~2GB），本层接口不变
- 预加载为可见行 ±1 行；方向感知（向下滚动只预加载下方）属 Phase 4

### 3.4 崩溃防线（分层）

1. **模块边界**：`document` 层所有 fz_* 调用 `fz_try/catch` 全覆盖，错误以返回值/结构化错误码出边界
2. **帧边界**：每页绘制独立 try/catch（TryInvoke 模式），单页异常不影响进程
3. **进程边界**：`set_terminate` + SEH 顶层 → MiniDump 写 exe 同目录 `crash/`，下次启动提示
4. **输入边界**：损坏文件 fuzz 集（空/截断/假后缀/加密）全部优雅报错（Phase 2 验收项）

### 3.5 加密 PDF

- 支持标准安全 handler 全系（RC4 40/128、AES-128、AES-256 R6）
- `fz_open_document` 密码错误 → UI 密码框 → `fz_authenticate_password`，权限位掩码读取并在 UI 层尊重（如禁用复制）；证书/PKI 与第三方 DRM 不支持，按损坏处理

## 4. 字体方案

- UI 文字全部由 ImGui + imgui_freetype 内存栅格化，**字体 `#embed` 进 exe**
- 主字体：中文字体子集（常用 3500 汉字 + Latin + 标点，`pyftsubset` 生成，约 1.5~2MB），候选：思源黑体 / 霞鹜文楷（后者阅读器气质更好）
- Fallback：可选运行时加载 `C:\Windows\Fonts\msyh.ttc` 补生僻字（缺失也不影响完整性）
- **尺寸**：基准字号（现 20px）× `FontScaleMain`（用户/全局设置）× `FontScaleDpi`（DPI）
  = 实际像素；DPI 与界面度量缩放见 §2.2.1
- PDF 页内文字由 MuPDF 用文档自带字体渲染，与 UI 字体无关

## 5. 持久化

- `reader_state.bin`（exe 同目录）：窗口状态、每文档阅读位置（键 = 文件路径 + 大小 + 修改时间哈希）、书签
- 全部写入为「临时文件 + 原子替换」，杜绝写坏配置
