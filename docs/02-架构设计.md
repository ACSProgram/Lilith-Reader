# 架构设计

> 本文用现在时描述**当前**实现；标注"Phase N 计划"的内容尚未实现，其规划见[迁移计划](01-迁移计划.md)。
> 关键选型及理由沿 ADR 台账追溯：[决策记录](03-决策记录.md)。
> 各模块更细的契约写在模块接口文件头注释里（`*.ixx`），与本文互为摘要。

## 1. 总体结构

```
┌────────────────────────────────────────────────────┐
│ src/app        应用层：main / platform / session / ui │
├────────────────────────────────────────────────────┤
│ src/canvas     自研画布：布局·缩放·平移·滚动·网格·对开 │
├────────────────────────────────────────────────────┤
│ src/render     渲染调度：工作线程·页状态机·纹理池·缩略图│
├────────────────────────────────────────────────────┤
│ src/document   MuPDF 封装：Document·页面·密码·目录   │
├────────────────────────────────────────────────────┤
│ src/state      阅读状态持久化：reader_state.bin       │
├────────────────────────────────────────────────────┤
│ src/utils      路径/编码/扩展名闸门/ini 持久化       │
└────────────────────────────────────────────────────┘
```

依赖方向自上而下单向；`document` 与 `canvas` 互不 import，通过 `render` 调度层衔接——这是为将来替换 MuPDF 为 PDFium 预留的解耦（ADR-003）。

- `app` 是唯一的非模块层：Win32/D3D11/ImGui 直连代码，按单一职责分四个普通翻译单元，
  共享的跨 TU 状态与函数声明集中在内部头 `src/app/app_internal.h`（ADR-046）：
  - `main.cpp`：入口、进程 DPI 感知、窗口类/创建/恢复、消息循环、窗口过程
  - `platform.cpp`：D3D11、ImGui 引导、DPI/界面缩放、主题、图标字体、输入法、用户偏好、全屏
  - `session.cpp`：文档状态机（UiDoc）、阅读位置/书签、视图变换、逐页尺寸、画布输入、渲染请求
  - `ui.cpp`：全部绘制（外壳/画布/侧栏/菜单/设置/按键设置/弹窗/引导页）
  文档经 `render` 调度层访问（UI 线程零 `fz_*`、零阻塞），布局数学全在 `canvas`（纯函数，可单测）。
- `utils` 当前只有路径/编码/扩展名白名单/ini 读写（窗口状态与用户偏好）四类工具；
  日志与崩溃转储属 Phase 7 计划，尚未落地。
- `state`（`lilithreader.reader_state`）零项目内依赖：纯序列化（可单测）+ Win32 原子文件 I/O，存阅读位置与书签（ADR-034）。

## 2. 自研画布设计

### 2.1 视图状态（唯一真源）

```
struct CanvasState {
    float   zoom;            // 每点屏幕像素（fit_width 时该值被派生值覆盖）
    float   scroll_x;        // 内容坐标（px）水平偏移
    float   scroll_y;        // 内容坐标（px）垂直偏移
    int     columns;         // 1~4 列
    bool    fit_width;       // fit-width 模式时 zoom 派生
    bool    spread;          // 双页对开（书籍模式）：封面单独成页，其余两页对开；与 columns 同层级互斥（切列即退出，ADR-038）
    float   margin_px;       // 四周留白（**屏幕像素**：界面 chrome，不随缩放）
    float   gap_ratio;       // 页间/列间间距，占列宽比例（**文档空间**：随缩放，ADR-029）
};
```

页面布局是**纯函数**：`page_rect(index, state) → 屏幕矩形`。任何输入（滚轮/拖拽/键盘）只修改 state，渲染每帧按 state 重算布局。无 Invalidate 区域管理，天然可预测。

**书籍模式的行/列映射（ADR-038）**：均匀网格为 `row=i/cols, col=i%cols`；`spread=true` 时改为
"页 0 独占第 0 行，页 i≥1 → `row=1+(i-1)/2, col=(i-1)%2`"（等效 2 列）。缩放/滚动/钳制/翻页全部复用网格逻辑，
差异仅在映射与"单独成页的行在整行内居中"。`spread=false` 时映射与行为**逐位不变**（`canvas_test` 有回归守卫）。
**列数与对开是同层级互斥的视图模式**（ADR-038 勘误）：对开 = 2 列 + 封面偏移，故显式切列
（`set_columns`）会**直接退出对开**（无需先按 `D`）；对开期间 `columns` 仅被暂时覆盖、值保留，关闭后恢复。

> **唯一的有状态量：阅读游标 `nav_row_`（ADR-023）**。它是"当前读第几行"，只服务翻页
> 与页码指示，**不参与任何布局计算**——布局仍是纯函数。之所以必须存在：当视口比"一行"
> 还高时（横向页 / 缩小 / 多列），末尾若干行的 `row_top` 会超过 `max_scroll_y`，无法对齐到
> 视口顶部；若翻页游标只能由滚动位置反推，就会在末行前反复无进展（"卡住"）。
> 手动滚动/缩放后游标按"视口顶部所在行"回同步，**已到底时取末行**（页码才显示末页）。

**坐标模型（ADR-018 / ADR-029）**：文档内部以**点（pt）**为单位，`zoom` = 每点屏幕像素
（`zoom = 1.0` 即 72dpi）。留白与间距的**单位刻意不同**：

- `margin_px` 是**屏幕像素**：它是"窗口边缘的呼吸空间"，属界面 chrome，**不随缩放变化**。
- `gap_ratio` 是**列宽的比例**（文档空间）：屏幕间距 = `gap_ratio × 列宽 × zoom`，
  故**随缩放线性变化**——缩小时页面变小、间距同比变小，视觉比例恒定。
  用比例而非固定 pt，是为了让不同页幅的文档视觉比例一致。
  （早期 gap 也是屏幕像素常量，缩小时页面变小而间距不变，看起来"间距过大"——第四轮反馈。）

`fit_width` 派生
`zoom = (viewport_w − 2·margin_px) / (cols · max_page_w_pt + (cols−1) · gap_pt)`，
其中 `gap_pt = gap_ratio × max_page_w_pt`，使内容宽度**恰等于**视口宽。
内容窄/矮于视口时居中，否则按 scroll 偏移并钳制到 `[0, content − viewport]`。
派生量（内容尺寸、行顶前缀和）做可失效缓存，滚动不使其失效；
`set_viewport` 在视口未变化时**不**使缓存失效（UI 每帧都会调用它）。

> **逐页尺寸（ADR-022）**：PDF 允许各页 MediaBox 不同（封面/横向插页/扫描裁切不一）。
> 画布按**逐页真实尺寸**布局——列宽取最宽页、行高取行内最高页、每页按自身纵横比绘制；
> 尺寸由 `document` 层逐页探测（`DocumentInfo::page_sizes`，每页独立容错）经
> `set_page_sizes()` 传入。只用首页尺寸统一布局会让异构 PDF **形变**。探测失败（`{0,0}`）
> 或整表未探测（页数超过上限）的页回退到首页尺寸。

### 2.2 输入映射

> **键盘命令自 ADR-054 起由命令表驱动**：每条命令（`Cmd` 枚举）在 `session.cpp` 的 `kCmds`
> 里有名称、分组、默认键（**两个槽**）与"是否可连发"；实际生效的键存在 `g_binds`，可由
> 设置窗口的**按键分栏**改键并落盘到 ini 的 `[keys]` 节。下表列的是**默认键**。
> 派发只有一条路径：`cmd_pressed(Cmd)` → 命中即执行（阅读命令见 `handle_reading_commands`，
> 全局命令见 `handle_global_commands`）。Esc 只是"关闭当前对话框"的固定键，不再是"退出"。

| 输入 | 行为 |
|---|---|
| 滚轮 | 垂直滚动 |
| Ctrl+滚轮 | 以**鼠标位置为不动点**缩放 |
| 左键拖拽 | 平移（**不做平滑**：直接操纵必须 1:1 跟手） |
| 拖拽右侧滚动条 / 点轨道空白 | 拖拽定位 / 滑块跳到该处；拖拽期间**不触发平移**（ADR-050） |
| ←→ | 上一行 / 下一行（单列即上/下页）；按**阅读游标**推进，见 §2.1 |
| ↑↓ / PgUp PgDn | 小步 / 整屏滚动 |
| Home / End | 首页 / 末页 |
| G | 跳页输入框 |
| 1~4（**主键盘或小键盘**） | 列数（对开期间切列即退出对开，二者同层级） |
| F / Ctrl+0 | 回到 fit-width |
| +/−（含小键盘 `+`/`-`） | 以视口中心缩放 |
| R | 旋转 +90°（0→90→180→270→0，Phase 5） |
| D | 双页对开（书籍模式）开关（Phase 5） |
| I / E | 反色 / 护眼配色开关（Phase 5） |
| O | 侧栏（目录 / 书签 / 缩略图）开关（Phase 5） |
| B | 当前页书签增删（Phase 5） |
| F1 | 打开设置的**按键分栏**（取代原"快捷键与帮助"窗口） |
| Ctrl+, | 打开设置 |
| Ctrl+O | 打开文档… |
| F3 | 调试浮层（FPS/DPI/画布状态/诊断读数） |
| Shift+F10 / 菜单键 | 打开**画布右键菜单**（与鼠标右键同一菜单，Phase 6） |
| F11（默认第二槽亦为 Esc） | 全屏开关 |
| Esc | **固定**：关闭当前对话框（设置 / 跳页 / 密码）。**不再**承担"关闭文档 / 退出"——阅读中误触会丢掉阅读位置，代价过大，关闭文档/退出一律走菜单（ADR-054） |

（缩放/滚动/跳页/顶栏滑动都有平滑插值，统一由 `[ui] Motion` 开关，ADR-047；
**惯性滚动**尚未实现——当前只有一阶滞后平滑，没有速度模型。）
状态栏页码取**阅读游标**（`current_page()`）而非 `visible_first()`：后者在视口高于一行时
会停在倒数第二行，与所见不符。

**键盘快捷键是应用级语义，不看 ImGui 窗口焦点**（ADR-026）：门只有「阅读态 + 无弹窗
（跳页弹窗）+ 无文本输入（`io.WantTextInput`）」。鼠标操作（滚轮/拖拽）仍需悬停在
画布上。原因：shell 与画布子窗口都带 `ImGuiWindowFlags_NoNav`（含 `NoNavFocus`），
ImGui 不会在启动时给它 `NavWindow`，以焦点为门会让快捷键在首次点击前**全部失效**。
数字/算术类快捷键一律**主键盘与小键盘两套都判**（ADR-027）：`ImGuiKey_1..4` 与
`ImGuiKey_Keypad1..4` 是不同的键，只判一套会出现"小键盘按了没反应"。

**命令表与改键**（ADR-054）：阅读命令在 `handle_reading_commands` 派发（画布悬停 + 阅读态），
全局命令在 `handle_global_commands` 派发（任何状态，但门 = **无文本输入 + 未在捕获按键 +
无对话框级界面**，`any_dialog_open()`）。改键只动 `g_binds`，`kCmds` 的 id 是 ini 键名、
**不得随显示文案改动**。绑定持久化在 ini 的 `[keys]` 节（值形如 `Ctrl+O|F11`，键名取
`ImGui::GetKeyName` 原文，ASCII）。

**窗口脱离输入法**（ADR-028）：输入法启用时，Windows 会把字母/数字键的 `WM_KEYDOWN` 换成
占位码 `VK_PROCESSKEY (0xE5)`，ImGui 后端不映射该键码 → 这些键在 ImGui 里完全不置位
（字符却经 `WM_CHAR` 正常送达）。故窗口创建后立即
`ImmAssociateContext(hwnd, nullptr)`（并在 `WM_INPUTLANGCHANGE` 切换输入语言后重新脱离），
让键盘回归原生语义。
**将来加入中文输入（搜索/批注）时必须在文本输入激活时重新关联输入法**，否则中文打不进去。

#### 2.2.1 界面缩放与 DPI（ADR-025）

- 进程为 **Per-Monitor V2 DPI aware**；ImGui 的 `DisplaySize` 是**物理像素**。
- 字体：`style.FontScaleDpi = 显示器 DPI 缩放`（`WM_DPICHANGED` 时刷新，1.92+ 动态字体
  自动按新尺寸重栅格化）；`style.FontScaleMain = g_user_scale` 是**将来"全局字号设置"**
  的接入点（现固定 1.0）。
- 界面度量：`style.ScaleAllSizes(dpi × user)`（每次从留底的基准样式重算，避免累积）。
- 自绘像素常量（状态栏高、画布留白、滚动步长、居中文本偏移、最小窗口尺寸）
  `ScaleAllSizes` 管不到，统一过 `px()`。**页/列间距例外**：它是列宽比例（§2.1，
  ADR-029），与页面同比例缩放，**刻意不过 `px()`**、不随 DPI 单独放大。

### 2.3 渲染请求协议（画布 → 调度层）

画布侧每帧由 `app` 层汇总 `std::vector<RenderWant>{ page, scale }`（可见页 + 预加载页及其
**目标倍率**，可见页优先）投递给调度层。预加载页的范围由 `app` 按**滚动方向**裁剪：
只在与滚动方向一致的一侧多取一行（ADR-032）。调度层负责去重、排队、按字节预算逐出、换入。
画布不感知线程，只读
`PageSlot{ PageStatus, void* texture, pixel_w/h, scale }`——`texture` 是**不透明句柄**
（`ID3D11ShaderResourceView*`），画布只读、绝不持有所有权（ADR-019）。

**缩略图通道（ADR-037）**：侧栏另走一条并行请求 `set_thumbs_wanted(pages, target_px)`，
读取 `thumb_slot(page)`。缩略图**独立缓存、不占页缓存预算**，失败不自动重试。

**视图动效（ADR-047）**：缩放/滚动/跳页/顶栏滑动的插值全部发生在 **app 层写入画布之前**
（`session.cpp` 的 `request_scroll / request_jump_scroll / zoom_*_animated / step_view_motion`），
画布不引入任何时间概念。跳页的目标位置仍由画布算（对开/网格/钳制的唯一真源），
app 只负责"从哪滑到哪"；滑行结束后重新钉一次阅读游标，保住"显式跳页显示目标行"的语义（ADR-023）。

**视图变换（ADR-036）**：旋转（0/90/180/270）与配色（正常/反色/护眼）是**文档级**状态，
经 `Renderer::set_view_transform` 下发。变换已固化进纹理像素，故任一变化即让全部页纹理与
缩略图失效并**整篇重渲**（失效走两段式退役队列）。旋转对画布透明：由 `app` 折算成
"页尺寸宽高互换"后交给画布，布局/翻页/缩放全部复用。

### 2.4 缩放清晰度策略

- 每页**一份**当前纹理；缩放变化 → **150ms 防抖** → 以新倍率请求渲染 → 完成后
  替换该页纹理，旧纹理入退役队列（ADR-019）
- 防抖期间**以及重渲染进行中**都用现有纹理**双线性放大**显示（不闪白、不错位）。
  落地要点（ADR-024）：页进入 `Loading` 时**只改状态、保留旧纹理**——若此时清空纹理，
  UI 会先退回"载入中…"占位框再换入，肉眼就是"缩放时闪一下"；且清空动作会让旧 SRV
  脱离退役队列而**泄漏**。新纹理就绪时在同一把锁内原子替换。
- 单页渲染尺寸上限钳制（默认 8192px）：超大页面（A0/长图 PDF）由 `document` 层按上限等比降采样后
  渲染（不 OOM、不形变）。**当前没有 tile 分块接口**——它是后续的候选优化（见 §9），尚未实现。
- 倍率与已投递倍率一致时**不重渲**；渲染请求按 (页, 倍率) 去重（ADR-020）

## 3. 渲染调度与稳定性

### 3.1 线程模型

- UI 线程：ImGui 帧循环 + 画布布局，**零阻塞调用**（绝不碰 fz_* 与磁盘）
- 渲染线程：**单线程串行**——`Document` 实例归属唯一工作线程，
  UI 线程只投递请求、读取快照（ADR-012）。阅读器单线程渲染已足够流畅，
  且彻底规避共享 `fz_document` 的并发风险。该线程由 `lilithreader.render`
  的 `Renderer` 持有（取代 Phase 2 的临时 `DocSession`，ADR-020）。
- 若将来确有并发渲染需求，再启用 ADR-006 预留的第二条路（每线程 `fz_clone_context`，
  共享 `fz_document`）；本期不实现，接口（`DocError` / `PageBitmap`）无需改动。
- 像素上传：渲染线程用 `ID3D11Device` 直接建纹理（`CreateTexture2D` + 初始数据，
  `IMMUTABLE`；device 方法 free-threaded，无需延迟上下文），上传完成即释放
  `PageBitmap`（ADR-019）

### 3.2 页状态机

```
Unloaded → Loading → Loaded
                  ↘ Failed（自动重试 ≤1 次后定格；显示错误占位，点击可重试）
```

`Loading`/`Failed` 都**保留旧纹理**（ADR-024）：从未成功渲染过的页才显示占位框。
失败后**自动重试 1 次**（可救瞬时失败，如一时分配不到显存）；仍失败则**定格**为 Failed，
不再随 wants 变化无限重渲 —— 定格绑定**失败时的倍率**，倍率一变即视为新请求、重置额度；
用户点击失败占位 → `Renderer::retry_page` 重置计数并重新排队（ADR-031）。
该状态机修复了 Lilith 原版"渲染任务异常后 status 永远停留 Loading（白屏）"的缺陷。

### 3.3 缓存与生命周期

- 纹理删除经过**两段式退役队列**：渲染线程把被替换/逐出的纹理放入 `retired_pending`
  （本帧），UI 线程**帧首** `drain_retired()` 先释放上一帧的、再收编本帧的 ——
  任何纹理**至少活过一个完整帧**，从机制上杜绝悬空 GPU 句柄（ADR-019/033）
- 缓存策略为按**字节预算**的 LRU：默认 **512MiB**，范围 **128MiB~2GiB**，
  由 ini `[cache] BudgetMB` 配置、`Renderer::set_cache_budget` 钳制（ADR-030）。
  本帧需要的页（可见 + 预加载）**pinned 不逐出**；其余按最久未用先出，直到总量降到预算内。
  逐出选择是纯函数（`lilithreader.page_cache::select_evictions`），可脱离 D3D/线程单测
- 预加载为可见行 ±1 行，且**方向感知**：向下滚只预取下方、向上滚只预取上方；
  方向未定（刚打开 / 跳页后）时两侧都预取（ADR-032）
- 缓存统计（预算/驻留字节/驻留页数/累计逐出）经 `Renderer::cache_stats` 暴露，F3 浮层可见

### 3.4 崩溃防线（分层）

1. **模块边界**（已实现）：`document` 层所有 fz_* 调用 `fz_try/catch` 全覆盖，错误以返回值/结构化错误码出边界
2. **输入边界**（已实现）：损坏文件 fuzz 集（空/截断/假后缀/加密）全部优雅报错（Phase 2 验收项，已自动化）
3. **帧边界**（Phase 7 计划）：每页绘制独立 try/catch（TryInvoke 模式），单页异常不影响进程
4. **进程边界**（Phase 7 计划）：`set_terminate` + SEH 顶层 → MiniDump 写 exe 同目录 `crash/`，下次启动提示

### 3.5 加密 PDF

- 识别：加密文档打开时返回 `DocError::NeedsPassword`，文档仍处于打开态。
- **解锁 UI（Phase 5 已实现）**：`app` 弹出模态密码框 → `Renderer::authenticate(pwd)` →
  `fz_authenticate_password`。支持标准安全 handler 全系（RC4 40/128、AES-128、AES-256 R6）；
  认证期间弹窗保持打开并显示"验证中…"，失败只更新"密码错误"提示，取消/Esc 关闭文档（ADR-044）。
  证书/PKI 与第三方 DRM 不支持，按损坏处理。
- **解密纪律（ADR-041）**：认证成功后不得再调用 `fz_needs_password()`（MuPDF 1.26.10 上会破坏
  解密状态，导致内容流静默解出乱码、整页空白）。`Document::Impl` 缓存该状态，`info()` 只读缓存值。
- **权限位（Phase 5）**：`DocumentInfo::can_copy` / `can_print` 经 `fz_has_permission` 读取；
  无加密或无法判定时一律 true（保守放行）。当前尚无复制/打印功能，字段先就位供后续置灰（ADR-039）。

## 4. 字体方案

- **UI 主字体（ADR-048）**：**随 exe 内嵌的子集** `assets/ui_font_subset.otf`（1.04MiB；
  源字体 Noto Sans SC Regular，OFL 1.1），以 `.rc` 的 RCDATA 内嵌、`AddFontFromMemoryTTF` 装载
  （`FontDataOwnedByAtlas=false`：资源内存全程有效，零拷贝零释放）。
  子集字符集 = 源码（去注释）非 ASCII 字符 ∪ ASCII 可见区 ∪ GB2312 一级字表 3755 字
  ∪ 常用标点/符号区段；**"源码字符集 ⊆ 子集"由 `assets/check_font_coverage.py` 在
  `tests/run_tests.ps1` 里断言**，生成脚本 `assets/make_font_subset.py`（源字体不入库）。
- **装载器**：FreeType（`io.Fonts->SetFontLoader(ImGuiFreeType::GetFontLoader())` + `LightHinting`）。
  子集是 CFF/OTF，内置 stb_truetype 只支持 TrueType；且小字号 CJK 栅格化质量更好。
  freetype 本身是 libmupdf 的传递依赖，未新增外部依赖。
- **生僻字 fallback**：系统 `msyh.ttc` 以 `MergeMode` 合并进同一 ImFont，只兜子集没有的字形
  （文件名、PDF 目录标题可能含生僻字）；系统缺该字体时静默跳过，界面自述文字不受影响。
  字形**按需栅格化**（DX11 后端声明了 `RendererHasTextures`，走动态图集路径）。
- **图标（Phase 6，ADR-045）**：图标字形取自系统 `Segoe MDL2 Assets`（`segmdl2.ttf`），以
  `MergeMode` 合并进同一 ImFont；只用 `ImFontGlyphRangesBuilder` 烘实际用到的几十个 PUA 码位。
  启动时用 GDI `GetGlyphIndicesW(GGI_MARK_NONEXISTING_GLYPHS)` 逐个校验字形存在，
  缺失则整体不合并、所有图标按钮退化为文字标签（不出现豆腐块）。
  度量校正：`GlyphMinAdvanceX = 基准字号`（图标宽度一致）、`GlyphOffset.y = +4`（消除 MDL2 与
  微软雅黑的基线差异——实测 150% DPI / 30px 有效字号下图标光学中心比汉字高约 6px，按基准字号
  折算为 4px；该值由 ImGui 随有效尺寸等比缩放）。
- **尺寸**：基准字号（现 20px）× `FontScaleMain`（用户/全局设置）× `FontScaleDpi`（DPI）
  = 实际像素；DPI 与界面度量缩放见 §2.2.1
- PDF 页内文字由 MuPDF 用文档自带字体渲染（无内嵌字体时走 MuPDF 内置 CJK 兜底，
  体积构成见[体积预算](05-体积预算.md)），与 UI 字体无关

## 5. 持久化

- **现状**（两个文件，均在 exe 同目录）：
  - `LilithReader.ini`：
    - `[window]`：位置/尺寸/最大化，恢复前做合法性校验（至少 100×100 落在虚拟屏幕内、最小 400×300）。
    - `[cache] BudgetMB`：页缓存字节预算（MB），缺省 512，渲染层钳制到 128~2048（ADR-030）。
    - `[ui]`（Phase 6，ADR-045）：`UiScale`（界面缩放 0.8~1.5）、`Theme`（0 跟随系统/1 浅/2 深）、
      `AutoHideToolbar`、`Motion`、`GapPercent`（页面间距，列宽百分比）。全部由「设置」窗口驱动，
      改动**即时生效并即时落盘**（写 ini 很小，不必攒到退出）。
    - `[reading] SmartMatch`（ADR-062）：0 关 / 1 询问 / 2 自动，缺省 1。
  - `reader_state.bin`（Phase 5，ADR-034；身份分层 ADR-062；位置列表 ADR-065）：每文档的阅读位置
    （页/缩放/列/旋转/对开/fit/配色）与书签表，外加身份三件套 `path_key` / `page_count` /
    `locations`（**已知位置列表**，最近打开的在前，上限 8 条）。
    - **主键 = 内容指纹**：`utils::file_fingerprint` 的头 128KB + 中 64KB + 尾 128KB
      **稀疏采样**（≤320KB，与文件大小无关），由 render 的**工作线程**在打开时算好随
      `DocState::file_fingerprint` 发布（UI 线程不读文件内容，ADR-009）。
    - 定位顺序（`reader_state::locate`）：内容指纹 → 路径键（`document_key`，路径+大小+
      修改时间，v1 迁移与兜底用）。命中即 `adopt`（改挂到指纹主键、把当前路径记进
      `locations`）。页数对不上不继承（书签是页号，页数变了会错位）。
      `relocated` = 当前位置不在已知位置里（**一份数据、若干路径**：同一份内容存了两处时，
      在已记过的位置上打开不再询问）。
    - 格式 v3（magic `LRS3`）；v2（单路径 → 位置列表）与 v1（旧键 → `path_key`，位置留空）
      仍可解码并迁移。解析失败一律安全拒绝（空状态）。
      写入为"临时文件 + `MoveFileExW` 原子替换"。
    - 用户侧入口：「设置 → 阅读数据」的智能匹配三态，以及同一分栏的卡片式清单（单条删除、
      全部清空、清理"位置未知"的旧记录，删除/清空均过确认弹窗，ADR-063/065）。
    - 「另起一份」（ADR-065）：确认弹窗的次按钮。把当前这份从共享记录里**摘出去**并各自
      退回按路径认（内容指纹一条记录只能挂一个，留着它会反复询问），两边进度互不影响。
- 计划中的其余写入（如 Phase 6 的主题设置）沿用「临时文件 + 原子替换」。

## 6. 阅读功能（Phase 5）

- **阅读位置记忆**：打开成功时先 `resolve_document_identity()` 定位记录（内容指纹 → 路径键，
  命中即 `adopt`），再按记录恢复页/缩放/列/旋转/对开/fit/配色；关闭与退出时落盘
  （`reader_state.bin`，见 §5）。位置在**首帧视口就绪后**恢复（fit-width 派生 zoom 依赖视口尺寸）。
  命中但路径变了时按「智能匹配」设置询问或静默沿用（ADR-062）。
- **目录侧栏**：`Document::outline()` 展平的前序序列（title/page/depth），按 depth 缩进渲染；
  点击跳转到目标页（`canvas.scroll_to_page`）。无目录显示占位。
- **书签**：`B` 在当前页增删，写入 `reader_state.bin`；侧栏列出并可跳转，行尾 `×` 删除
  （Selectable 显式让出按钮宽度，避免整行命中区盖住按钮）。状态栏在书签页显示 `★`。
- **缩略图侧栏**：只请求当前页 ±40 页（随当前页扩展），点击跳转（ADR-037）。
- **旋转 / 双页对开 / 反色 / 护眼**：见 §2.3 与 ADR-036/038/042/043；均为文档级视图状态并随阅读位置一同记忆。
  - 旋转：交换版面宽高，切换时**整体失效重渲**（旧纹理贴新框会形变）。
  - 配色（反色/护眼）：**仅配色变化时保留旧纹理原地换入**，不做整篇白闪（ADR-042）。
  - 反色为**柔化暗色映射**（白→`#1F1D1B`、黑→`#D8D4CE`），且**整套 chrome 同步转深色**（ADR-043）。
- **侧栏结构**：左侧单一 child（宽度 `px(300)`），内部三个标签（目录/书签/缩略图）；`O` 开关，默认定位"目录"。

## 7. 界面外壳（Phase 6，ADR-045）

界面由**顶栏 + 画布（可选左侧栏）+ 状态栏**三段构成，全部自绘/ImGui 绘制，无原生控件。

**弹窗（模态对话框）**：跳页 / 密码 / 通用确认三处，统一走 `popup_anim_apply` 做开合动效
（淡入淡出 + 轻微滑落，ADR-059）。**不变量：套用的透明度必须 > 0**（下限 `kPopupMinAlpha = 1/255`）
—— ImGui 在 `style.Alpha <= 0` 时会把窗口判为 Hidden，`Begin()` 返回 false，于是"收敛后再关闭"
那一步永远执行不到，弹窗会作为不可见的模态永久残留并挡住全部输入（ADR-064）。
通用确认弹窗（`request_confirm` + `draw_confirm_popup`）为**自绘版式**：标题（强调色）/ 说明 /
明细行（标签 + 可折行的值）/ 右对齐按钮，复用于智能匹配询问与阅读数据删除的二次确认（ADR-062/063）。

**三段的几何由 `draw_shell` 显式给出**（ADR-049）：自己算 `top_h / body_h / status_h` 并用
`SetCursorPosY` 落位，画布与侧栏的高度由调用方传入，三段**恰好铺满客户区、中间不留缝**。
不让 ImGui 顺着排的原因：三者是同级子窗口，`EndChild()` 会为每个子窗口记一个 item，
相邻子窗口之间被插入一份 `ItemSpacing.y`，三段之和会比客户区多出一个间距，
**状态栏被挤出窗口底部、文字下缘被裁**（实测即"状态栏文字贴边"的真实原因）。
状态栏高度按 **CJK 墨迹盒**（ascent+descent ≈ 1.32 em）而不是 ImGui 的名义行高来定。

- **命令集中、按钮克制**：可点控件只出现在顶栏一簇与各种菜单里；**状态栏只放只读信息**
  （页码 + 非默认视图状态的 chip + 右侧格式；扩展名不符的提示也在此）。
- **顶栏**：左侧「主菜单（☰）」+「侧栏」；中间文档名（空间不足自动省略）；右侧控件簇
  （书签 / − / 缩放百分比 / + / 设置）。按钮一律**扁平**（默认无底色，悬停/按下/激活才浮现），
  图标字体缺失时退化为文字标签。阅读态可**自动隐藏**（鼠标停在窗口顶部即重现）。
- **主菜单**：打开文档 / 关闭文档 / 视图 / 导航 / 缩放 / 设置 / 按键设置 / 退出。
- **画布右键菜单**：导航（上/下一页）、缩放、视图、跳页、书签、侧栏、设置、按键设置。
  与主菜单**共用同一批内容函数**（`draw_zoom/view/nav_menu_contents`），不重复维护。
  菜单里显示的快捷键取**当前绑定**（`menu_item_cmd`），改键后同步。
  键盘等价入口 `Shift+F10` / 菜单键（§2.2）。
- **设置窗口**：五个分栏 —— 界面（缩放/主题/顶栏自动隐藏/动效）、阅读（页面间距/当前配色）、
  性能（页缓存预算）、**按键**（按命令分组列出全部命令，每条两个键槽：点击进入捕获、
  右键清除、冲突即时提示、可一键恢复默认）、**阅读数据**（智能匹配三态 + `reader_state.bin`
  的**卡片式**清单，ADR-062/063/065）。正文装在 `BeginChild` 里、
  **底栏固定**（内容多时只滚动正文）；全部即时生效并即时落盘（§5）。
  原「快捷键与帮助」窗口已删除，其参考信息并入按键分栏（ADR-054）。
  F1 直达按键分栏。智能匹配放在阅读数据分栏而不是阅读分栏：它决定"要不要跨位置共用同一份
  数据"，与那一栏是同一件事，也省掉「阅读」栏里那句"见阅读数据分栏"。
  - 阅读数据卡片 = 标题行（文档名 + 行尾删除按钮）/ 统计行（第 N / M 页 · K 个书签 ·
    J 个位置）/ 缩进的**路径树**（左侧一条竖导引线把若干位置挂在标题下）—— 用卡片而不是
    `TreeNode`，是因为路径是只读信息、不该看起来可点；路径**单行中间省略**、完整路径给悬停
    提示（折行会让卡片高度参差）。删除与"清空全部 / 清理旧记录"共用一套**破坏性按钮**观感：
    默认无底色、悬停浮出危险色，而不是 ImGui 默认的灰方块。
  - 「位置未知的旧记录」（v1 记录没存过路径）单独成区放在末尾，附一句解释与"清理这 N 条"，
    不再混在主列表里显示成一堆"未知文档"。
- **间距基准**：`kChromePadX / kChromeGapX / kPopupPadXY / kMenuItemGapY`（100% 缩放值，用前过 `px()`）。
  弹出菜单的项高由 `ItemSpacing.y` 决定（`Selectable` 高度 = 文字高，不吃 `FramePadding`）。
- **主题**：浅色/深色/跟随系统；反色模式强制深色（ADR-043）。`g_pal` 管自绘的 chrome 颜色，
  `apply_theme_colors` 管 ImGui 控件配色，两者在**帧首**同步切换（不在帧中途改样式）。
- **自绘滚动条**（ADR-050）：几何由 `scroll_bar_geom()` 一处给出，**绘制与命中测试共用**；
  支持拖拽滑块、点轨道空白跳转、悬停加宽高亮，拖拽期间抑制画布平移。命中区（12px）比可见
  滑块（5~7px）宽 —— 细滑块好看但按不中。
- **微动效**（ADR-047）：页面首次出现淡入、滚动条浮现后渐隐、顶栏自动隐藏**滑出/滑入**
  （高度插值，内容按整条高度排布后整体上移）、**侧栏滑入/滑出**（宽度插值，面板仍按**整宽**
  排布、整体左移，不重排内容，ADR-055）；缩放/滚动/跳页的平滑插值见 §2.3。
  **设置窗口**打开/关闭为**缩放 + 淡入淡出**（以窗口中心为不动点，尺寸 96%↔100%，
  透明度 0↔1；关闭时边缩边淡，不是原地整窗透明，ADR-056）。
  **弹出对话框**（跳页 / 密码）为**淡入淡出 + 轻微滑落**（ADR-059）：它们是 `AlwaysAutoResize`
  的输入框，缩放外框会裁剪内部固定宽度控件，故刻意不做缩放；关闭走"延迟关闭"
  （先淡出、收敛后才真正 `CloseCurrentPopup`）。
  全部由 `[ui] Motion` 统一开关，关闭即直切。F3 浮层有动效读数（pending / zoom 目标 /
  顶栏高度 / 是否在拖滚动条）。
  **不纳入动效**（刻意）：主菜单 / 右键菜单（桌面惯例是菜单即时弹出）、调试浮层（诊断 HUD）。
- **两套插值，分工明确**（ADR-047 / ADR-061）：
  - **连续输入驱动**（滚动 / 缩放 / 顶栏 / 侧栏）→ **一阶滞后**（`approach`）。理由：连续输入
    需要自然叠加，补间则每次输入都要重排时间轴。
  - **一次性开合**（设置窗口 / 弹出对话框）→ **定时补间 + 三次缓出**（`ToggleAnim`，
    `kOpenCloseDur = 160ms`）。理由：单向、有明确终点，定时补间时长确定、末端干脆，
    没有"收敛到 99% 之后还拖一个时间常数"的长尾（人工反馈"再利落一点"）。

### 7.1 窗口生命周期：swapchain 重建与全屏切换（ADR-057 / ADR-058 / ADR-060）

> **总纪律：一切改变帧级几何的操作都在"帧首"做。** 在 ImGui 一帧中途改窗口几何，本帧的
> 绘制数据就已经与窗口矩形不一致了，只能被 DWM 拉伸 —— 无论怎么调 Win32 调用顺序都救不回来。
> 具体落点：`WM_SIZE` 只记录待处理尺寸；全屏切换只置请求标志；两者都在主循环帧首应用。

- **swapchain 重建延到帧首**：`WM_SIZE` 只把客户区尺寸记进 `g_resize_pending`，**不**在消息里
  `ResizeBuffers`。因为 `WM_SIZE` 会在 `SetWindowPos` / `SetWindowPlacement` 过程中**同步**到达，
  而这类调用可能发生在 ImGui 一帧中途（命令派发时）；当场重建会让"按旧尺寸排布的本帧绘制数据"
  被画进新尺寸的后备缓冲，呈现为一帧拉伸/闪烁。改为帧首统一应用后：每帧至多重建一次、
  与 ImGui 视口尺寸严格一致，且多次 `WM_SIZE` 自动合并。`Graphics::resize` 另加"尺寸未变即跳过"。
- **全屏切换**：命令只置 `g_request_fullscreen_toggle`，由主循环**帧首**执行（ADR-060）。
  进入 = `WS_POPUP` + 单次 `SetWindowPos(FRAMECHANGED)` 铺满显示器；
  退出 = **先提交新样式（`FRAMECHANGED`，仍在全屏矩形上、`NOMOVE|NOSIZE`）再 `SetWindowPlacement` 落位**。
  反过来（先落位再补 `FRAMECHANGED`）会先用尚未生效的无边框度量摆放窗口、再被帧重算挪一次。
  进入前的 `WINDOWPLACEMENT` 被保存，退出时原样恢复（含最大化态）。
  **已知缺陷**：最大化状态下退出全屏仍有一次可见抖动（`SetWindowPlacement(SW_SHOWMAXIMIZED)`
  内部的"先落 `rcNormalPosition` 再最大化"属单次调用的内部中间态，帧首纪律管不到），
  见根 README「已知问题」。
- **最小化期间整帧不渲染**（ADR-061）：`WM_SIZE(SIZE_MINIMIZED)` 置 `g_minimized`，主循环
  帧首 `Sleep(10); continue;`。最小化后客户区为 0，ImGui 在 0 尺寸视口下什么都画不出，
  整帧只剩**清屏色** —— 在收起动画里就是一闪；顺带省掉最小化期间的 CPU/GPU。

  `assets/ui_font_subset.otf`）；安装包已落地（Phase 7，见 §8.2）；UPX 压缩仍属计划

### 8.1 图标资源（Phase 7，ADR-051）

| 资源 | 用途 | 生成脚本 |
|---|---|---|
| `assets/icon.ico` | exe / 窗口 / 任务栏 / 安装包图标 | `assets/make_app_icon.py`（从 256 母版 LANCZOS 重采样） |
| `installer/icons/lilith_<EXT>.ico` | 各格式的关联图标，装到 `{app}\icons\<版本>\`（路径含版本号 → Explorer 图标缓存自然失效） | `assets/make_format_icons.py`（按尺寸分级、超采样原生绘制） |

两套都用同一份**完整帧集** `16/20/24/28/32/36/40/48/56/64/72/80/96/128/160/192/256`，
覆盖 100%~200% 下的非整数缩放率（125% 要 20px、150% 要 24px、175% 要 28px……）：
缺帧时 Windows 会拉伸邻近帧，表现为"发糊 + 一圈灰边"。

**帧集与每帧真实尺寸由 `assets/check_icons.py` 在 `tests/run_tests.ps1` 里断言**（280 项）——
ICO 最常见的错不是画得不好，而是帧集不全或"小图塞进大槽位"，且只在特定 DPI 下才暴露。

### 8.2 安装包（Phase 7，ADR-052/053）

`installer/LilithReader.iss`（Inno Setup 6.5+），`installer/build_installer.bat` 一键构建，
产物 `installer/dist/LilithReader-<版本>-setup.exe`（当前约 26MB）。

- **每用户安装**（`PrivilegesRequired=lowest`）：装到 `%LOCALAPPDATA%\Programs\Lilith Reader`。
  理由见 ADR-052——程序把数据写在 exe 同目录（§5），装到 Program Files 会静默写不进去；
  关联写 HKCU 也要求非提权上下文。
- **升级 = 就地覆盖**：同 AppId + `UsePreviousAppDir / UsePreviousTasks`，沿用上次的安装目录与
  任务勾选；不做"先静默卸载旧版"（那会把旧卸载器的数据询问插进升级流程，ADR-053）。
- **编译期版本校验**：脚本里的 `MyAppVersion` 必须等于 `bin\Release\LilithReader.exe` 的版本资源
  （`src/app/app.rc`），不一致直接编译失败，杜绝两处版本漂移。
- **文件关联**：全部写 HKCU（`Software\Classes\LilithReader.<ext>` + `OpenWithProgids` +
  `Capabilities` + `RegisteredApplications`），勾选页默认文档格式全选、图片格式全不选；
  实际绑定的扩展名记入 `HKCU\Software\LilithReader\Bindings`，卸载时据此精确回收。
- **卸载**：数据去留只问一次（`TaskDialogMsgBox`，默认保留；静默卸载一律保留），
  之后回收关联注册表。
- **运行中检测**：`CloseApplications`（Windows 重启管理器），不自行做文件占用试探。

## 9. 扩展点（当前已存在的接缝）

> 本节只描述**代码里已经存在**的接缝，用于承载后续成熟化功能；未实现的能力一律标注为规划，
> 具体排期见[迁移计划 §后续成熟化方向](01-迁移计划.md)。

- **文档后端可替换**（ADR-003）：`document` 对外只暴露与 MuPDF 无关的类型，`fz_*` 全藏在 PIMPL。
  换成 PDFium 只改这一个模块，`render` 及以上不动。
- **渲染并发 / 大页面**（ADR-006 预留）：当前单工作线程独占 `Document`；若将来需要并发渲染，
  启用"每线程 `fz_clone_context`、共享 `fz_document`"这条路，接口（`DocError`/`PageBitmap`）不变；
  超大页面的 tile 分块亦在此层拓展（当前**未实现**，超限页只做等比降采样）。
- **视图变换集中下发**：旋转/配色经 `Renderer::set_view_transform` 统一入口；新增变换类型
  （亮度/对比度/双色等）应扩展该入口与其内部状态，而不是在 UI 层叠加 shader。
- **阅读状态可演进**：`reader_state.bin` 带 magic `LRS3` + 版本号，字段扩展时递增版本并保持
  "解析失败安全拒绝"；旧版（`LRS1`/`LRS2`）都能解码并迁移（ADR-065）。`Bookmark` 已含
  `label` 字段（当前留空），可直接承载具名书签/批注锚点。
- **权限位已就位**（ADR-039）：`DocumentInfo::can_copy/can_print` 已读取，供将来的复制/打印置灰。
- **文本输入与输入法**（ADR-028/040）：`update_ime_association` 按 `io.WantTextInput` 切换输入法关联，
  新增搜索框/批注框等中文输入无需再动这一层。
- **偏好集中**：界面/阅读/性能设置统一走 `UiPrefs` 与 `[ui]`/`[cache]` ini 段；新增设置项
  只需加字段 + 读写 + 一处 UI。
- **命令入口集中**（ADR-045）：所有命令的入口只有顶栏主菜单与画布右键菜单两处，共用
  `draw_zoom/view/nav_menu_contents`；新增命令在一处定义，两处自动可见。
