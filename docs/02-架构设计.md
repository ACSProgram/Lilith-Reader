# 架构设计

> 本文用现在时描述**当前**实现。未实现的能力一律标"规划"，其候选池与排期见[计划](01-计划.md)。

## 1. 总体结构

```
┌────────────────────────────────────────────────────┐
│ src/app        应用层：main / platform / session / 交互切片 / ui / settings_ui │
├────────────────────────────────────────────────────┤
│ src/canvas     自研画布：布局·缩放·平移·滚动·网格·对开 │
├────────────────────────────────────────────────────┤
│ src/render     渲染调度：工作线程·页状态机·纹理池·缩略图│
├────────────────────────────────────────────────────┤
│ src/document   MuPDF 封装：Document·页面·密码·目录   │
├────────────────────────────────────────────────────┤
│ src/state      阅读状态持久化：reader_state.bin       │
├────────────────────────────────────────────────────┤
│ src/utils      路径/编码/扩展名闸门/ini 持久化       │
└────────────────────────────────────────────────────┘
```

依赖方向自上而下单向；`document` 与 `canvas` 互不 import，通过 `render` 调度层衔接——这是为将来替换 MuPDF 为 PDFium 预留的解耦（ADR-003）。

- `app` 是唯一的非模块层：Win32/D3D11/ImGui 直连代码，按单一职责分多个普通翻译单元，
  共享的跨 TU 可变状态集中在内部头 `src/app/app_internal.h` 的容器 `AppContext`（单例 `g_app`）
  里，不再散落成一堆全局；文档/会话模型由其中的 `SessionController`（`g_app.session`）独占
  （ADR-046/086）。各 TU 只 include 本头，切片之间经本头声明的自由函数互调、互不 include（ADR-087）：
  - `main.cpp`：入口、进程 DPI 感知、窗口类/创建/恢复、消息循环、窗口过程
  - `platform.cpp`：D3D11、ImGui 引导、DPI/界面缩放、主题、图标字体、输入法、用户偏好、全屏
  - `session.cpp`：承载 `SessionController`——文档状态机（UiDoc）、身份与阅读数据、阅读位置恢复、
    视图变换（旋转/纸张方案）、逐页尺寸、目录、密码框；打开/认证结果在这里**按文档代次 +
    请求代次在唯一验收点 `poll()` 落定**（ADR-081/086）。另有画布输入映射、缩放防抖与渲染请求
  - `input_bindings.cpp`：命令表 `kCmds` 与按键绑定（`cmd_pressed`/改键捕获/ini 序列化，ADR-054）
  - `view_motion.cpp`：视图动效（滚动/缩放/跳页的插值入口，ADR-047）
  - `text_interaction.cpp`：文本交互与剪贴板（命中测试、选区、链接、复制）
  - `search.cpp`：全文搜索（输入防抖、增量命中、跳转；检索在渲染工作线程执行）
  - `ui.cpp`：绘制（外壳 / 画布 / 侧栏 / 菜单 / 弹窗 / 引导页）
  - `settings_ui.cpp`：设置窗口（界面 / 性能 / 按键 / 阅读数据四个分栏、阅读数据卡片、改键捕获、
    开合动效），自 `ui.cpp` 抽出（ADR-094）
  - `tone.h`：纸张方案 → chrome 色调的**纯函数**（无 ImGui / Win32 依赖，故可被单测直接断言，ADR-068）
  - `page_map.h`：屏幕点 ↔ **未旋转页面 pt** 的坐标折算（含 0/90/180/270 旋转），同为纯函数、
    同样可被单测直接断言（ADR-069）
  - `imgui_raii.h`：ImGui 栈操作的 RAII 作用域包装（ADR-078）；`imgui_stacks.h`：栈平衡自检
    （依赖 `imgui_internal.h`，故与 RAII 分开，避免内部头泄进所有 TU）
  - `crash.h/.cpp`：进程级崩溃防线（set_terminate / SEH / MiniDump，ADR-080）
  文档经 `render` 调度层访问（UI 线程零 `fz_*`、零阻塞），布局数学全在 `canvas`（纯函数，可单测）。
- `utils` 当前只有路径/编码/扩展名闸门（含"扩展名 → 格式族"表，单一出处 ADR-093）/ini 读写
  （窗口状态与用户偏好）四类工具。
- `log`（`lilithreader.log`，ADR-077）：轻量自实现日志。等级 + 时间 + pid/线程 + 模块 +
  `name=value` 字段；写入只入队、后台线程落盘（UI 线程零阻塞）；单文件 2 MiB，写满轮转为
  `.log.1`（恒定最多两个文件）；未 `init()` 时安全退化。只记低频事件（打开/关闭文档、渲染
  失败、重试、线程异常、设备错误、退出），**不进**每帧/每页热路径。崩溃路径不依赖它（见
  ADR-080）。**跨进程**：多实例并存时行级追加在 NTFS 上原子、行头带 pid 可归属；轮转在
  另一实例持有句柄时会失败，按退避重试（见 `log.ixx` 头注释）。
- `state`（`lilithreader.reader_state`）零项目内依赖：纯序列化（可单测）+ Win32 原子文件 I/O，存阅读位置与书签（ADR-034）。
- `persist`（`lilithreader.persist`，ADR-082）：阅读状态的**异步写盘服务**——独立工作线程 +
  防抖 + 退出 flush。UI 线程只经 `request_save`（纯序列化产快照）投递，服务不接触
  `ReaderState`，故与 UI 线程无共享可变状态。依赖 `reader_state`（编码/原子写入）与 `log`。
- `document` 的 `PageBitmap` 属性在**构造时快照**，访问器零 `fz_*` 回调；MuPDF 资源释放
  集中在边界函数（`pixmap_attrs` / `drop_*_safe`）内受 `fz_try/fz_catch` 覆盖（ADR-083）。
- `render`（`lilithreader.render`）：单工作线程调度，对外只暴露 `Renderer`（投递命令/请求 +
  读取快照）。实现单元按职责拆为**五个内部组件**（ADR-085）：`TextureStore`（页/缩略图纹理
  所有权、字节记账、两段式退役队列、LRU 逐出）、`DocumentWorker`（`Document` 生命周期与
  视图旋转/配色）、`PageScheduler`（渲染/缩略图请求去重调度、tile 拆分、资源档位）、
  `ContentService`（文本/图片/链接辅助请求）、`SearchJob`（全文检索代次与增量扫描）；
  **唯一互斥量与工作线程归 `Impl`**，组件不各自持锁。可脱离硬件的纯策略独立成两个模块：
  页状态机 `lilithreader.page_state`（`PageStatus`/`PageState` + 转移函数）与缓存逐出
  `lilithreader.page_cache`，二者连同 `render` 重导出，故 `lr::PageStatus` 等对 app 层可见。

## 2. 自研画布设计

### 2.1 视图状态（唯一真源）

```
struct CanvasState {
    float   zoom;            // 每点屏幕像素（fit_width 时该值被派生值覆盖）
    float   scroll_x;        // 内容坐标（px）水平偏移
    float   scroll_y;        // 内容坐标（px）垂直偏移
    int     columns;         // 1~4 列
    bool    fit_width;       // fit-width 模式时 zoom 派生
    bool    spread;          // 双页对开（书籍模式）：封面单独成页，其余两页对开；与 columns 同层级互斥（切列即退出，ADR-038）
    float   margin_px;       // 四周留白（**屏幕像素**：界面 chrome，不随缩放）
    float   gap_ratio;       // 页间/列间间距，占列宽比例（**文档空间**：随缩放，ADR-029）
};
```

页面布局是**纯函数**：`page_rect(index, state) → 屏幕矩形`。任何输入（滚轮/拖拽/键盘）只修改 state，渲染每帧按 state 重算布局。无 Invalidate 区域管理，天然可预测。

**书籍模式的行/列映射（ADR-038）**：均匀网格为 `row=i/cols, col=i%cols`；`spread=true` 时改为
"页 0 独占第 0 行，页 i≥1 → `row=1+(i-1)/2, col=(i-1)%2`"（等效 2 列）。缩放/滚动/钳制/翻页全部复用网格逻辑，
差异仅在映射与"单独成页的行在整行内居中"。`spread=false` 时映射与行为**逐位不变**（`canvas_test` 有回归守卫）。
**列数与对开是同层级互斥的视图模式**（ADR-038 勘误）：对开 = 2 列 + 封面偏移，故显式切列
（`set_columns`）会**直接退出对开**（无需先按 `D`）；对开期间 `columns` 仅被暂时覆盖、值保留，关闭后恢复。

> **唯一的有状态量：阅读游标 `nav_row_`（ADR-023）**。它是"当前读第几行"，只服务翻页
> 与页码指示，**不参与任何布局计算**——布局仍是纯函数。之所以必须存在：当视口比"一行"
> 还高时（横向页 / 缩小 / 多列），末尾若干行的 `row_top` 会超过 `max_scroll_y`，无法对齐到
> 视口顶部；若翻页游标只能由滚动位置反推，就会在末行前反复无进展（"卡住"）。
> 手动滚动/缩放后游标按"视口顶部所在行"回同步，**已到底时取末行**（页码才显示末页）。

**坐标模型（ADR-018 / ADR-029）**：文档内部以**点（pt）**为单位，`zoom` = 每点屏幕像素
（`zoom = 1.0` 即 72dpi）。留白与间距的**单位刻意不同**：

- `margin_px` 是**屏幕像素**：它是"窗口边缘的呼吸空间"，属界面 chrome，**不随缩放变化**。
- `gap_ratio` 是**列宽的比例**（文档空间）：屏幕间距 = `gap_ratio × 列宽 × zoom`，
  故**随缩放线性变化**——缩小时页面变小、间距同比变小，视觉比例恒定。
  用比例而非固定 pt，是为了让不同页幅的文档视觉比例一致。
  （早期 gap 也是屏幕像素常量，缩小时页面变小而间距不变，看起来"间距过大"——第四轮反馈。）

`fit_width` 派生
`zoom = (viewport_w − 2·margin_px) / (cols · max_page_w_pt + (cols−1) · gap_pt)`，
其中 `gap_pt = gap_ratio × max_page_w_pt`，使内容宽度**恰等于**视口宽。
内容窄/矮于视口时居中，否则按 scroll 偏移并钳制到 `[0, content − viewport]`。
派生量（内容尺寸、行顶前缀和）做可失效缓存，滚动不使其失效；
`set_viewport` 在视口未变化时**不**使缓存失效（UI 每帧都会调用它）；视口变化时以当前视口中心的文档坐标为锚点，
再按新 `fit_width` 缩放换回滚动像素，避免窗口尺寸变化把阅读位置映射到另一页。

> **逐页尺寸（ADR-022）**：PDF 允许各页 MediaBox 不同（封面/横向插页/扫描裁切不一）。
> 画布按**逐页真实尺寸**布局——列宽取最宽页、行高取行内最高页、每页按自身纵横比绘制；
> 尺寸由 `document` 层逐页探测（`DocumentInfo::page_sizes`，每页独立容错）经
> `set_page_sizes()` 传入。只用首页尺寸统一布局会让异构 PDF **形变**。探测失败（`{0,0}`）
> 或整表未探测（页数超过上限）的页回退到首页尺寸。

### 2.2 输入映射

> **键盘命令自 ADR-054 起由命令表驱动**：每条命令（`Cmd` 枚举）在 `input_bindings.cpp` 的 `kCmds`
> 里有名称、分组、默认键（**两个槽**）与"是否可连发"；实际生效的键存在 `g_binds`，可由
> 设置窗口的**按键分栏**改键并落盘到 ini 的 `[keys]` 节。下表列的是**默认键**。
> 派发只有一条路径：`cmd_pressed(Cmd)` → 命中即执行（阅读命令见 `handle_reading_commands`，
> 全局命令见 `handle_global_commands`）。Esc 只是"关闭当前对话框"的固定键，不再是"退出"。

| 输入 | 行为 |
|---|---|
| 滚轮 | 垂直滚动 |
| 按住「滚轮缩放」键 + 滚轮（默认 `Ctrl`） | 以**鼠标位置为不动点**缩放；修饰键**可自定义**（无 / Ctrl / Alt / Shift / Ctrl+Alt，见下行） |
| 左键拖拽 | 平移（**不做平滑**：直接操纵必须 1:1 跟手） |
| 拖拽右侧滚动条 / 点轨道空白 | 拖拽定位 / 滑块跳到该处；拖拽期间**不触发平移**（ADR-050） |
| ←→ | 上一行 / 下一行（单列即上/下页）；按**阅读游标**推进，见 §2.1 |
| ↑↓ / PgUp PgDn | 小步 / 整屏滚动 |
| Home / End | 首页 / 末页 |
| G | 跳页输入框 |
| 1~4（**主键盘或小键盘**） | 列数（对开期间切列即退出对开，二者同层级） |
| F / Ctrl+0 | 回到 fit-width |
| +/−（含小键盘 `+`/`-`） | 以视口中心缩放 |
| R | 旋转 +90°（0→90→180→270→0） |
| D | 双页对开（书籍模式）开关 |
| I / E | 深色纸张 / 暖色纸张方案开关 |
| O | 侧栏（目录 / 书签 / 缩略图）开关 |
| B | 当前页书签增删 |
| F1 | 打开设置的**按键分栏**（取代原"快捷键与帮助"窗口） |
| Ctrl+, | 打开设置 |
| Ctrl+O | 打开文档… |
| F3 | 调试浮层（FPS/DPI/画布状态/诊断读数） |
| Shift+F10 / 菜单键 | 打开**画布右键菜单**（与鼠标右键同一菜单） |
| F11（默认第二槽亦为 Esc） | 全屏开关 |
| Esc | **固定**：关闭当前对话框（设置 / 跳页 / 密码）。**不再**承担"关闭文档 / 退出"——阅读中误触会丢掉阅读位置，代价过大，关闭文档/退出一律走菜单（ADR-054） |

（缩放/滚动/跳页/顶栏滑动都有平滑插值，统一由 `[ui] Motion` 开关，ADR-047；
**惯性滚动**尚未实现——当前只有一阶滞后平滑，没有速度模型。）
状态栏页码取**阅读游标**（`current_page()`）而非 `visible_first()`：后者在视口高于一行时
会停在倒数第二行，与所见不符。

**键盘快捷键是应用级语义，不看 ImGui 窗口焦点**（ADR-026）：门只有「阅读态 + 无弹窗
（跳页弹窗）+ 无文本输入（`io.WantTextInput`）」。鼠标操作（滚轮/拖拽）仍需悬停在
画布上。原因：shell 与画布子窗口都带 `ImGuiWindowFlags_NoNav`（含 `NoNavFocus`），
ImGui 不会在启动时给它 `NavWindow`，以焦点为门会让快捷键在首次点击前**全部失效**。
数字/算术类快捷键一律**主键盘与小键盘两套都判**（ADR-027）：`ImGuiKey_1..4` 与
`ImGuiKey_Keypad1..4` 是不同的键，只判一套会出现"小键盘按了没反应"。

**命令表与改键**（ADR-054）：阅读命令在 `handle_reading_commands` 派发（画布悬停 + 阅读态），
全局命令在 `handle_global_commands` 派发（任何状态，但门 = **无文本输入 + 未在捕获按键 +
无对话框级界面**，`any_dialog_open()`）。改键只动 `g_binds`，`kCmds` 的 id 是 ini 键名、
**不得随显示文案改动**。绑定持久化在 ini 的 `[keys]` 节（值形如 `Ctrl+O|F11`，键名取
`ImGui::GetKeyName` 原文，ASCII）。

**修饰键型命令**（`CmdDef::mod_only`，当前只有「滚轮缩放」`ZoomWheelMod`，ADR-066）：
它绑定的不是"被按下的键"而是"按住不放的修饰键"（值就是 `ImGuiMod_*` 的集合，ini 里写作
`Ctrl` / `Ctrl+Alt`，空 = 无），故**不走 `cmd_pressed` 派发**，由 `wheel_zoom_mod_held()`
在画布输入里读；界面侧在按键分栏渲染成**下拉框**而不是捕获框（`chord_to_string` /
`chord_from_string` 都能表示"无主键、纯修饰键"的串）。设为"无"时滚轮只滚动、不缩放。

**不在命令表里的输入**（改不了，但必须让用户查到）：滚轮滚动、左键拖拽平移、右键菜单、
拖拽/点击滚动条、单击失败占位重试、鼠标移到窗口顶部重现顶栏、`Esc` 关对话框。
它们在「设置 → 按键」分栏末尾的**鼠标与固定键**一节里列出（ADR-066）——
早期只列可自定义的命令，用户无从知道这些操作存在。

**窗口脱离输入法**（ADR-028）：输入法启用时，Windows 会把字母/数字键的 `WM_KEYDOWN` 换成
占位码 `VK_PROCESSKEY (0xE5)`，ImGui 后端不映射该键码 → 这些键在 ImGui 里完全不置位
（字符却经 `WM_CHAR` 正常送达）。故窗口创建后立即
`ImmAssociateContext(hwnd, nullptr)`（并在 `WM_INPUTLANGCHANGE` 切换输入语言后重新脱离），
让键盘回归原生语义。
**将来加入中文输入（搜索/批注）时必须在文本输入激活时重新关联输入法**，否则中文打不进去。

#### 2.2.1 界面缩放与 DPI（ADR-025）

- 进程为 **Per-Monitor V2 DPI aware**；ImGui 的 `DisplaySize` 是**物理像素**。
- 字体：`style.FontScaleDpi = 显示器 DPI 缩放`（`WM_DPICHANGED` 时刷新，1.92+ 动态字体
  自动按新尺寸重栅格化）；`style.FontScaleMain = g_user_scale` 是**将来"全局字号设置"**
  的接入点（现固定 1.0）。
- 界面度量：`style.ScaleAllSizes(dpi × user)`（每次从留底的基准样式重算，避免累积）。
- 自绘像素常量（状态栏高、画布留白、滚动步长、居中文本偏移、最小窗口尺寸）
  `ScaleAllSizes` 管不到，统一过 `px()`。**页/列间距例外**：它是列宽比例（§2.1，
  ADR-029），与页面同比例缩放，**刻意不过 `px()`**、不随 DPI 单独放大。

### 2.3 渲染请求协议（画布 → 调度层）

画布侧每帧由 `app` 层汇总 `std::vector<RenderWant>{ page, scale }`（可见页 + 预加载页及其
**目标倍率**，可见页优先）投递给调度层。预加载页的范围由 `app` 按**滚动方向**裁剪：
只在与滚动方向一致的一侧多取一行（ADR-032）。调度层负责去重、排队、按字节预算逐出、换入。
画布不感知线程，只读
`PageSlot{ PageStatus, void* texture, pixel_w/h, scale }`——`texture` 是**不透明句柄**
（`ID3D11ShaderResourceView*`），画布只读、绝不持有所有权（ADR-019）。

**缩略图通道（ADR-037）**：侧栏另走一条并行请求 `set_thumbs_wanted(pages, target_px)`，
读取 `thumb_slot(page)`。缩略图**独立缓存、不占页缓存预算**，失败不自动重试。

**视图动效（ADR-047）**：缩放/滚动/跳页/顶栏滑动的插值全部发生在 **app 层写入画布之前**
（`view_motion.cpp` 的 `request_scroll / request_jump_scroll / zoom_*_animated / step_view_motion`），
画布不引入任何时间概念。跳页的目标位置仍由画布算（对开/网格/钳制的唯一真源），
app 只负责"从哪滑到哪"；滑行结束后重新钉一次阅读游标，保住"显式跳页显示目标行"的语义（ADR-023）。

**视图变换（ADR-036/067）**：旋转（0/90/180/270）与纸张方案（原色/深色纸张/暖色）是**文档级**状态，
经 `Renderer::set_view_transform` 下发。变换已固化进纹理像素，故任一变化即让全部页纹理与
缩略图失效并**整篇重渲**（失效走两段式退役队列）。旋转对画布透明：由 `app` 折算成
"页尺寸宽高互换"后交给画布，布局/翻页/缩放全部复用。

### 2.4 缩放清晰度策略

- 每页**一份**当前纹理；缩放变化 → **150ms 防抖** → 以新倍率请求渲染 → 完成后
  替换该页纹理，旧纹理入退役队列（ADR-019）
- 防抖期间**以及重渲染进行中**都用现有纹理**双线性放大**显示（不闪白、不错位）。
  落地要点（ADR-024）：页进入 `Loading` 时**只改状态、保留旧纹理**——若此时清空纹理，
  UI 会先退回"载入中…"占位框再换入，肉眼就是"缩放时闪一下"；且清空动作会让旧 SRV
  脱离退役队列而**泄漏**。新纹理就绪时在同一把锁内原子替换。
- 普通页仍按单边上限渲染；超出资源档位 tile 单边的页面走 `Document::render_page_tile`，
  按旋转后输出像素空间拆分为有界 RGBA 纹理，UI 以 tile 列表拼合显示，避免整页巨型 pixmap。
- 倍率与已投递倍率一致时**不重渲**；渲染请求按 (页, 倍率) 去重（ADR-020）

## 3. 渲染调度与稳定性

### 3.1 线程模型

- UI 线程：ImGui 帧循环 + 画布布局，**零阻塞调用**（绝不碰 fz_* 与磁盘）。
  阅读状态的落盘已移至持久化线程；打开流程不再做磁盘预检（ADR-081）。
- 渲染线程：**单线程串行**——`Document` 实例归属唯一工作线程，
  UI 线程只投递请求、读取快照（ADR-012）。阅读器单线程渲染已足够流畅，
  且彻底规避共享 `fz_document` 的并发风险。该线程由 `lilithreader.render`
  的 `Renderer` 持有（ADR-020）。
- 持久化线程：阅读状态（`reader_state.bin`）的写盘在**独立工作线程**完成 ——
  UI 线程只产快照（`encode_state`，纯序列化、不碰磁盘），服务（`lilithreader.persist`）
  按防抖窗口落盘、退出时 `flush`（ADR-082）。触发时机：阅读位置有变时**进程内每
  `kAutoSaveSec`（2s）节流落盘**一次（ADR-098，防异常结束丢进度），书签增删等显式操作后即时投递。
  该线程不接触 `ReaderState`，
  与渲染线程互不交互。
- 若将来确有并发渲染需求，再启用 ADR-006 预留的第二条路（每线程 `fz_clone_context`，
  共享 `fz_document`）；本期不实现，接口（`DocError` / `PageBitmap`）无需改动。
- 像素上传：渲染线程用 `ID3D11Device` 直接建纹理（`CreateTexture2D` + 初始数据，
  `IMMUTABLE`；device 方法 free-threaded，无需延迟上下文），上传完成即释放
  `PageBitmap`（ADR-019）

### 3.2 页状态机

```
Unloaded → Loading → Loaded
                  ↘ Failed（自动重试 ≤1 次后定格；显示错误占位，点击可重试）
```

`Loading`/`Failed` 都**保留旧纹理**（ADR-024）：从未成功渲染过的页才显示占位框。
失败后**自动重试 1 次**（可救瞬时失败，如一时分配不到显存）；仍失败则**定格**为 Failed，
不再随 wants 变化无限重渲 —— 定格绑定**失败时的倍率**，倍率一变即视为新请求、重置额度；
用户点击失败占位 → `Renderer::retry_page` 重置计数并重新排队（ADR-031）。
该状态机修复了 Lilith 原版"渲染任务异常后 status 永远停留 Loading（白屏）"的缺陷。

状态本体与转移函数在纯模块 `lilithreader.page_state`（`PageState`：`plan_render` /
`on_loaded` / `consume_retry` / `set_failed` / `request_retry` / `on_evicted` /
`on_invalidated` / `on_staled`，ADR-085），`TextureStore` 持有它、`PageSlot::status` 由它派生；
转移语义由 `tests/page_state_test.cpp` 钉住，不再靠 `Entry` 的多字段组合。

### 3.3 缓存与生命周期

- 纹理删除经过**两段式退役队列**：渲染线程把被替换/逐出的纹理放入 `retired_pending`
  （本帧），UI 线程**帧首** `drain_retired()` 先释放上一帧的、再收编本帧的 ——
  任何纹理**至少活过一个完整帧**，从机制上杜绝悬空 GPU 句柄（ADR-019/033）
- 缓存策略为按**字节预算**的 LRU；资源档位控制缓存上限与 tile 单边：
  低档 256MiB/1536px，中档 512MiB/2048px，高档 768MiB/2560px。缓存按需增长，不会启动时一次性分配；
  当前渲染由单个 MuPDF worker 串行执行。
  设置落在 ini `[cache] ResourceTier`，旧版 `BudgetMB` 仅作一次性兼容映射。
  本帧需要的页（可见 + 预加载）**pinned 不逐出**；其余按最久未用先出，直到总量降到预算内。
  逐出选择是纯函数（`lilithreader.page_cache::select_evictions`），可脱离 D3D/线程单测
- 预加载为可见行 ±1 行，且**方向感知**：向下滚只预取下方、向上滚只预取上方；
  方向未定（刚打开 / 跳页后）时两侧都预取（ADR-032）
- 缓存统计（预算/驻留字节/驻留页数/累计逐出）经 `Renderer::cache_stats` 暴露，F3 浮层可见

### 3.4 崩溃防线（分层，ADR-078/079/080）

四层边界各管一段，**下层不依赖上层、上层不越过下层**：

1. **模块边界**（已实现）：`document` 层所有 fz_* 调用 `fz_try/catch` 全覆盖，错误以返回值/结构化错误码出边界
2. **输入边界**（已实现）：损坏文件 fuzz 集（空/截断/假后缀/加密）全部优雅报错（已自动化）
3. **线程边界**（已实现，ADR-079）：`render` 工作线程入口 lambda 标 `noexcept`，`run()` 最外层
   try/catch 兜底；单页渲染、文档打开、辅助请求、检索各自捕获并转成**文档级/页级失败状态**。
   工作线程异常一旦逃出线程函数就是 `std::terminate`，这是最危险的一条路径，已封死。
   D3D 纹理所有权集中管理（发布/退役队列/关闭三处统一释放），尺寸与数量做上限检查。
4. **帧边界**（已实现，ADR-078）：`ui.cpp` 全量改用 ImGui RAII 作用域包装 —— Push/Pop 与
   Begin/End 由**词法作用域**保证配对，绘制中途抛异常时栈展开自动收回，不靠 catch 事后补 Pop
   （那既不可能也不可靠）。主循环帧级 try/catch：异常时用 ImGui 官方 `ErrorRecoveryStoreState`
   把内部栈拉回帧首基线、记日志、跳过本次 Present（保留上一帧画面）；Debug 构建再比对帧首/帧尾
   栈深度，任何漏配对**当帧点名**。ImGui 自身的可恢复错误接到 `lr::log`（ErrorCallback）。
5. **进程边界**（已实现，ADR-080）：`std::set_terminate` + `SetUnhandledExceptionFilter` +
   purecall/invalid-parameter 处理器 → MiniDump 写 exe 同目录 `crash/`，附人类可读摘要
   `last_crash.txt`；下次启动提示用户并可一键打开报告目录。处理器**只记录、不尝试恢复**：
   use-after-free / 数据竞争 / 栈破坏属于未定义行为，不可能"捕获后继续运行"。

边界能力**不夸大**：模块/线程/帧边界能把 MuPDF 错误、D3D 失败、内存分配异常转成可见状态，
不影响其他页面与进程存活；但未定义行为只能靠第 5 层留痕定位，不可能优雅续命。

### 3.5 加密 PDF

- 识别：加密文档打开时返回 `DocError::NeedsPassword`，文档仍处于打开态。
- **解锁 UI**：`app` 弹出模态密码框 → `Renderer::authenticate(pwd)` →
  `fz_authenticate_password`。支持标准安全 handler 全系（RC4 40/128、AES-128、AES-256 R6）；
  认证期间弹窗保持打开并显示"验证中…"，失败只更新"密码错误"提示，取消/Esc 关闭文档（ADR-044）。
  证书/PKI 与第三方 DRM 不支持，按损坏处理。
- **解密纪律（ADR-041）**：认证成功后不得再调用 `fz_needs_password()`（MuPDF 1.26.10 上会破坏
  解密状态，导致内容流静默解出乱码、整页空白）。`Document::Impl` 缓存该状态，`info()` 只读缓存值。
- **权限位**：`DocumentInfo::can_copy` / `can_print` 经 `fz_has_permission` 读取；
  无加密或无法判定时一律 true（保守放行）。**复制已落地，但尚未与 `can_copy` 联动**
  （声明禁复制的文档目前仍可复制），待办见 [计划](01-计划.md) §3。

### 3.6 显示设备丢失与失败提示

- **格式识别边界**：MOBI 支持取决于压缩方式 —— 未压缩与 PalmDOC 可打开，HUFF/CDIC 未实现
  （`unknown compression method`）；`document::classify` 在该情形判 `Unsupported`（"暂不支持的格式"），
  不误报"文件已损坏"（ADR-089/090）。
- **失败提示体系**（ADR-089；呈现契约统一于 ADR-100）：三类失败各归其位，但**共用一套通知模型**
  —— 状态栏是唯一文案面（左侧常驻告警 `NoticeId`：`SaveFailed` / `PageRenderFailed` /
  `OpenFailed`，条件成立即显示、消失即撤下；中间瞬时 toast；右侧格式），画布只留**作用域标记**：
  - 打开失败（文档作用域）：`UiDoc::error` 经 `lr::describe` 呈现在画布引导页，原因行与状态栏同源；
  - 渲染失败（页作用域）：**从未渲染成功**时画布显示极淡填充 + 醒目描边 + **左上角小标**
    「渲染失败 · 点击重试」（锚在页角，页面再大也在视口内）；**保留旧纹理**时（ADR-031）画布
    不加标记，但状态栏照常告知「第 N 页：…，当前显示低清版本 · 点击该页重试」—— 原因取
    `describe(slot.error)`（如"页面尺寸超出渲染上限"），故画面变糊时有据可查；
  - 落盘失败：帧首采样 `PersistService::last_save_failed()` → `g_app.persist_failed`，
    首次弹 toast、经 `update_notices()` 置位常驻告警直到下次写盘成功；**退出路径**在销毁服务前
    显式 `flush` 并采样失败位，失败则弹**原生提示框** —— 此刻 ImGui 已销毁、无后续帧，帧内提示
    来不及显示（ADR-098 对 ADR-089 的补充）。持续失败只在"由成功转入失败"时记一条日志，不刷屏。
  - **全屏底栏强制弹出**（ADR-100）：只要有活动消息（常驻告警或未过期 toast），全屏下底栏也强制
    滑出，不再要求鼠标贴近底端。
- **显示设备丢失**（ADR-088）：`Present` / `ResizeBuffers` 返回 `DXGI_ERROR_DEVICE_REMOVED/RESET`
  时置 `device_lost`、停止呈现；主循环帧尾用原生弹窗如实告知用户并干净退出（先更新阅读位置快照，
  退出路径 flush 持久化服务）。**不重建** device/swapchain —— 重建面覆盖 ImGui 字体纹理与
  `Renderer` 全部纹理，且在"不运行本软件"的纪律下无法验证。

## 4. 字体方案

- **UI 主字体（ADR-048）**：**随 exe 内嵌的子集** `assets/ui_font_subset.otf`（1.04MiB；
  源字体 Noto Sans SC Regular，OFL 1.1），以 `.rc` 的 RCDATA 内嵌、`AddFontFromMemoryTTF` 装载
  （`FontDataOwnedByAtlas=false`：资源内存全程有效，零拷贝零释放）。
  子集字符集 = 源码（去注释）非 ASCII 字符 ∪ ASCII 可见区 ∪ GB2312 一级字表 3755 字
  ∪ 常用标点/符号区段；**"源码字符集 ⊆ 子集"由 `assets/check_font_coverage.py` 在
  `tests/run_tests.ps1` 里断言**，生成脚本 `assets/make_font_subset.py`（源字体不入库）。
- **装载器**：FreeType（`io.Fonts->SetFontLoader(ImGuiFreeType::GetFontLoader())` + `LightHinting`）。
  子集是 CFF/OTF，内置 stb_truetype 只支持 TrueType；且小字号 CJK 栅格化质量更好。
  freetype 本身是 libmupdf 的传递依赖，未新增外部依赖。
- **生僻字 fallback**：系统 `msyh.ttc` 以 `MergeMode` 合并进同一 ImFont，只兜子集没有的字形
  （文件名、PDF 目录标题可能含生僻字）；系统缺该字体时静默跳过，界面自述文字不受影响。
  字形**按需栅格化**（DX11 后端声明了 `RendererHasTextures`，走动态图集路径）。
- **图标（ADR-045）**：图标字形取自系统 `Segoe MDL2 Assets`（`segmdl2.ttf`），以
  `MergeMode` 合并进同一 ImFont；只用 `ImFontGlyphRangesBuilder` 烘实际用到的几十个 PUA 码位。
  启动时用 GDI `GetGlyphIndicesW(GGI_MARK_NONEXISTING_GLYPHS)` 逐个校验字形存在，
  缺失则整体不合并、所有图标按钮退化为文字标签（不出现豆腐块）。
  度量校正：`GlyphMinAdvanceX = 基准字号`（图标宽度一致）、`GlyphOffset.y = +4`（消除 MDL2 与
  微软雅黑的基线差异——实测 150% DPI / 30px 有效字号下图标光学中心比汉字高约 6px，按基准字号
  折算为 4px；该值由 ImGui 随有效尺寸等比缩放）。
- **尺寸**：基准字号（现 20px）× `FontScaleMain`（用户/全局设置）× `FontScaleDpi`（DPI）
  = 实际像素；DPI 与界面度量缩放见 §2.2.1
- PDF 页内文字由 MuPDF 用文档自带字体渲染（无内嵌字体时走 MuPDF 内置 CJK 兜底，
  体积构成见[体积预算](05-体积预算.md)），与 UI 字体无关

## 5. 持久化

- **现状**（两个文件，均在 exe 同目录）：
  - `LilithReader.ini`：
    - `[window]`：位置/尺寸/最大化，恢复前做合法性校验（至少 100×100 落在虚拟屏幕内、最小 400×300）。
    - `[cache] ResourceTier`：资源档位 0 低 / 1 中 / 2 高；控制页缓存上限与 tile 单边。
    - `[ui]`（ADR-045）：`UiScale`（界面缩放 0.8~1.5）、`Theme`（0 跟随系统/1 浅/2 深）、
      `AutoHideToolbar`、`Motion`、`GapPercent`（页面间距，列宽百分比）。全部由「设置」窗口驱动，
      改动**即时生效并即时落盘**（写 ini 很小，不必攒到退出）。
    - `[reading] SmartMatch`（ADR-062）：0 关 / 1 询问 / 2 自动，缺省 1。
  - `reader_state.bin`（ADR-034；身份分层 ADR-062；位置列表 ADR-065）：每文档的阅读位置
    （页/缩放/列/旋转/对开/fit/纸张方案）与书签表，外加身份三件套 `path_key` / `page_count` /
    `locations`（**已知位置列表**，最近打开的在前，上限 8 条）。
    - **主键 = 内容指纹**：`utils::file_fingerprint` 的头 128KB + 中 64KB + 尾 128KB
      **稀疏采样**（≤320KB，与文件大小无关），由 render 的**工作线程**在打开时算好随
      `DocState::file_fingerprint` 发布（UI 线程不读文件内容，ADR-009）。
    - 定位顺序（`reader_state::locate`）：内容指纹 → 路径键（`document_key`，路径+大小+
      修改时间，v1 迁移与兜底用）。命中即 `adopt`（改挂到指纹主键、把当前路径记进
      `locations`）。页数对不上不继承（书签是页号，页数变了会错位）。
      `relocated` = 当前位置不在已知位置里（**一份数据、若干路径**：同一份内容存了两处时，
      在已记过的位置上打开不再询问）。
    - 格式 v3（magic `LRS3`）；v2（单路径 → 位置列表）与 v1（旧键 → `path_key`，位置留空）
      仍可解码并迁移。解析失败一律安全拒绝（空状态）。
      写入为"临时文件 + `MoveFileExW` 原子替换"；写盘在**持久化线程**按防抖进行
      （`lilithreader.persist`，ADR-082）。触发时机见 §3：位置有变时进程内每 2s 节流落盘
      （ADR-098），退出时 flush。
    - 用户侧入口：「设置 → 阅读数据」的智能匹配三态，以及同一分栏的卡片式清单（单条删除、
      全部清空、清理"位置未知"的旧记录，删除/清空均过确认弹窗，ADR-063/065）。
    - 「另起一份」（ADR-065）：确认弹窗的次按钮。把当前这份从共享记录里**摘出去**并各自
      退回按路径认（内容指纹一条记录只能挂一个，留着它会反复询问），两边进度互不影响。
- 其余写入（如主题设置）沿用「临时文件 + 原子替换」。

## 6. 阅读功能

- **阅读位置记忆**：打开成功时先 `resolve_document_identity()` 定位记录（内容指纹 → 路径键，
  命中即 `adopt`），再按记录恢复页/缩放/列/旋转/对开/fit/纸张方案；状态变脏后由持久化线程
  **防抖落盘**，且进程内每 2s 按需保存一次、退出时 flush（`reader_state.bin`，见 §5 / ADR-082/098）。
  位置在**首帧视口就绪后**恢复
  （fit-width 派生 zoom 依赖视口尺寸）。
  命中但路径变了时按「智能匹配」设置询问或静默沿用（ADR-062）。
- **目录侧栏**：`Document::outline()` 展平的前序序列（title/page/depth），按 depth 缩进渲染；
  点击跳转到目标页（`canvas.scroll_to_page`）。无目录显示占位。
- **书签**：`B` 在当前页增删，写入 `reader_state.bin`；侧栏列出并可跳转，行尾 `×` 删除
  （Selectable 显式让出按钮宽度，避免整行命中区盖住按钮）。状态栏在书签页显示 `★`。
- **缩略图侧栏**：只请求当前页 ±40 页（随当前页扩展），点击跳转（ADR-037）。
- **旋转 / 双页对开 / 纸张方案**：见 §2.3 与 ADR-036/038/042/043/067；均为文档级视图状态并随阅读位置一同记忆。
  - 旋转：交换版面宽高，切换时**整体失效重渲**（旧纹理贴新框会形变）。
  - 纸张方案：**仅它变化时保留旧纹理原地换入**，不做整篇白闪（ADR-042）。
  - 深色纸张为**柔化暗色映射**（白→`#1F1D1B`、黑→`#D7D5D3`），暖色为（黑→`#2B2318`、白→`#F6EEDC`）；
    两个端点必须**逐通道等斜率**（亮端 = 暗端 + 184），否则"越亮的那一端越暖" ——
    原亮端 `#D8D4CE` 的 r−b 差是 10、暗端只有 4，正文比纸面暖 2.5 倍（ADR-043 勘误）；
    **变换只作用于纸墨层，照片与插图原样保留**，chrome 按同一条色调规则派生（ADR-067/068）。
  - 分层实现（ADR-067）：`document` 层在页面与 draw device 之间夹一台**内容分流设备**
    （`SplitDevice`，逐回调转发），把一笔绘制按"是不是 `fill_image`"分给两层；`render_page`
    于是跑两遍 —— 纸墨层（跳过图像）→ 套配色 LUT → 图像层（只放行图像，按 `kImageDim` 降
    alpha 压暗后叠回同一张 pixmap）。`fill_image_mask`（单色蒙版图）算墨迹，跟着变换；
    裁剪/容器类调用两层都转发。整页扫描件（图像覆盖 ≥55% 且纸墨层几乎没画东西）改走
    "图像铺满 → 最后整体变换"，否则深色纸张模式下扫描书会是一整页白。原色方案仍是单遍直绘。
- **侧栏结构**：左侧单一 child（宽度 `px(300)`），内部四个标签（目录/书签/缩略图/搜索）；
  `O` 开关，默认定位"目录"，`Ctrl+F` 定位到"搜索"。分栏标题栏与窗口上沿之间留 `px(6)` 留白
  —— 紧贴顶端会让点标题的手感变成"在顶栏唤出带里试探"（ADR-070）。

## 7. 界面外壳（ADR-045）

界面由**顶栏 + 画布（可选左侧栏）+ 状态栏**三段构成，全部自绘/ImGui 绘制，无原生控件。
**会自动隐藏的栏按覆盖层处理**（ADR-097）：阅读态且开启「顶栏自动隐藏」时，顶栏不占画布的布局
高度、盖在画布之上滑入/滑出；全屏时状态栏同理（鼠标移到窗口底端才滑入；**有活动消息时强制滑出**，
ADR-100）。两者的出现与消失都**不改动画布视口**，页面不会跟着动画重排"呼吸"。**侧栏是唯一例外**：
它始终按顶栏的实际高度让位（分栏标题就在窗口顶端，被顶栏盖住会点不中）。

**弹窗（模态对话框）**：跳页 / 密码 / 通用确认三处，统一走 `popup_anim_apply` 做开合动效
（淡入淡出 + 轻微滑落，ADR-059）。**不变量：套用的透明度必须 > 0**（下限 `kPopupMinAlpha = 1/255`）
—— ImGui 在 `style.Alpha <= 0` 时会把窗口判为 Hidden，`Begin()` 返回 false，于是"收敛后再关闭"
那一步永远执行不到，弹窗会作为不可见的模态永久残留并挡住全部输入（ADR-064）。
通用确认弹窗（`request_confirm` + `draw_confirm_popup`）为**自绘版式**：标题（强调色）/ 说明 /
明细行（标签 + 可折行的值）/ 右对齐按钮，复用于智能匹配询问与阅读数据删除的二次确认（ADR-062/063）。

**三段的几何由 `draw_shell` 显式给出**（ADR-049）：自己算 `top_h / body_h / canvas_h / status_h`
并用 `SetCursorPosY` 落位，画布与侧栏的高度分别由调用方传入（覆盖层那一段不让位，故
`canvas_h` 与 `body_h` 不总是相等）。不让 ImGui 顺着排的原因：三者是同级子窗口，`EndChild()`
会为每个子窗口记一个 item，相邻子窗口之间被插入一份 `ItemSpacing.y`，三段之和会比客户区
多出一个间距，**状态栏被挤出窗口底部、文字下缘被裁**（实测即"状态栏文字贴边"的真实原因）。
**绘制顺序即 z 序**：`draw_top_bar` 必须排在画布之后 —— ImGui 按本帧子窗口的**创建顺序**
渲染与命中（`EndFrame` 会把窗口表按 `DC.ChildWindows` 递归重排），故"后画即在最上"是稳定成立的。
状态栏高度按 **CJK 墨迹盒**（ascent+descent ≈ 1.32 em）而不是 ImGui 的名义行高来定。

- **命令集中、按钮克制**：可点控件只出现在顶栏一簇与各种菜单里；**状态栏只放只读信息**。
  状态栏同时是**唯一的文案面**（ADR-100，统一通知体系）：左侧 = 页码 + 非默认视图 chip +
  **常驻告警**（落盘失败 / 打开失败 / 当前页渲染失败，告警色），中间 = 瞬时 toast，
  右侧 = 格式（扩展名不符的提示也在此）。**全屏下只要有活动消息，底栏强制滑出**。
- **顶栏**：左侧「主菜单（☰）」+「侧栏」；中间文档名（空间不足自动省略）；右侧控件簇
  （书签 / − / 缩放百分比 / + / 设置）。按钮一律**扁平**（默认无底色，悬停/按下/激活才浮现），
  图标字体缺失时退化为文字标签。阅读态可**自动隐藏**（鼠标停在窗口顶部即重现），
  自动隐藏的顶栏是**覆盖层**（ADR-097）：滑入/滑出不改动画布视口，页面不跟着重排。
  **唤醒顶栏的只有三类**（ADR-066）：鼠标靠近窗口顶端、设置窗口开着、**顶栏自身的弹出菜单**
  （主菜单 / 缩放档位，`g_toolbar_pinned` —— 菜单挂在顶栏按钮下方，顶栏滑走会让菜单悬空）。
  **画布右键菜单与跳页 / 密码 / 确认弹窗刻意不唤醒顶栏**：它们是画布或屏幕中央的操作，
  把顶栏一并滑出来只是视觉噪音（人工反馈）；非阅读态（引导/打开中/失败/需密码）顶栏本就常显。
  **侧栏区（x < 侧栏宽）不参与顶栏的唤起/收起**（ADR-070）：侧栏的分栏标题栏就在窗口最上方，
  鼠标必然要贴到顶端才点得到它；若这里也按"贴近顶端即唤出"，顶栏一滑出就把整条侧栏推下去
  40px —— 正要点的分栏跳走、反而点中刚滑出的顶栏（实测反馈）。故鼠标在侧栏区时**冻结**
  顶栏状态（既不因它唤起，也不因离开顶端带而收起）。顶栏仍可从画布一侧的顶端带唤起。
- **主菜单**：打开文档 / 关闭文档 / 视图 / 导航 / 缩放 / 设置 / 按键设置 / 退出。
- **外观菜单**位于“视图”下，分为“界面（全局）”与“纸张（本书）”；无文档时仍可选择界面主题，纸张方案置灰。
- **画布右键菜单**：导航（上/下一页）、缩放、视图、跳页、书签、侧栏、设置、按键设置。
  与主菜单**共用同一批内容函数**（`draw_zoom/view/nav_menu_contents`），不重复维护。
  菜单里显示的快捷键取**当前绑定**（`menu_item_cmd`），改键后同步。
  键盘等价入口 `Shift+F10` / 菜单键（§2.2）。
- **设置窗口**：四个分栏 —— 界面（缩放/界面主题/纸张方案/主题联动说明/顶栏自动隐藏/动效/页面间距）、
  性能（页缓存上限与 tile 尺寸；缓存按需占用，悬停说明当前 worker 策略）、**按键**（按命令分组列出全部命令，每条两个键槽：点击进入捕获、
  右键清除、冲突即时提示、可一键恢复默认；**滚轮缩放的修饰键是下拉框**（无 / Ctrl / Alt /
  Shift / Ctrl+Alt）而不是捕获框；分栏末尾另有**鼠标与固定键**参考清单 —— 滚轮滚动、右键菜单、
  拖拽滚动条、单击失败占位、`Esc` 等改不了的输入都列在这里，ADR-066）、**阅读数据**（智能匹配三态 + `reader_state.bin`
  的**卡片式**清单，ADR-062/063/065）。正文装在 `BeginChild` 里、
  **底栏固定**（内容多时只滚动正文）；全部即时生效并即时落盘（§5）。
  原「快捷键与帮助」窗口已删除，其参考信息并入按键分栏（ADR-054）。
  F1 直达按键分栏。智能匹配放在阅读数据分栏而不是界面分栏：它决定"要不要跨位置共用同一份
  数据"，与那一栏是同一件事，也省掉「界面」栏里那句"见阅读数据分栏"。
  - 阅读数据卡片 = 标题行（文档名 + 行尾删除按钮）/ 统计行（第 N / M 页 · K 个书签 ·
    J 个位置）/ 缩进的**路径树**（左侧一条竖导引线把若干位置挂在标题下）—— 用卡片而不是
    `TreeNode`，是因为路径是只读信息、不该看起来可点；路径**单行中间省略**、完整路径给悬停
    提示（折行会让卡片高度参差）。删除与"清空全部 / 清理旧记录"共用一套**破坏性按钮**观感：
    默认无底色、悬停浮出危险色，而不是 ImGui 默认的灰方块。
  - 「位置未知的旧记录」（v1 记录没存过路径）单独成区放在末尾，附一句解释与"清理这 N 条"，
    不再混在主列表里显示成一堆"未知文档"。
- **间距基准**：`kChromePadX / kChromeGapX / kPopupPadXY / kMenuItemGapY`（100% 缩放值，用前过 `px()`）。
  弹出菜单的项高由 `ItemSpacing.y` 决定（`Selectable` 高度 = 文字高，不吃 `FramePadding`）。
- **外观**：界面主题（跟随系统/浅色/深色）是全局偏好，纸张方案（原色/深色纸张/暖色）随文档记忆。
  深色纸张只在界面主题为“跟随系统”时额外令 chrome 变暗；显式浅色/深色不被文档状态覆盖（ADR-074）。
  `g_pal` 管自绘的 chrome 颜色，
  `apply_theme_colors` 管 ImGui 控件配色，两者在**帧首**同步切换（不在帧中途改样式）。
  两个正交维度（ADR-067/068/074）：**界面主题**（用户偏好）管明暗，**纸张方案**管页面，并通过
  `g_tone`（`Tone`，见 `src/app/tone.h`）决定 chrome 的**色调**。中性底只有浅/深两套，
  实际用到的颜色由 `tone_apply` 现场派生 —— 手写多套相近调色板既难保持一致又必然漏改。
  色调映射**按角色分类**：中性族（表面/文字/边框）旋到方案色相并**保持 WCAG 相对亮度**，
  中间调再压深一档补偿彩色底偏低的感知对比；强调族（冷色）整族换到方案强调色；
  语义族（红/橙）只把色相拉近 25%。三套参数：原色 `inactive`（零改动）、深色纸张 `hue 29 / sat 0.08`、
  暖色 `hue 40 / sat 0.155 / level 0.87 / ink 0.70`（色相都取页面纸色所在色相）。
  **两个分支都必须先整套重置 ImGui 样式**（`StyleColorsLight` / `StyleColorsDark`）再逐项覆盖 ——
  ImGui 有 62 个 `ImGuiCol_*`，"只覆盖在意的那些"会让未覆盖项带着上一个主题的值活过来（ADR-068）。
- **自绘滚动条**（ADR-050）：几何由 `scroll_bar_geom()` 一处给出，**绘制与命中测试共用**；
  支持拖拽滑块、点轨道空白跳转、悬停加宽高亮，拖拽期间抑制画布平移。命中区（12px）比可见
  滑块（5~7px）宽 —— 细滑块好看但按不中。
- **微动效**（ADR-047）：页面出现淡入、滚动条浮现后渐隐、顶栏自动隐藏**滑出/滑入**
  （高度插值，内容按整条高度排布后整体上移）、**侧栏滑入/滑出**（宽度插值，面板仍按**整宽**
  排布、整体左移，不重排内容，ADR-055）；缩放/滚动/跳页的平滑插值见 §2.3。
  **页面淡入的触发条件是"纹理在眼前就绪"**（ADR-066）：占位 → 内容的换入才渐显；
  页面**预加载好之后才滑入视野的不淡入**（直接显示）。原实现"本页第一次被画到就淡入"
  会让每次翻页都从透明渐显（边框与投影已是全不透明，页面内容才慢慢浮出来），
  看起来就像"翻到哪才开始加载"。
  **设置窗口**打开/关闭为**缩放 + 淡入淡出**（以窗口中心为不动点，尺寸 96%↔100%，
  透明度 0↔1；关闭时边缩边淡，不是原地整窗透明，ADR-056）。
  **弹出对话框**（跳页 / 密码）为**淡入淡出 + 轻微滑落**（ADR-059）：它们是 `AlwaysAutoResize`
  的输入框，缩放外框会裁剪内部固定宽度控件，故刻意不做缩放；关闭走"延迟关闭"
  （先淡出、收敛后才真正 `CloseCurrentPopup`）。
  全部由 `[ui] Motion` 统一开关，关闭即直切。F3 浮层有动效读数（pending / zoom 目标 /
  顶栏高度 / 是否在拖滚动条）。
  **不纳入动效**（刻意）：主菜单 / 右键菜单（桌面惯例是菜单即时弹出）、调试浮层（诊断 HUD）。
- **两套插值，分工明确**（ADR-047 / ADR-061）：
  - **连续输入驱动**（滚动 / 缩放 / 顶栏 / 侧栏）→ **一阶滞后**（`approach`）。理由：连续输入
    需要自然叠加，补间则每次输入都要重排时间轴。
  - **一次性开合**（设置窗口 / 弹出对话框 / 全屏状态栏弹出）→ **定时补间 + 三次缓出**
    （`ToggleAnim`，`kOpenCloseDur = 160ms`）。理由：单向、有明确终点，定时补间时长确定、
    末端干脆，没有"收敛到 99% 之后还拖一个时间常数"的长尾（人工反馈"再利落一点"）。
    状态栏弹出只**偏移内部内容**并交给子窗口自身裁剪（子窗口矩形不动、不越界），
    子窗口背景关掉（`NoBackground`）以免露出一条不随偏移的底色（ADR-097）。

### 7.1 窗口生命周期：swapchain 重建与全屏切换（ADR-057 / ADR-058 / ADR-060）

> **总纪律：一切改变帧级几何的操作都在"帧首"做。** 在 ImGui 一帧中途改窗口几何，本帧的
> 绘制数据就已经与窗口矩形不一致了，只能被 DWM 拉伸 —— 无论怎么调 Win32 调用顺序都救不回来。
> 具体落点：`WM_SIZE` 只记录待处理尺寸；全屏切换只置请求标志；两者都在主循环帧首应用。

- **swapchain 重建延到帧首**：`WM_SIZE` 只把客户区尺寸记进 `g_resize_pending`，**不**在消息里
  `ResizeBuffers`。因为 `WM_SIZE` 会在 `SetWindowPos` / `SetWindowPlacement` 过程中**同步**到达，
  而这类调用可能发生在 ImGui 一帧中途（命令派发时）；当场重建会让"按旧尺寸排布的本帧绘制数据"
  被画进新尺寸的后备缓冲，呈现为一帧拉伸/闪烁。改为帧首统一应用后：每帧至多重建一次、
  与 ImGui 视口尺寸严格一致，且多次 `WM_SIZE` 自动合并。`Graphics::resize` 另加"尺寸未变即跳过"。
- **全屏切换**：命令只置 `g_request_fullscreen_toggle`，由主循环**帧首**执行（ADR-060）。
  进入 = `WS_POPUP` + 单次 `SetWindowPos(FRAMECHANGED)` 铺满显示器；
  退出普通窗口仍先提交新样式再由 `SetWindowPlacement` 落位；退出最大化窗口则把目标外框一次性
  提交为当前显示器工作区矩形，再用 `SW_MAXIMIZE` 提交最大化状态，避免 `SetWindowPlacement(SW_SHOWMAXIMIZED)`
  内部的可见恢复中间态。
  进入前的 `WINDOWPLACEMENT` 被保存，退出时原样恢复（含最大化态）；样式/几何事务期间临时设置
  `DWMWA_TRANSITIONS_FORCEDISABLED`，并保持到切换后的首帧 `Present` 完成，避免 DWM 合成可见的
  过渡中间帧（普通窗口与最大化窗口双向进出全屏 2026-10-07 人工验证通过，见归档 16-8）。
  页面布局在视口改变后会按新的 `fit_width` 尺寸重排；画布以视口中心的文档坐标为锚点，
  减少重排造成的阅读位置位移。
- **最小化期间整帧不渲染**（ADR-061）：`WM_SIZE(SIZE_MINIMIZED)` 置 `g_minimized`，主循环
  帧首 `Sleep(10); continue;`。最小化后客户区为 0，ImGui 在 0 尺寸视口下什么都画不出，
  整帧只剩**清屏色** —— 在收起动画里就是一闪；顺带省掉最小化期间的 CPU/GPU。

### 8.0.1 依赖安装位置（重要）

vcpkg 的依赖**不在项目目录内**，安装根由仓库根 `Directory.Build.props` 的 `LilithVcpkgRoot`
注入（**不在 vcxproj 写死机器路径**）：

```
$(LilithVcpkgRoot)\x64-windows-static\        # 默认 %LOCALAPPDATA%\vcpkg-roots\LilithReader
```

取值优先级（低 → 高）：本文件默认值 → 环境变量 `LilithVcpkgRoot` → 本机
`Directory.Build.props.local`（不入库，见 `.gitignore`）→ 命令行 `/p:LilithVcpkgRoot=`。
`src/LilithReader.vcxproj` 里 `<VcpkgInstalledDir>$(LilithVcpkgRoot)</VcpkgInstalledDir>`，
`tests/run_tests.ps1` 按同一优先级解析（`-VcpkgRoot` 参数优先）。

为什么安装根必须在仓库之外：项目路径含空格，而 meson 端口（harfbuzz）生成的链接命令行未给
`/libpath:` 加引号，路径会被截断成两个参数（LNK1181）；同时 vcpkg 的 MSBuild 集成会把 triplet
拼两次。安装根须**不含空格、不含 triplet**，两者一并消除。理由与决策见
[ADR-010](03-决策记录.md)（含 2026-10-07 勘误：写死路径已改为可覆盖配置）。
**首次克隆后直接 `build.bat` 即可**（vcpkg 会自动装依赖到默认安装根）。

覆盖端口（overlay ports）：

| 端口 | 作用 | ADR |
|---|---|---|
| `overlay-ports/gumbo/` | 修正上游归档哈希失效 | [ADR-011](03-决策记录.md) |
| `overlay-ports/libmupdf/` | 剔除罕用字体，裁剪 exe 体积 | [ADR-072](03-决策记录.md) |

**环境坑：MSBuild 报 `MSB6001`**（"CL.exe 的命令行开关无效 / 字典中的关键字 'Path'"）：
这是环境问题而非工程问题 —— 当前进程的环境块里同时有 `Path` 与 `PATH`（大小写重复），
MSBuild 构造子进程环境时抛异常。用一份清理过重复键的环境启动 MSBuild 即可，`build.bat` 本身无需改。

### 8.1 图标资源（ADR-051）

| 资源 | 用途 | 生成脚本 |
|---|---|---|
| `assets/icon.ico` | exe / 窗口 / 任务栏 / 安装包图标 | `assets/make_app_icon.py`（从 256 母版 LANCZOS 重采样） |
| `installer/icons/lilith_<EXT>.ico` | 各格式的关联图标，装到 `{app}\icons\<版本>\`（路径含版本号 → Explorer 图标缓存自然失效） | `assets/make_format_icons.py`（按尺寸分级、超采样原生绘制） |

### 8.2 安装包（ADR-052/053）

`installer/LilithReader.iss`（Inno Setup 6.5+），`installer/build_installer.bat` 一键构建，
产物 `installer/dist/LilithReader-<版本>-setup.exe`（1.0-rc.1 实测约 24 MiB）。

- **每用户安装**（`PrivilegesRequired=lowest`）：装到 `%LOCALAPPDATA%\Programs\Lilith Reader`。
  理由见 ADR-052——程序把数据写在 exe 同目录（§5），装到 Program Files 会静默写不进去；
  关联写 HKCU 也要求非提权上下文。
- **升级 = 就地覆盖**：同 AppId + `UsePreviousAppDir / UsePreviousTasks`，沿用上次的安装目录与
  任务勾选；不做"先静默卸载旧版"（那会把旧卸载器的数据询问插进升级流程，ADR-053）。
- **编译期版本校验**：脚本里的 `MyAppVersionNumeric` 必须等于 `bin\Release\LilithReader.exe` 的
  数字版本资源（`src/app/app.rc` 的 `FILEVERSION`），不一致直接编译失败，杜绝两处版本漂移。
  显示版本 `MyAppVersion`（如 `1.0-rc.1`，可含预发布后缀）用于文件名、注册表显示与文案；
  数字版本是 4 段纯数字（预发布后缀无法进 PE 版本资源），两者分离。
- **文件关联**：全部写 HKCU（`Software\Classes\LilithReader.<ext>` + `OpenWithProgids` +
  `Capabilities` + `RegisteredApplications`），勾选页默认文档格式全选、图片格式全不选；
  实际绑定的扩展名记入 `HKCU\Software\LilithReader\Bindings`，卸载时据此精确回收。
- **卸载**：数据去留只问一次（`TaskDialogMsgBox`，默认保留；静默卸载一律保留），
  之后回收关联注册表。
- **运行中检测**：`CloseApplications`（Windows 重启管理器），不自行做文件占用试探。

### 8.3 持续集成（2026-10-06，ADR-076/081/084）

`.github/workflows/pr.yml`：`pull_request` 与 push 到 `main` 触发，在 `windows-2025` runner 上分两个 job：

- **build-and-test**（Debug/Release 矩阵）：跑 **MSBuild + vcpkg 构建**（Debug 只编不测——
  回归脚本自带编译、与主工程产物无关，见 ADR-084）；Release 实例额外跑 **`tests/run_tests.ps1`
  全量回归**，并把 exe 作为 artifact 传给打包 job。失败时按配置上传 `_build` / `samples` /
  `build` / `bin` 诊断包。
- **installer**（依赖构建）：复用仓库自带 `installer\build_installer.bat` 打安装包
  （Inno Setup 6，runner 镜像预装），`tests/check_installer_size.py` 断言体积 ≤ 35 MiB
  （依据 [体积预算 §5](05-体积预算.md)），产物上传 artifact 供 docs/04 人工安装验证取材。

要点：vcpkg 安装根与二进制缓存都置于 runner 临时目录（**必须在仓库检出目录之外**，见 ADR-010
的空格路径问题）；manifest 的 `builtin-baseline` 只在 CI 内临时注入、不改仓库 `vcpkg.json`；
runner 上显式执行 `vcpkg integrate install`（经典 MSBuild 集成不在镜像里，ADR-076 勘误）；
`run_tests.ps1` 统一设 `PYTHONUTF8=1`（Python 子进程编码不依赖机器 locale，ADR-076 勘误二）；
平台工具集按 runner 上已装的 MSVC 探测（`v145` 优先，回落 `v143`）。

## 9. 扩展点（当前已存在的接缝）

> 本节只描述**代码里已经存在**的接缝，用于承载后续功能；未实现的能力一律标注为规划，
> 候选需求池见[计划 §2](01-计划.md)。

- **文档后端可替换**（ADR-003）：`document` 对外只暴露与 MuPDF 无关的类型，`fz_*` 全藏在 PIMPL。
  换成 PDFium 只改这一个模块，`render` 及以上不动。
- **并发渲染仍是候选能力**：当前每个 Renderer 使用一个 MuPDF worker；基线中多份独立 Document/context
  的短批次测试未显示稳定收益。若更长批次实测证明收益覆盖额外内存，再设计每 worker 独立 context 的有界队列。
- **视图变换集中下发**：旋转/纸张方案经 `Renderer::set_view_transform` 统一入口；新增变换类型
  （亮度/对比度/双色等）应扩展该入口与其内部状态，而不是在 UI 层叠加 shader。
- **阅读状态可演进**：`reader_state.bin` 带 magic `LRS3` + 版本号，字段扩展时递增版本并保持
  "解析失败安全拒绝"；旧版（`LRS1`/`LRS2`）都能解码并迁移（ADR-065）。`Bookmark` 已含
  `label` 字段（当前留空），可直接承载具名书签/批注锚点。
- **权限位已就位**（ADR-039）：`DocumentInfo::can_copy/can_print` 已读取。当前「复制」只在
  "有选区"时可用（§10），**尚未**把它与 `can_copy` 联动 —— 加密文档声明禁复制时应当置灰，
  这是一个明确的待办（见[计划 §3](01-计划.md)）。
- **文本输入与输入法**（ADR-028/040）：`update_ime_association` 按 `io.WantTextInput` 切换输入法关联。
  搜索框（§10）已直接受益 —— 中文输入无需再动这一层。
- **页面可交互内容快照可扩展**（ADR-069）：`PageContent` 目前是"字符四边形 + 行框 + 图片框 + 链接"。
  批注/高亮/笔记需要的就是同一份字符四边形，扩展时在 `document` 加字段、在 UI 加一层绘制即可，
  不必再碰线程模型。
- **检索可扩展**（ADR-069）：`Renderer::start_search` 是"分页增量 + 可取消"的通用形态，
  正则/整词/区分大小写等只是 `document::search_page` 的入参扩展。
- **偏好集中**：界面/阅读/性能设置统一走 `UiPrefs` 与 `[ui]`/`[cache]` ini 段；新增设置项
  只需加字段 + 读写 + 一处 UI。
- **命令入口集中**（ADR-045）：所有命令的入口只有顶栏主菜单与画布右键菜单两处，共用
  `draw_zoom/view/nav_menu_contents`；新增命令在一处定义，两处自动可见。

## 10. 文本交互与检索（ADR-069/070/071）

> 本节描述**当前**实现：文本选择与复制、嵌入图片复制、超链接、全文搜索。
> 设计取舍（为什么这么切分线程与坐标）见 [ADR-069](03-决策记录.md)；
> 实测反馈的修正见 ADR-070（命中测试分档、侧栏与顶栏互不打架）、ADR-071（防抖自动检索、公式复制边界定性）
> 与 ADR-075（取消搜索时清空查询状态）。

### 10.1 坐标空间：只有一种

所有文本/链接/命中坐标都是**未旋转页面 pt**（原点在页面左上、y 向下、单位点），
与 `fz_stext_page` / `fz_load_links` 的原生空间一致。旋转**不在** `document` 层做。

屏幕 ↔ 页面 pt 的折算集中在 `src/app/page_map.h`（纯函数，无 ImGui/Win32 依赖）：
旋转 90° 的整数倍只是归一化坐标的置换（`rot 90: (u,v) = (1-nv, nu)`），
与页面包围盒原点是否为零无关。于是**旋转视图下整套命中测试与高亮没有任何分支**。

该置换由 `tests/page_map_test.cpp` 断言（26 条）：四角对应（最易写反的一处）、
正逆往返一致（含页外点 —— 拖动选择依赖它）、退化输入返回 false、角度归一化。

### 10.2 文本层：抽取、缓存、发布

- `document` 侧：`page_content(page)` 抽一页的 `PageContent`（字符四边形 + 行框 +
  图片框 + 链接），`copy_text(page, a, b)` 走 `fz_copy_selection`，
  `image_at(page, x, y)` 走 `fz_get_pixmap_from_image`（嵌入图片原图），
  `search_page(page, needle)` 走 `fz_search_stext_page` + `fz_copy_rectangle`（命中行上下文）。
  `stext` **只缓存一页**（与渲染一页同价，必须缓存；只一页则内存与页数无关）。
- `render` 侧：`request_page_content` 投递辅助请求 → 工作线程抽好 → `take_page_content`
  一次性取走；复制文本/图片结果同构（`take_copy_text` / `take_copy_image`）。
  辅助队列**有界 + latest-wins**（ADR-092）：复制类只保留最近一次（连点不积压）；队列上限
  `kMaxAuxQueue = 64`，超出丢最旧的（页内容有 0.6s 超时重发，可自愈）。
- `app` 侧：`g_content` 是当前页快照；命中测试（`char_index_at` / `link_index_at` /
  `image_index_at`）全部是纯浮点运算，每帧跟着鼠标跑，**不回工作线程**。
- **请求范围只有鼠标所在那一页**（不是全部可见页）：抽一页 stext 与渲染一页同价，
  全可见页盲发会在滚动时把工作线程塞满。首次悬停因此有约一帧的 I 型光标延迟；
  请求超时 0.6s 未到达则重发一次（自愈：页复杂或失败时不至于永远没有光标）。

### 10.3 交互：手势与光标

- **悬停在可选文本上 → I 型光标**；**悬停在链接上 → 手型光标**（链接优先，它常叠在文字上）。
- **命中测试分两档**（`char_index_at` 的 `clamp_to_nearest` 参数）：
  **悬停/按下走严格档** —— 只有落在某行文字的近旁（行框 ± 行高 1/4，且横向离行内字符不超过
  半个字高）才算命中，否则返回 -1；**拖拽走宽松档** —— 吸附到最近字符，于是拖到行尾之外
  选区仍能"到底"。两档必须分开：只有一档时要么"整页都算可选文本、光标离开文字也不复原"
  （实测反馈），要么"拖到行尾就选不动"。
  行的"文字高度"取 bbox 高与宽的较小者 —— 竖排文字的 bbox 高是文字长度，拿它当容差会整页误判。
  **选行是两维的**（多列版面同一 y 区间有左右两行，且左列在 stext 顺序里靠前）：先按"纵向
  距行带"取近，纵向并列时再按"横向距行框"取近 —— 否则右列的点会被判给左列、几乎选不中
  （ADR-091）。判据抽在 `src/app/text_hit.h`（纯函数，`pick_text_line`），由 `text_hit_test` 钉死。
- **左键拖拽**：按下点落在文本上 ⇒ 选择文本（平移让位）；否则 ⇒ 平移页面（1:1 跟手，手感不变）。
  这是本轮的交互设计选择：手势由"按下的位置有没有文字"决定，而不是加修饰键。
- **中键拖拽 = 平移，任何位置都可用**。这不是可选项：放大到文字铺满视口时左键处处都是选择，
  没有这个兜底就无法平移（桌面阅读器的通行做法）。它列在「设置 → 按键」的
  **鼠标与固定键**清单里。
- **单击**（位移 < `kClickSlopPx`）：落在链接上 ⇒ 打开；落在文字上 ⇒ 取消选区。
- 选区**限单页**；几何（复制端点 + 按行合并的高亮矩形）在确定时**冻结**进 `Selection`，
  与内容快照解耦（快照只有一页，会随鼠标移动到别的页而被换掉）。
- 高亮按行合并成矩形：逐字符画四边形会因相邻框重叠而"深一块浅一块"。每行的矩形再**居中裁进
  "行距"**（`clamp_rect_to_pitch`）—— 重排文本（EPUB）里字符 quad 的纵向是整行行框，可能大于
  行距（实测 16.17pt vs 13.20pt），不裁会与相邻行重叠；"行距" = 与横向有交叠的最近邻行中心距
  （多列靠横向交叠区分）。普通 PDF 行距 ≥ 行框，此处为空操作（ADR-099）。

### 10.4 剪贴板

- 文本：`CF_UNICODETEXT`（内部 UTF-8 → UTF-16）。直接写 `CF_TEXT` 会让中文变乱码。
- 图片：`CF_DIB`，32bpp、自下而上、**BGRA**（不是 RGBA）、alpha 恒 255。
  沿用源图 alpha=0 会让 Word/画图整张变黑。
- **写入不阻塞 UI 线程**（ADR-092）：平台层单次尝试，`OpenClipboard` 失败即返回 false；
  app 层留存待写内容在**下一帧重试**（最多 `kClipboardRetries = 5` 次），仍失败才如实报错
  （状态栏 toast："复制失败：剪贴板被占用"），不假装成功。

### 10.5 全文搜索

- **分页增量**：工作线程每轮扫 `kSearchBatchPages = 24` 页，之后必然回到主循环让位给渲染
  请求（滚动不卡）；结果**渐进发布**，UI 边搜边显示。
- **取消**：`cancel_search()` 使在途批次失效并清空渲染层结果；UI「取消」同时清空输入框、
  进度、结果列表与当前命中高亮。换关键字、换文档或关闭文档时也会作废旧查询。
- **改字即取消**：输入框内容一变就立刻 `cancel_search()` 并清空旧结果。取消在途是必须的
  （检索与渲染抢同一个工作线程）；清空旧结果也是必须的（结果列表必须与关键字一致，
  否则点进去跳到的地方与输入框里的词对不上）。
- **两级上限**：单页 200 条（`document`）+ 全局 5000 条（`render`）；触顶置 `truncated`，
  UI 显示"（已达上限）"。
- **入口**：侧栏第 4 个分栏「搜索」（`Ctrl+F` 直达并聚焦输入框；主菜单与画布右键菜单亦有入口）。
  **`Ctrl+F` 必须让分栏真的切过去**：ImGui 的 `TabBar` 自带选中态，只改 `g_sidebar_tab` 不会
  切栏；故用一次性标志 `g_sidebar_tab_want`，在下一次绘制时对该分栏带一次
  `ImGuiTabItemFlags_SetSelected`（只带一帧 —— 每帧都带会把该分栏锁死，用户再也点不到别的）。
- **触发：停手即搜（防抖）+ 两条快捷路 + 取消**：
  - **防抖自动检索**（`kSearchDebounceSec = 0.4`）：输入内容一变就作废旧查询并起计时，
    **停手 0.4s 自动发起**。三件状态必须分开：`g_search_committed`（结果对应哪个关键字）、
    `g_search_seen`（上一帧的输入内容，用来判定"这一帧是否改了字"）、`g_search_pending`
    （有改动、在等计时）。拿 `committed` 直接和输入框比会**每帧都判定"改了"**，计时器被
    每帧重置、永远等不到到期。
  - 回车 / 「搜索」按钮 = **不等防抖、立刻检索**。按钮不是装饰：中文输入法下第一次回车是
    "上屏"，未必送到输入框。关键字为空时（**显式**触发才）状态栏提示"请输入要查找的关键字"。
  - 「取消」按钮清空当前查询、结果和高亮；无查询时置灰。
  - **不做"逐键检索"**：每敲一个字符扫全文会把工作线程持续占满。输入法安全由"按缓冲变化
    计时"天然保证 —— Windows IME 的组字串在**上屏**时才进入 ImGui 的输入缓冲。
  - 中文输入由既有的输入法关联切换自动支持（ADR-028/040）。
- **状态文案**：未输入 / 待检索（防抖计时中）/ 检索中（`N/M 页 · 已找到 K 处`）/
  无匹配 / 扫完（`共 N 处`）。
- **结果与高亮**：结果列表用 `ListClipper` 虚拟化（可达数千条），每条显示页码 + 命中行上下文
  （`fz_copy_rectangle` 取该行文本，按 UTF-8 边界截断）；点击跳转。
  画布上命中以强调色半透明高亮，**当前命中颜色更重**且最后绘制（不被其他命中盖住）。
  命中矩形同样**居中裁进"行距"**（`trim_hit_to_line_pitch`，规则同 §10.3，ADR-099）——
  重排文本里命中 quad 高过行距时会偏大、相邻行的命中相叠。

### 10.6 已知边界：哪些内容选不中、复制不全

> 这一节是**产品边界**，不是待修缺陷。用户实测"公式复制有时候不完善"即属此列（ADR-071 决策 5）。

| 现象 | 根因 | 可否修 |
|---|---|---|
| 悬停**没有** I 型光标、完全选不中 | 该处**没有文本层**：内容被画成矢量路径（字形轮廓）或位图。命中测试如实返回 -1 | **不可修**。只有 OCR 能覆盖，而"不做 OCR"是明确的产品决定 |
| 能选中，但复制出的字**缺字/错字/方块** | 字体没有可用的 `ToUnicode` CMap（子集字体、Type3、符号字体自定义编码），MuPDF 无法把字形码映射回 Unicode | 不可修（同属字体信息缺失） |
| 能选中，但**顺序错乱**（上下标/分式错位） | 公式在版面上是多个文本对象，`fz_copy_selection` 按**阅读顺序**（非视觉顺序）拼接 | 不修（阅读顺序是文本层的唯一顺序） |
| 纯扫描件整页选不中、搜不到 | 同上第一条：整页只有一张图 | 不可修 |

UI 侧的表现是**诚实的**：选不中就是选不中，不会假装选中一段空内容，也不会在复制失败时
静默成功。
