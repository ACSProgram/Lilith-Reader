## 工作方式

1. **按批次推进**：一个需求（或一组相关需求）在本文件开一节，写明`目标 / 范围 / 验收 /
   涉及模块 / 相关 ADR`。落地后整节移入 `archive/YYYY-MM/`，并在
   [归档索引](archive/README.md)登记一行，本文件只留"已完成 + 链接"。
2. **选型先出 ADR**：凡是接口形态、线程归属、持久化格式、缓存预算这类会影响后续扩展的决定，
   先在 [03-决策记录.md](03-决策记录.md) 末尾追加 ADR，再动手改代码。
3. **验收分两路**：能写成断言的进 `tests/`（见 [tests/README.md](../tests/README.md)）；
   只能靠肉眼/手感判定的写入 [04-人工验证.md](04-人工验证.md)，通过后整节归档。
4. **不猜**：排查"某功能不生效"类问题，先取原始数据（窗口消息、日志、探针）再推理——
   纯推理走过弯路的教训见 [AGENTS.md](../AGENTS.md) §历史教训速查。

## 2. 待排期（候选需求池）

> 本节是**待评估**的需求池，不是排期承诺。每项落地前先出 ADR 定接口。
> 括注其依托的已有接缝（见[架构设计 §9](02-架构设计.md)）。优先级大体按
> "对阅读体验的收益 / 实现代价"排。

**阅读与检索**
- **批注 / 高亮 / 笔记**：读写 PDF 注释或旁挂 sidecar 文件；`Bookmark::label` 可先承接轻量备注。
  `PageContent` 已带每字符四边形，可直接作为高亮/批注的锚点来源。
- **搜索增强**：正则 / 整词 / 区分大小写 —— 都是 `document::search_page` 的入参扩展，
  调度形态（分页增量 + 可取消）已就位。
- **跨页选择**：当前限单页，扩展是纯 app 层改动（复合定位 + 跨页高亮）。
- **复制与权限位联动**（ADR-039 的既定用途）：`DocumentInfo::can_copy` 为假时把复制项置灰 ——
  **产品决定不联动**（保持放行），仅在 README 说明措辞上如实交代（见 §3）。

**导航与组织**
- **多标签 / 最近打开列表**：`Renderer` 已是"UI 投递命令 + 工作线程执行"的队列模型，多文档需
  每文档一个 `Document` 实例与独立的页缓存分区，属**架构级改动**，必须先出 ADR 定生命周期与
  缓存预算分配。
- **跳转历史（前进/后退）**、**页码/位置书签**：可扩展 `reader_state` 的版本化格式。
- **fit-page / fit-height / 自定义缩放档位**：纯画布派生逻辑，`Canvas` 已有 fit_width 先例。

**呈现与体验**
- **惯性滚动**（甩动后继续滑行；当前只有一阶滞后平滑，没有速度模型，ADR-047）。
- **字体子集按需扩充**：当前子集 = GB2312 一级 + 源码字符集，更生僻的字靠系统字体 fallback；
  若要完全摆脱系统字体，可把 GB2312 二级（+3008 字）也纳入（体积 +0.6MB 量级）。
- **主题自定义 / 更多页面配色**（依托 `Renderer::set_view_transform` 集中入口）。

**健壮与工程**
- **异步辅助请求有界化**：复制文本 / 复制图片改"latest-wins + 有界队列"，不再无限 FIFO
  积压（ADR-081 第 3 条，本批未做）。
- **剪贴板失败改下一帧重试**：去掉 `platform.cpp` 里失败时的 `Sleep(10)` 重试，改为下一帧
  重试状态（ADR-081 第 4 条）。
- **文档会话状态统一（SessionController）**：把 `UiDoc` / `DocState` / `session.cpp` 的 `g_*`
  收敛为**单一**会话状态源，UI 与渲染层都作为它的投影；所有异步结果带**文档代次 + 请求代次**，
  在统一处验收（ADR-081 第 2 条的后续落地）。
- **渲染后台服务拆分**：单工作线程不变，内部拆 DocumentWorker / PageScheduler / TextureStore /
  ContentService / SearchJob（复查报告 §一.4）。
- **页状态机显式化**：`render.cpp` 的 `Entry` 把 status / stale / manual_retry / auto_retries /
  failed_scale 收成状态对象与转移函数（复查报告 §一.5）。
- **扩展名策略归一去重**：`utils.ixx` 白名单与 `document.cpp` 的扩展名族判断合并为单一出处，
  或加结构检查固化一致（复查报告 §二）。
- **document 边界静态检查**：扫描 `fz_*` 是否都落在边界函数内（ADR-083 遗留）。
- **静态分析**：`/analyze` + Debug AddressSanitizer 跑一轮完整冒烟（迁移阶段遗留，见 §3）。
- **自动化**：把纯函数测试的思路扩展到 `reader_state` 的版本迁移/兼容用例。

## 4. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| MuPDF AGPL 协议 | 闭源商业分发受限 | 当前自用/开源无碍；若商用换 PDFium（BSD），`document` 层的抽象已按此预留（ADR-003） |
| vcpkg 静态库构建环境敏感 | 换机器可能复现 | 安装根必须无空格且不含 triplet（ADR-010）；gumbo 用覆盖端口修上游哈希（ADR-011）。细节见 [架构设计 §8](02-架构设计.md) |
| epub 排版质量不佳 | 多格式体验参差 | epub 渲染缺陷记录在案，不承诺完美；PDF 优先级永远最高 |
| 最大化态退出全屏抖动 | 观感受影响；普通窗口不受影响 | 见 §3 遗留问题；候选方案：转换期间抑制重绘，或先 `SW_RESTORE` 再重新最大化 |
| Windows Defender 误报 | 用户首次运行被拦截/删除 | 短期本机排除 + 上报误报；已加版本资源与图标；根治需代码签名证书 |
