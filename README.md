# Lilith Reader

[![PR CI](https://github.com/ACSProgram/Lilith-Reader/actions/workflows/pr.yml/badge.svg)](https://github.com/ACSProgram/Lilith-Reader/actions/workflows/pr.yml)

一个 Windows 上的**轻量文档阅读器**：单个 exe、不装任何运行时、打开就用。

它是从 [Lilith](F:\programs\Lilith) 主项目里分离出来的独立应用，只做一件事 —— 把 PDF / EPUB
这类文档**读得舒服**：翻页跟手、放大不模糊、记住读到哪、界面不吵。

---

## 它能做什么

**打开就能读**

- 双击直接打开：`LilithReader.exe <文件路径>`，也可以在资源管理器里右键"打开方式"关联
- 支持 PDF、EPUB、MOBI、FB2、CBZ、XPS，以及 png/jpg/gif/bmp/tif 等图片（图片按单页文档打开）
- 加密 PDF 弹密码框；格式认不出来就如实说认不出来，不假装打开

**读得顺**

- 连续滚动、单列阅读，或 1~4 列并排浏览（翻杂志、对版式）
- 双页对开（书籍模式）；旋转 0/90/180/270°
- 按缩放级别重新渲染，**放大不模糊**：缩放时先显示旧图，高清渲染好再换上，不会闪白
- 每页按**真实尺寸**排版 —— 一本 PDF 里页面大小不一样也不会被拉变形
- 记住每本书读到第几页、缩放和版式；关机、移动文件、重新下载都不丢
- 书签、目录（PDF 书签树）、页面缩略图，点一下就跳过去

**看着舒服**

- **纸张方案**：原色 / 深色纸张 / 暖色。只改纸面与文字，**页面里的照片和插图保持原色**
  （整页扫描件整体变换）
- **界面主题**：浅色 / 深色 / 跟随系统 —— 与纸张方案是两个独立维度，互不干扰
- 界面随显示器缩放，高 DPI 下不发糊

**界面与操作**

- 顶栏图标按钮 + 主菜单 + 画布右键菜单，命令都收在菜单里，不堆按钮
- 设置窗口五栏：界面、阅读、性能、**按键**、阅读数据，改完立刻生效并保存
- **按键全部可自定义**：每条命令两个键槽，可改键、清除、恢复默认；滚轮缩放的修饰键也能改
- 动效：缩放插值、滚动平滑、跳页滑行、顶栏自动隐藏、侧栏滑入滑出、弹窗淡入淡出；
  不想要就在「设置 → 界面」里一键关掉
- 全屏（`F11`）、可拖拽的滚动条

**文字可以用**

- **选中文字并复制**（有文字层的文档；**不做 OCR**，纯扫描件选不了）
- **复制图片**：右键点页面上的插图，按原始分辨率复制
- **超链接**：外部链接用系统浏览器打开，文档内链接直接翻页
- **全文搜索**：`Ctrl+F`，打字停手就自动检索，结果列在侧栏、命中处高亮，点一下跳过去

**设置与数据**

- 程序是便携的：设置写在 exe 同目录的 `LilithReader.ini`，阅读进度写在 `reader_state.bin`，
  拷走整个目录就带着全部数据
- 「设置 → 阅读数据」里能看到存了哪些书，可单条删除或清空
- 崩溃会留一份报告在 exe 同目录 `crash/`，下次启动提示你查看；日常运行日志在 `logs/`

### 快捷键（默认）

| 键 | 作用 |
|---|---|
| `O` / `B` | 侧栏 / 当前页书签 |
| `R` / `D` | 旋转 90° / 双页对开 |
| `I` / `E` | 深色纸张 / 暖色纸张 |
| `1`~`4` | 列数 |
| `F` / `Ctrl+0` / `+` `-` | 适应宽度 / 缩放 |
| `←` `→` `↑` `↓` `PgUp` `PgDn` `Home` `End` | 翻页与滚动 |
| `G` | 跳页 |
| `Ctrl+O` / `Ctrl+,` / `F1` | 打开文档 / 设置 / 按键设置 |
| `Ctrl+C` / `Ctrl+A` / `Ctrl+F` | 复制选中 / 全选本页文字 / 查找 |
| `F11` / `Esc` | 全屏开关 / 关闭当前对话框 |

鼠标：滚轮滚动，按住 `Ctrl` 滚轮缩放（修饰键可改），左键拖拽平移（在文字上是选择文本），
中键拖拽平移，右键菜单。全部键位可在「设置 → 按键」里查看与修改，
改不了的鼠标操作也在同一栏列出。

## 架构

Reader 分成六层，依赖自上而下单向，每层只管一件事：

```
┌──────────────────────────────────────────┐
│ app       界面与交互：窗口、菜单、设置、绘制      │
├──────────────────────────────────────────┤
│ canvas    页面怎么摆：缩放、平移、多列、滚动      │
├──────────────────────────────────────────┤
│ render    渲染调度：后台渲染、缓存、纹理管理      │
├──────────────────────────────────────────┤
│ document  解析文档（MuPDF）                    │
├──────────────────────────────────────────┤
│ state     阅读进度与书签的持久化                │
├──────────────────────────────────────────┤
│ utils     路径、编码、配置读写                   │
└──────────────────────────────────────────┘
```

三条约束决定了这套结构的形状：

1. **界面永远不卡**：读文件、渲染页面都在后台线程做，界面线程只负责画和收结果，
   不等任何慢操作 —— 再大的 PDF 也不会拖住滚动。
2. **布局是纯计算**：页面摆在哪、怎么缩放，是不碰界面的纯函数，所以能写成自动化测试，
   改一次就断言一次。
3. **解析层可替换**：`document` 对外只暴露与具体解析库无关的类型，
   将来要换掉底层的 PDF 引擎，只改这一层。

技术栈：C++20（大量用 C++20 modules）、ImGui + Direct3D 11 自绘界面、MuPDF 静态链接、
vcpkg 管理依赖、`/MT` 静态编译。

## 支持格式

PDF、EPUB、MOBI、FB2、CBZ、XPS、图片（png/jpg/jpeg/gif/bmp/tif/tiff）。

识别是**看内容而不是看扩展名**：文件能认出是什么就按什么打开，扩展名不对只作提示
（epub 改名 `.pdf` 照样按 epub 读）。唯一的例外是**压缩包冒充单文档**：zip 图集改名成
`.epub`/`.pdf` 会被拒绝 —— 处理器会按压缩包里的图片凭空编出页数，必须拦住。

`.webp` 没有对应的解码器，暂不支持。

## 从源码构建

- Visual Studio 18 (2026) Community（PlatformToolset v145）+
  [vcpkg](https://vcpkg.io/)（manifest 模式，`x64-windows-static`）
- 打开 `LilithReader.slnx` 按 F5，或命令行跑 `build.bat`；依赖由 vcpkg 自动装
- 产物：`bin\Release\LilithReader.exe`，静态链接，只依赖 Windows 系统组件

体积约 **38 MiB**，其中约 30 MiB 是内置的兜底字体（中文文档未内嵌字体时必须有），
约 1 MiB 是内嵌的界面字体。构成与裁剪手段见
[体积预算](docs/05-体积预算.md)。

> 环境细节（依赖安装位置、覆盖端口、已知的 MSBuild 环境坑）见
> [架构设计 §8](docs/02-架构设计.md)。

## 安装

发布形态是一个 Inno Setup 安装包：

```
installer\build_installer.bat        :: 需 Inno Setup 6；先跑过 build.bat
→ installer\dist\LilithReader-<版本>-setup.exe
```

- **每用户安装**，装到 `%LOCALAPPDATA%\Programs\Lilith Reader`，**不需要管理员权限**
  （程序把数据写在 exe 同目录，装进 `Program Files` 会写不进去）
- 向导里勾选**文件关联**（文档格式默认全勾、图片默认不勾），卸载时精确回收
- **升级是就地覆盖**：沿用上次的安装目录与勾选，阅读数据原样保留
- **卸载**时会问一次是否保留阅读数据，默认保留

## 已知问题与限制

- **最大化状态下退出全屏有一次可见抖动**：窗口会先向左上缩一下再归位。
  普通（非最大化）窗口没有这个问题。三种常见成因已经排除（帧内命令时机、调用顺序、
  交换链重建时机），剩下的疑点在 Windows 自身的窗口还原行为里。
- **Windows Defender 可能误报**：未签名 + 静态链接的 exe 容易被启发式引擎误判。
  本机把 `bin\` 加入排除项即可；也可以[向微软上报误报](https://www.microsoft.com/en-us/wdsi/filesubmission)。
  彻底解决需要购买代码签名证书。
- **不做 OCR**：纯扫描件没有文字层，选不中也搜不到。
- **文字选择限单页**，拖到页外就止于本页。
- **公式与矢量内容复制不全**：画成矢量或位图的内容没有文字层；字体缺少 `ToUnicode` 映射时
  能选中但复制会缺字；公式的上下标由多个文本对象拼成，复制顺序可能与看到的顺序不同。
  这些是 PDF 文本提取的固有限制。
- **界面字体是内嵌子集 + 系统兜底**：界面文字 100% 覆盖，但文件名、目录标题这类
  文档侧的生僻字依赖系统字体，系统缺字体时会显示缺字框。
- **加密文档声明"禁复制"时目前仍可复制**：权限位已读取，尚未与复制功能联动。
- **搜索有 0.4 秒防抖**：打完字停手约半秒才开始检索，这是刻意的 —— 逐字符检索会把
  后台线程占满。
